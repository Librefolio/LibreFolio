## [Unreleased]

### ✨ Added

- After an update, each user sees once what changed since their last version: the new changelog chapters, in their language where translated. New accounts never see it, and it never opens over a guide or another window. Same on self-hosted and managed instances.
- `./dev.py db currencies` lists stored currency codes that are not ISO codes (names or numbers saved by earlier versions), and the server warns about them at every start.
- **Currency fields show what a non-ISO stored code stands for.** A currency saved as `978` or `EURO` by an earlier version stays visible in the picker, next to the ISO code it stands for (`EUR`), so you can pick the right one. Restoring a backup also warns about such codes before you confirm.
- The Dashboard's data-quality banner names a stored currency code that is not an ISO code (`978`, `EURO`) with the code it stands for, instead of asking for an FX pair that cannot exist.
- `GET /api/v1/transactions` accepts `asset_event_id` and lists the transactions linked to that asset event, within the brokers you can see.
- `./dev.py user create … --role user` creates a regular account; without `--role`, the command still creates an administrator.
- Secrets can be read from files: `JWT_SECRET_FILE`, `LIBREFOLIO_INSTANCE_KEY_FILE` and `LIBREFOLIO_WEB_LINK_FINDER_API_KEY_FILE`, as Docker and Kubernetes secrets mount them.
- **Instance key**: one secret per installation, generated on first use in the `secrets/` folder of the data directory, or given through the environment. LibreFolio derives its encryption keys from it: back up `secrets/` together with the data.
- At startup the log warns about settings that leave the instance weaker: a short session key, a secret set twice, loose permissions on the instance key, `SESSION_COOKIE_SECURE=never`, a verbose log level.
- At startup, the log reports how many stored instance-wide plugin secrets the instance key can no longer read — after a lost key file, or data restored without `secrets/` — with what to do.
- `.env.example` lists every option LibreFolio reads, grouped by function.
- `GET /api/v1/system/instance`: the public configuration of the instance, read by the app at startup.
- A currency exchange explains its two dates, in the form and in the guide: they usually match, and differ when the broker credits the new currency on another day.
- `GET /api/v1/system/ready`: 200 when the database answers and its schema is at the latest migration, 503 otherwise, one code per check — for Docker health checks, Uptime Kuma and hosting panels.
- `LIBREFOLIO_PROFILE`: `selfhosted` (the default, nothing changes) or `managed`, for whoever hosts LibreFolio for others. In the managed profile a `JWT_SECRET` shorter than 32 characters stops the server at startup; elsewhere it stays a warning in the log. Documented in the new admin page "Hosting for Others".
- **Instance block, for hosting providers**: with `LIBREFOLIO_BLOCKED=1` the data stays, and whoever signs in sees a page saying the instance is blocked, with the deletion date when `LIBREFOLIO_DELETION_DATE` is set. To a signed-in user the API answers `423 instance_blocked` to everything except signing in and out, following a password-reset link already sent, deleting their own account, the block page, the public configuration and the health, readiness and version probes. A malformed value of either variable stops the server at startup, naming the variable.
- On a blocked instance, administrators see **Manage subscription** on the block page, linking to the hosting provider's billing page set in `LIBREFOLIO_BILLING_URL`.
- On a blocked instance, administrators can still back up the whole instance from the block page: the backup card of Settings › Backup.
- `GET /api/v1/system/block`: the block state behind that page, for signed-in users.
- **Who can sign up**: in Settings › Admin, «Registration» is Open, By invitation or Closed. `LIBREFOLIO_REGISTRATION` can set it from the server; the field then shows the mode in force, read-only.
- **Invitation links**: an administrator creates single-use links, valid 7 days, with `./dev.py user invite [--admin] [--email …]` or the admin API. The link opens the registration form with the role and, if given, the suggested address, which can be changed.
- **Password-reset links**: `./dev.py user reset-link <username>`, or the admin API, creates a single-use link valid 30 minutes. The user chooses a new password there, and every session of the account ends.
- **Initial administrator for hosting providers and scripted installs**: with `LIBREFOLIO_ADMIN_EMAIL` (and `LIBREFOLIO_ADMIN_USERNAME`, `admin` by default, and optionally `LIBREFOLIO_ADMIN_BOOTSTRAP_TOKEN` or its `_FILE`), the first start of an instance without accounts creates that administrator, not yet active, sets registration to invitations, and issues a single-use setup link valid 72 hours, written once in the log and emailed when email works, or the hosting panel's own link when it gives the token. On an instance with accounts the variables are ignored; a value that cannot be used stops the server, naming the variable. `./dev.py user setup-link` prints a new link. API: `POST /api/v1/auth/setup` sets the password with the setup link and signs in; `POST /auth/tokens/inspect` accepts `admin_setup`.
- **Initial administrator: the setup page.** The link `https://<instance>/setup#token=…` opens a page where the administrator chooses the password and is signed in. A link that no longer works says to ask the hosting provider or run `dev.py user setup-link`. On a blocked instance the page says the setup waits for the unblock.
- **Users tab: the administrator waiting for setup.** It shows the «Waiting for setup» badge and has no Reactivate; the API refuses to activate it (`409 PENDING_SETUP`).
- **Open registration, reachable from outside: a warning.** An administrator who reaches an instance with open registration through a non-local address sees a warning, with a link to Settings › Admin. When `LIBREFOLIO_REGISTRATION` pins the mode, the warning names the variable instead.
- `LIBREFOLIO_MAX_USERS` caps the number of accounts (unset: no cap). `LIBREFOLIO_PUBLIC_URL` prints full links instead of bare paths. `LIBREFOLIO_BILLING_URL` is for hosting providers.
- Admin API under `/api/v1/users`: list accounts, activate and deactivate, promote and demote, sign out of every device, restart the guides, reset links, invitations.
- `./dev.py user reset-onboarding <username> [--flow …]` restarts an account's guides.
- `GET /api/v1/brokers/{id}/summary` accepts `as_of`, the day to read the summary for; the broker page sends your today.
- `POST /api/v1/assets/events` accepts `mode: "create"` for an event that must be new. One on a day and type the asset already has, manual or from a provider, is refused with 409 `EVENT_EXISTS` listing the events already there, instead of overwriting them. Each result also gives the `event_ids` it wrote, in request order.
- `POST /api/v1/assets/events` accepts `delete_ids`: events of the asset deleted first, in the same transaction. An id that is not an event of the asset is a 400 `EVENT_NOT_DELETABLE`, an event linked to transactions a 409 `EVENT_IN_USE`. Each result lists the `deleted_ids`.
- **Email, optional**: LibreFolio can send emails through your own SMTP server, named only by the `LIBREFOLIO_SMTP_*` variables, the password also from a file (`LIBREFOLIO_SMTP_PASSWORD_FILE`). Nothing of it is stored, shown in the app or put in a backup, and without a server nothing changes. **Settings › Administration › Email**, for administrators, says whether email works, which variable to fix when it does not, and sends a test email to your own address in your language. `LIBREFOLIO_SMTP_MAX_PER_HOUR` caps the emails of the instance (50 an hour by default); the startup checks report an unusable configuration and a server reached without encryption. Documented in the new admin page "Email".
- **Instance backup**: an administrator downloads a zip of the whole instance from **Settings › Backup**, or writes one with `./dev.py backup create` (and checks it with `./dev.py backup inspect`); it also works when the hosting provider has blocked the instance. Documented in Admin › Command-Line Tools.
- Hosting panels can download backups of the whole instance with a token: set `LIBREFOLIO_BACKUP_DOWNLOAD_TOKEN` (or its `_FILE`) and call `/api/v1/backup/panel/jobs` with `Authorization: Bearer`, also on a blocked instance. Off by default.
- **Users tab for administrators** (Settings → Users): see every account and the open invitations with the places taken; deactivate, reactivate, promote, demote, sign out everywhere, send a password-reset link, restart the guides, and delete an account after a preview of what goes (deactivation offered first); invite with a single-use link whose server address can be edited and is checked from the browser. Deleting your own account now shows the same preview first.
- **Plugin settings, the foundation**: an asset or exchange-rate provider plugin can declare the settings it needs (an API key, a region, a limit). Administrators set the instance-wide ones and each user their own, through `GET /api/v1/settings/plugins` and `PATCH /api/v1/settings/plugins/bulk` (all or nothing). Secrets are write-only and stored encrypted with a key derived from the instance key. An instance-wide field can also come from `LIBREFOLIO_PLUGIN_<FAMILY>_<CODE>_<FIELD>` or its `_FILE` form, which locks it. justETF and Borsa Italiana declare a search preference, and **Settings › Plugins** shows every plugin's settings.
- **Email links**: every link an email carries is built from `LIBREFOLIO_PUBLIC_URL` alone. While email works, the start log and Settings › Administration › Email say when that variable is missing or cannot be used, and `GET /api/v1/system/instance` tells whether emails with a link can go out.
- Settings › Administration › Email checks, from the administrator's browser, that `LIBREFOLIO_PUBLIC_URL` reaches this very instance, and warns, for this device only, when another server answers there or nothing does; the startup warning about `LIBREFOLIO_PUBLIC_URL` now lists every rule the address must follow.
- **Email verification at sign-up**: with **Require Email Verification** on in Settings › Admin, a new account, except the instance's first, waits for a link emailed to its address, valid 24 hours, and signs in once the link is opened; the sign-in page offers to send a new one. The switch turns on only while emails with a link can go out (SMTP and `LIBREFOLIO_PUBLIC_URL`); turning it off always works and leaves the waiting accounts waiting. Verification emails go to the same mailbox at most 3 times an hour, and past 10 sign-ups an hour from the same network the accounts are created without their email: their owners ask for the link again from the sign-in page. API: `POST /auth/register` answers `verification_required`, or 409 `EMAIL_VERIFICATION_UNAVAILABLE` when no email with a link can go out; `POST /auth/login` answers 403 `EMAIL_NOT_VERIFIED` to a waiting account; `POST /api/v1/email/verification/confirm` and `/resend`.
- **Forgot password by email**: when email works and `LIBREFOLIO_PUBLIC_URL` is set, *Forgot Password?* on the login page asks for your username or email and sends a single-use reset link, valid 30 minutes, to the account's address. The answer is the same whether an account matches or not, and requests are limited per client, per name typed and per mailbox. The server commands stay, in a panel closed by default; without email the card shows them as before. API: `POST /api/v1/email/password-reset` (202).
- **Send by email**: the invitation and password-reset link dialogs of Settings › Users can email the link, a reset link in the language of its account and an invitation in the language chosen in the dialog, the instance's by default, with the outcome naming the language used, when email works and `LIBREFOLIO_PUBLIC_URL` is set. API: `POST /api/v1/email/links`.
- **Notice of an email change**: when email works and someone changes the email address of an account, LibreFolio writes to the address it had before, showing only the domain of the new one, so its owner learns of a change they did not make. At most 3 such notices go out an hour per account and per old address; past that the change still goes through, without the notice.
- `GET /api/v1/brokers/import/files`: each file carries `can_delete`, true when the caller may delete it.
- Test configuration shows until when a provider is paused after too many requests. API: live prices, asset refresh and FX sync results carry `error_code="RATE_LIMITED"` and `retry_after`.
- **Scheduled wake-up**: `POST /api/v1/system/wake-sync` runs the price and exchange-rate updates that are due, for a hosting panel or a cron; off until `LIBREFOLIO_WAKE_TOKEN` is set. Documented in the new admin page "Sleep and Wake".
- **Files page: a Visibility column** shows whether each file is shared with every user or personal. From the row menu or a grid card you can share a file with everyone or make it personal again, with a confirmation, since the others lose it.
- **Restore an instance backup**, from **Settings › Backup** or with `./dev.py backup restore ARCHIVE`. The archive is first checked on a copy — unpacked, brought to this version's schema and verified — and the report says what the restore would do: the backup's administrators, the migrations applied, the rows, and whether the ledger's totals still match. Nothing changes until you confirm. In the app you type a word shown in your language (pasting is refused); LibreFolio then restarts, and its next start applies the restore: the data swaps places with the checked copy in an instant, and if that start does not complete, the next one puts the data of before back. Success leads to the sign-in page; a failure shows on the same screen, with the reason. `--dry-run` still checks without restoring, and hosting providers can cap the upload with `LIBREFOLIO_BACKUP_MAX_UPLOAD_MB` (500 MB by default in the managed profile).
- **The old instance key at a restore** — `./dev.py backup restore ARCHIVE --instance-key-file FILE` takes the instance key of the installation that made a clear backup (a copy of its `secrets/instance.key`, or its old `LIBREFOLIO_INSTANCE_KEY` in a file). The check re-encrypts the saved provider keys with this installation's key instead of leaving them to be entered again. Command line only, with or without `--dry-run`; the key is never printed.
- **A legal notice**: a short disclaimer under every sign-in page, at the foot of the sidebar, in Settings › About, on the welcome page and at the end of every AI Export (before the answer-language line), in your language. An instance can link its own terms of service and privacy policy with `LIBREFOLIO_TOS_URL` and `LIBREFOLIO_PRIVACY_URL`.
- **Cancel an administrator's setup link**: Settings › Administration › Users offers «Cancel setup link» on the administrator still waiting for its setup. The handed-over link stops working, the account keeps waiting, and `./dev.py user setup-link` gives a new one; the waiting administrator can also be deleted directly, while «Remove administrator» stays off for it.
- **Secure backups** — in Settings › Backup, choose a *clear* backup (a plain `.zip`, as before) or a *secure* one: an `.lfbk` file encrypted with a password you choose, with the same rules and strength meter as account passwords and at least 12 characters. Only that password opens it, and a lost password cannot be recovered. A secure backup also carries the instance key that protects your saved provider keys, so restoring it on another installation keeps them.
- **Restoring a secure backup** — pick the `.lfbk` and type its password: a wrong password asks again, without sending the file again. The report says how many saved provider keys are re-encrypted with this installation's key, and how many must be entered again.
- **From the command line** — `dev.py backup create --encrypt` (or `--password-file`, `--password-stdin`: a password is never an argument), `inspect` and `restore` of an `.lfbk`, and `dev.py backup decrypt FILE.lfbk -o FILE.zip` to move an installation by hand.
- `./dev.py backup pending` shows the restore waiting for the next start, or how the last one ended; `--cancel` drops it together with its checked copy. A restore found waiting can also be restarted or cancelled from **Settings › Backup**.
- A restore never takes a database back to an older version: an archive made by a newer LibreFolio is refused (update first), and an older one is migrated on the copy. The archive must hold an active administrator. The instance key (`secrets/`) is never in it, so the restored instance keeps its own key: plugin secrets saved with another key must be entered again, and until then every start logs how many.
- Backups record the ledger's totals (cash per broker and currency, quantity per broker and asset): checking an archive compares them on the copy and warns when they differ.
- API: `POST /api/v1/backup/restore/restart` answers with a one-time `outcome_ticket`. For an hour, `GET /api/v1/backup/restore/outcome` with that ticket in the `X-Restore-Ticket` header, and no session, tells whether the restore was applied, rolled back (and why) or is still waiting — so the page knows the outcome even when the restart signed everyone out, as it does without `JWT_SECRET`. `DELETE /api/v1/backup/restore/pending` now drops the checked copy too.
- New admin guide, **Backup, Restore and Moving Your Instance**: what a backup holds; making, checking and restoring one; and moving LibreFolio between a hosted instance and your own server, both ways.
- **Settings › Plugins**: price and exchange-rate sources can ask for settings. Personal ones are yours; instance-wide ones (an API key, for example) are set by an administrator, and a saved secret is never shown again, not even in a source's error message or in the address of an asset's page. A server variable can set the instance-wide ones and lock them. Each family and each plugin is shown with its icon.
- **Asset search**: justETF and Borsa Italiana can show only your preferred currency or language; a provider that still needs settings says so, with a «Configure» button, also in the provider panel of an asset; a legend explains the 👑.
- **Idle suspension on Fly.io**: with `LIBREFOLIO_IDLE_SUSPEND_MODE=fly` the machine asks Fly to suspend it after `LIBREFOLIO_IDLE_SUSPEND_MINUTES` (5) without a user and with no work in progress; Fly resumes it at the next request. Off by default; documented in the admin page "Sleep and Wake".
- `LIBREFOLIO_CLIENT_IP_HEADER`: behind a reverse proxy that passes the visitor's address in a header of its own (`Fly-Client-IP` on Fly.io, `X-Real-IP` from Nginx), the per-address limits of the emails (sign-up, «send the link again», forgotten password) count each visitor on their own instead of all visitors together. Unset by default; set it only when every request crosses that proxy. Without it, behind a proxy LibreFolio does not trust on a local address (a proxy container in front of the Docker image), these limits leave its requests out instead of counting every visitor together; the other limits still apply, and the log and the security checks say so.
- **A limit on failed sign-ins**: after 10 wrong passwords in 15 minutes for one username or email address, or 50 from one address, sign-ins wait (the login page says so). Wrong current passwords when changing the password or the email address, and **Send the link again**, count too. On by default; `LIBREFOLIO_LOGIN_LIMIT=off` turns it off for test instances, with a warning at every start. Behind a reverse proxy on a local address that LibreFolio does not trust, only the per-name limit applies, and the server logs a warning; trust the proxy with `FORWARDED_ALLOW_IPS` or `LIBREFOLIO_CLIENT_IP_HEADER`.
- **Settings: an «Administration» group and a «Security» tab** — the administrator's tabs (Users, Email, Backup, Scheduler…) sit under one group, and the new Security tab shows the instance's configuration checks, with a badge on the group when one needs attention. The tab bars never leave the selected tab under their edge fade.
- API: `GET /api/v1/security/checks` (administrators) evaluates the instance's configuration checks on demand.
- The start log names an unusable hosting-panel backup token (`LIBREFOLIO_BACKUP_DOWNLOAD_TOKEN`) or restore upload limit (`LIBREFOLIO_BACKUP_MAX_UPLOAD_MB`) right away, not at the first call.
- While the server catches up on prices — at startup, on the first visit after a pause, or at a scheduled wake-up — the app shows "Updating prices…" above the pages.
- `./dev.py user set-email <username> <address>` changes an account's email address from the command line (sessions ended and verification reset on a real change, as from the Profile).
- **Faster first broker import, optional**: `LIBREFOLIO_BRIM_PREWARM=true` prepares the broker-import processes at startup, with their plugins loaded, so the first import after a start is about 4 s faster, at the cost of about 80 MB of memory and 1.4 s of CPU at every server start. Off by default.
- **The sync window warns before you start** when the period already holds stored prices or rates: it says how many of the assets or pairs have data there, which the sync replaces with the provider's values, manual edits included. On the Assets and FX pages, and on the detail pages of an asset or a pair.
- **Test configuration says what it read**: only the last few days of prices, while a new asset gets its whole price history when it is created.
- **Premium sources first in the asset search**: an instance can mark price sources as premium (`LIBREFOLIO_ASSET_PROVIDERS_PREMIUM`) and set their order (`LIBREFOLIO_ASSET_PROVIDERS_ORDER`). When a premium source takes part in a search, its results come first under a «Premium» badge, and the others wait in a closed «Non-premium sources (community)» section that, once opened, warns that LibreFolio does not vouch for them. Without a premium source the list looks as before.
- **«Can't find it? Let us know»** after every asset search: a report of the search — the text, the sources asked and what each answered, the currency, type and identifiers already in the form, the version — sent from your own device. `LIBREFOLIO_SUPPORT_URL` says where: an email address (`mailto:` and one address), or a support page that opens with the report in its address (`title` and `body`, as for a GitHub issue, so a support form can fill itself in) and copied for you; without it, on a self-hosted instance, a GitHub issue you review before sending; on an instance run by a hosting provider the link appears only once the provider sets an address. Nothing about you or your portfolio goes in it.
- **Dashboard: a transfer between two brokers you own at different shares now shows an info note**: each side counts at its own share, and the difference counts as a gain or loss.

### 🔄 Changed

- **Leaner database indexes.** The upgrade to 1.3 removes 13 database indexes no query used: copies of the indexes unique constraints already have, and shorter versions of other indexes. Every new price now updates one index fewer, and price history takes about a fifth less space with its indexes. An existing database file keeps its size: the freed space is reused as new data arrives. Backups are written compact.
- The same portfolio report requested twice at once (two tabs, a refresh during a slow load) is computed once.
- **One change over the range, from the server.** The change over the selected range on the Assets cards, in the FX table and cards, on an FX pair's page and on an asset's page is now computed by the server, so the same figure appears everywhere; beside a live price it is the change up to that price. A price written down to 0 shows −100 %, and a change that cannot be computed in the display currency is left out instead of mixing currencies.
- AI Export: when a value is unavailable in every row of a table, the prompt now names that column right after the table instead of leaving it out silently (unless a null there only means "none", such as an open lot's closing date or a single asset's portfolio weight), so the AI can tell missing data from data that isn't part of the export.
- A user's base currency is saved only as an ISO 4217 code, and a refused currency now names the ISO code it stands for (`'840'`: USD).
- Requests that save a currency accept only ISO 4217 alphabetic codes; names such as "Euro" or numeric codes such as "978" are refused (422). Stored data is read as before.
- After a cancelled setup link, the startup log says the link was withdrawn, not that it expired.
- The Dashboard warns when transactions are dated before 1900: they still count, but the history starts on 1 January 1900.
- Testing a provider's settings is limited to 30 times a minute per user (`LIBREFOLIO_PROBE_RATE_LIMIT`, `0` turns it off); a scheduled investment holds at most 10,000 manual events.
- `./dev.py user deactivate` on the administrator still waiting for its setup cancels its setup link; `./dev.py user demote` refuses it.
- On very large instances the asset and FX lists load their prices in several requests, each within the server's limits, instead of one oversized request.
- **Lots with a broken history**: when an asset's lots cannot be rebuilt (for example a sale of more units than were held), the lots panel no longer draws lots it cannot trust. It says why, lists each transaction to fix (day, broker, a link) and keeps only the average-cost lines; AI Export lists the asset as failed instead of adding wrong figures to the totals.
- On a managed instance (`LIBREFOLIO_PROFILE=managed`) the app no longer invites users to donate (no coffee links, no popup) and never checks for updates (no «Check for updates» in the changelog). «Forgot password?» asks users to contact their administrator instead of showing server commands. None of this shows before the server has said which kind of instance it is.
- An empty or blank secret counts as not set, as if the variable were absent.
- Changing your password or your email signs out every other device; the one you changed it from stays signed in.
- **Changing your email asks for your current password** in Settings › Profile.
- A password reset from the command line, a deactivation or a demotion signs the account out of every device; reactivating an account does not bring its old sessions back.
- Import wizard: when a broker's default plugin, DEGIRO or the Generic CSV, cannot read an uploaded file, the wrong-broker prompt gives the reason in your language.
- `GET /api/v1/system/info` without a session answers only the app version; signed-in users still get the full report.
- The list of exchange-rate providers no longer waits for the ECB and the SNB every time it opens: each provider's currency list is kept for a day, and a slow or unreachable provider is given up after 5 seconds, showing the last list it gave.
- «Enable registration» becomes «Registration»: the upgrade keeps an open instance open and a closed one closed. The login page offers «Register here» only when registration is open, or while the instance has no account yet.
- `./dev.py user create`, `invite` and `activate` warn, then go ahead, when the instance has reached `LIBREFOLIO_MAX_USERS`.
- `LIBREFOLIO_MAX_USERS` also counts the accounts waiting for their email verification, while their link is live: reactivating one of them, from Settings › Users (`holds_place` in `GET /api/v1/users`) or `./dev.py user activate`, takes no new place even on a full instance. Activating or deactivating an account, through the admin API or the command line, revokes its verification link.
- API: refusals of `POST /auth/register` carry an error code (`REGISTRATION_DISABLED`, `INVITE_REQUIRED`, `INVITE_INVALID`, `USER_LIMIT_REACHED`). `GET /system/instance` carries `accounts`, with `first_account_open` true while the instance has no account.
- Docker: the image exposes only port 6040, and both compose files set `PORT=6040` inside the container; `PORT` in `.env` still chooses the host port. The unused 6041 mapping is gone.
- **Live prices pause while you are away.** On the Assets page (every minute) and on an asset's page (every 30 seconds), live prices stop refreshing while the tab is in the background or after two minutes without using the page, with a small «Updates paused» label, and start again by themselves as soon as you come back. An asset's page now sends one request per refresh instead of two, and none at all on a date range that ends in the past.
- **Saving the asset events editor is all or nothing.** The Events tab saves deletions, edits and new rows in one step: if anything is refused, none of them is kept, and the message, in your language, names the event at fault. An event linked to transactions can no longer be deleted together with other changes: the save stops and says which event and how many transactions use it, so remove the link first. Until now the other changes were saved and that deletion was skipped with a warning. Deleting an event and giving its date and type to another in the same save now works.
- **«+ New event» never overwrites an event.** On a date and type the asset already has, entered by hand or from a data provider, nothing is saved: the form shows the event already there, to use it or, if entered by hand, to edit it. Until now the new event replaced the manual one of that day and type, or added a manual copy next to a provider's.
- Logs: the startup and shutdown lines are written by the logger `backend.app.services.platform.app_lifespan` (before: `backend.app.main`).
- `LIBREFOLIO_WEB_LINK_FINDER_TIMEOUT` and `_MAX` below 1, or not a finite number, take their default. A timeout under a second used to mean no timeout, and `0` still returned one link. A fractional timeout is now honoured, rounded up to whole seconds.
- **The server stops within 8 seconds.** After a `docker stop`, a restart or Ctrl+C, requests still running after 3 seconds are cancelled and what they had not saved is rolled back; the server's own work (scheduled syncs, workers, caches) gets the rest of the time, and worker processes still alive are ended, so none is left behind. If something still holds the server when the time is up, it ends anyway and its log says what was still running. `LIBREFOLIO_SHUTDOWN_TIMEOUT_SECONDS` changes the budget (`0`: no limit, as before). Docker waits 10 seconds by default: if you raise the budget, give the container more time too (`stop_grace_period`).
- **Uploaded files have a scope.** Common files (images: icons, logos, asset photos, avatars) are visible to every signed-in user; personal files (every other type) only to their uploader and the administrators. Files uploaded before this version follow the same rule.
- API: `POST /api/v1/uploads` accepts `scope`; `PATCH /api/v1/uploads/{id}` changes it; file info carries `scope` and `can_delete`. Another user's personal file answers 404, as a missing one.
- **Yahoo Finance no longer retries a "too many requests" refusal three times**: like every price and exchange-rate provider, it pauses. During a pause the last stored price stays on screen.

#### 🔒 Security

- A username can no longer contain `@`, and an email address can no longer be another account's username. Sign-in reads an identifier with `@` as an email address first, so an account named after someone else's address can no longer take over their sign-in or lock them out. Existing usernames with `@` stay; their owners sign in with their email address.
- Price and FX queries no longer accept date ranges without a ceiling: the end stops at tomorrow and the FX start at 100 years before it; a range reaching year 9999, which previously exhausted the server and ended in an error, now answers at once.
- Price and FX queries now refuse at once, with an explicit error, a request of more than 1,000 items or one that would build more than 1 million daily points; such a request could previously hold the server for minutes.
- A risk analysis or an AI Export over a very long period with many assets no longer fails with a server error: it tells you to choose a shorter period (or fewer assets).
- A risk analysis or a historical replay over a very long or future period no longer walks every day of it: the period ends tomorrow and spans at most 100 years, and a suggested replay window stays inside it.
- Current prices: an asset requested twice is fetched once, a request over 1,000 assets is refused, conversions over many currency pairs no longer fail, and server errors no longer show internal details.
- A number that is not finite (`NaN`, `Infinity`) nested in a provider's parameters or in a risk analytic's parameters is refused (422): a provider's was saved and read back as `null`.
- The test doubles shipped in the image (`mockprov` for prices, `MOCKFX` and `MOCKFX_FAIL` for exchange rates) are no longer reachable outside test mode. Before, any signed-in user could assign `mockprov` to an asset, which is shared, and give everyone a made-up price series, or route a currency pair through `MOCKFX` and give every conversion a made-up rate. To check an existing instance, look for an asset whose price source is `mockprov` and for an exchange-rate route that names `MOCKFX`.
- Frame protection (`LIBREFOLIO_FRAME_PROTECTION`, on in the managed profile) now also enforces `object-src 'none'`, `base-uri 'self'` and `form-action 'self'` on HTML pages.
- Frame protection's page policy now also covers SVG and XML documents, and a 304 Not Modified response carries no policy that could replace the cached page's.
- A restore's archive cannot fill the disk: the check refuses, before unpacking anything, an archive whose files add up to more than `LIBREFOLIO_BACKUP_MAX_RESTORE_MB` (`unpacked_too_large`). There is no limit by default on your own installation; in the managed profile it is 8 times the upload limit (4000 MB). `backup restore` follows it too, and the Security tab reports a value that cannot be used.
- CSV exports are safe to open in a spreadsheet: in the price, event and exchange-rate exports, a text cell that starts like a formula (`=`, `+`, `-`, `@`) gets a leading apostrophe, so Excel, LibreOffice or Google Sheets show it as text instead of running it; numbers are untouched, and importing an exported events file removes the apostrophe again, so notes come back exactly.
- A secret file read as root cannot be a trap: `./dev.py backup` reads `--password-file` and `--instance-key-file` only from a regular file (a FIFO, a folder or a device is refused, never waited on), and, run as root, never through a link inside the data directory, which LibreFolio's user could have planted to point at a file only root may read.
- The initial administrator's setup link can't be replayed: no new link goes to an account set up meanwhile, and a leftover link of an account already set up is refused and retired.
- A configuration check reports `LIBREFOLIO_TEST_MODE` turned on outside LibreFolio's own test runs as an error, in the startup log and in Settings › Administration › Security; with the managed profile the server does not start.
- The post-migration and broker-report lock files no longer follow a symbolic link planted in their place, and are created readable by the server's user only.
- A password change and an administrator's sign-out-everywhere arriving at the same moment both end the sessions: the cookie the first issued no longer survives the second.
- The in-memory limits forget the visitor with the fewest attempts first: a flood of new usernames or addresses no longer resets the count of one being guessed.
- In the managed profile, the startup log and the security checks report frame protection turned off (a warning) and the report-only Content-Security-Policy turned off (info).
- Behind a reverse proxy LibreFolio does not trust, the limits per visitor's address no longer count every visitor together: such requests are left out, and LibreFolio warns once in its log and in the security checks until `FORWARDED_ALLOW_IPS` or `LIBREFOLIO_CLIENT_IP_HEADER` is set.
- **Nothing left in clear after a crash** — at every start, LibreFolio removes what a backup, a restore check or `dev.py backup inspect` left on disk when it was stopped outright (a power cut, `kill -9`): a decrypted archive, even a partial one, an `inspect` folder older than an hour, and the database copy and clear zip of a backup that died. Nothing a running command still holds is touched, and nothing through a link. Finished backups past their hour are removed at start too, not only at the next backup.
- **Passwords never shown** — `--password-stdin` at a terminal now asks the password without showing it (twice for `dev.py backup create`), and the password fields of a secure backup in Settings › Backup are marked as new passwords, so a password manager does not fill in your account password there.
- **What a decrypted backup holds** — `dev.py backup decrypt` now says when the zip also holds the instance key, which opens every saved provider key.
- **The secure backup's envelope** — scrypt (32 MiB per attempt) and AES-256-GCM in authenticated chunks: a file that was changed, cut short or reordered is refused, and a crafted header cannot push the password check past about 64 MiB of memory. An `.lfbk` downloads as a plain binary file, never presented as a zip.
- **The instance key leaves only inside a secure backup**, and only when LibreFolio generated it: a key given by the environment or a hosting panel never leaves. A restore keeps the installation's own key.
- **Passwords and clear copies are never left behind** — a password is never stored or logged, and a malformed request to the backup routes (and to the plugin settings) no longer repeats its body in the error. The clear copy that `inspect` and `restore` decrypt into a private folder is removed at the end; one an interrupted `inspect` left behind is removed by the next one once it is an hour old.
- The setup link of the initial administrator stops working once the account is set up another way (activated, or given a password, from the command line or with a reset link), and when its address changes.
- Validation errors (422) no longer repeat the values that were sent: no password or token comes back in an error response.
- Emails that can be requested without being an administrator (password reset, email verification, and the notice of an email address change) now greet the reader without the account's username, and the notice no longer shows the new address. The per-mailbox email limits count the aliases of an address (`name+tag@…`, dots in Gmail addresses) as one mailbox.
- **Broker reports uploaded by older versions are no longer open to every user.** A report stored without a broker could be listed, read, parsed and deleted by any signed-in user. Now only the user who uploaded it and an administrator can reach it, and only an administrator when no uploader was recorded.
- **Parsing a report checks the broker it imports into.** The parse compared the report with the transactions of the broker named in the request without checking that the caller could edit it. It now needs EDITOR or OWNER there too, as the duplicates check already did.
- **Report file ids are checked first.** An id that is not a file's own UUID answers 404; a very long one used to cause a server error.
- **Thumbnails of uploaded images are no longer kept by shared caches**: they are sent `Cache-Control: private`, so a proxy in front of the instance does not store them.
- **Every response carries `X-Content-Type-Options: nosniff` and `Referrer-Policy: strict-origin-when-cross-origin`.** Fonts and source maps are served with their own type, also without the system's MIME table.
- `LIBREFOLIO_FRAME_PROTECTION` and `LIBREFOLIO_CSP_REPORT_ONLY`, off by default: frame protection (`X-Frame-Options: SAMEORIGIN`, `Content-Security-Policy: frame-ancestors 'self'`) and a report-only Content-Security-Policy on the web app's pages, which blocks nothing and lists in the browser console what an enforced policy would block; the web app's own inline scripts are allowed by their hashes, so they no longer appear there.
- **Changing your email address or your password, or an administrator setting a new password with `./dev.py user reset`, now cancels every password-reset link still open for the account**: a link asked for before the change no longer works.
- A failed sign-in no longer writes the username or email address that was typed into the server log: the log names the account by its id when it exists, and nothing otherwise.
- Updating your profile no longer writes your email address into the server log: the log notes only whether the address changed.
- **A restore ends every session and expires every invitation and link sent before it.** Users sign in again with the accounts and passwords of the backup.
- **A restore is never applied while the hosting provider blocks the instance**: one confirmed before the block waits for the unblock. On a blocked instance every restore route answers 423, except reading the outcome of a restart with its ticket, which changes nothing.
- **The outcome ticket stays out of logs and URLs**: the server keeps only its hash, it travels in a header and expires after an hour; `ticket` joins the query parameters the access log masks.
- **A tampered backup cannot run code during a restore check** — a check now refuses an archive whose database holds triggers, views or virtual tables, which LibreFolio never creates, before anything of it can run (`database_foreign_objects`): a crafted backup can no longer keep the check busy forever or bring its own code into the server. The schema is read without running any of it, and the connections to the copy use SQLite's `trusted_schema=OFF`.
- Prices and exchange rates entered by hand are now refused, with an explicit error, when dated after tomorrow, and provider data dated after tomorrow is skipped. Dates far in the past are accepted: charts and risk analyses no longer walk hundreds of thousands of days because of them.
- A price dated far in the past (e.g. year 1), stored by an older version, no longer makes an asset's full-history drawdown load hundreds of thousands of days: the history starts on 1 January 1900.
- The restore outcome route, which answers without signing in, no longer fills the server log: it reads the restore's state only for the ticket of the restart, and a ticket file it cannot use is logged once, not at every request.
- A restored backup's database can no longer make the server run code through its schema: every database connection turns SQLite's `trusted_schema` off first and reads the schema again last, so a `CHECK`, a `DEFAULT` or an index that calls a function the app registers is refused instead of run, in the server and in the restore check's upgrade.
- A restore's check now refuses, as a damaged database, an archive whose schema calls a function LibreFolio's server cannot use. Before, such an archive ended the check with a generic error (`dev.py backup restore` stopped with a traceback), or passed the check and broke the first start after the restore.
- Unexpected errors in the asset and exchange-rate requests (assets, their providers, events and market data; exchange-rate providers, routes and sync) no longer reveal internal details, such as database errors, in their answer: it says only which action failed, and the details go to the server log.

#### 📚 Documentation

- The admin guide says what to do when LibreFolio has replaced a lost instance key: put your copy of `secrets/instance.key` back before anyone enters a plugin secret again.

### ⚠️ Breaking changes

- **`POST /api/v1/assets/prices`: `-1` no longer empties a field.** Open, high, low and volume take a number of 0 or more, `null` (or no field) to leave the stored value as it is, or the string `"clear"` to empty it; `-1` is now a negative number, refused with 422 like any other. A close must be above 0.
- `POST /api/v1/fx/currencies/rate`: when every rate in a request is refused, the 400 answer's `detail` is now an object `{code: "fx_rates_refused", message, rejected}` instead of a plain string (the `message` keeps the old text). API clients that read `detail` as a string should read `detail.message`.
- The global setting `enable_registration` becomes `registration_mode` (`open`, `invite`, `disabled`): an API client that read the old key must read the new one.
- **`DELETE /api/v1/assets/events` requires `asset_id`.** Only that asset's events are deleted, so a wrong or crafted request can no longer delete another asset's events. A request with `ids` alone is refused (422), and an id of another asset answers `not_found`, its event untouched. A client deleting events must send their asset.
- **`POST /api/v1/assets/events` answers a refusal with an object.** `detail` is `{error_code, message, params}` instead of a sentence; `params` names the item (`item_index`, `asset_id`) and the events at fault. A missing asset is now a 400 instead of a 200 that saved nothing. A client showing `detail` as text must read `detail.message`.
- **The four placeholder backup endpoints are removed**: `/api/v1/backup/export`, `/backup/restore`, `/backup/formats` and `/backup/status` only answered "not implemented". The instance backup has its own endpoints under `/api/v1/backup/instance`.
- **A new instance registers by invitation.** Its first account signs up without one and becomes the administrator; every later account needs an invitation link, unless an administrator sets «Registration» to Open. An upgraded instance keeps the mode it had.
- `GET /api/v1/settings/global` and `/settings/global/{key}` need a signed-in session: an API client must sign in to read them.
- `PUT /api/v1/auth/profile` with a new `email` needs `current_password`: missing → 400 `CURRENT_PASSWORD_REQUIRED`, wrong → 400 `CURRENT_PASSWORD_INVALID`.
- `POST /api/v1/auth/register`, `/auth/change-password` and `/auth/password-reset` refuse a password that misses a rule with 400 `PASSWORD_TOO_WEAK` and the `rules` it misses, checked before anything else; until now the API asked only for 8 characters, with a 422.
- **Email addresses are unique regardless of capitals.** An address another account already uses with other capitals (A–Z) is refused like an exact duplicate: `400 Email already registered`, or `ACCOUNT_EXISTS` at registration. If two existing accounts share an address apart from capitals, the upgrade stops at that step and names them by id and username, with no account changed: give all but one of them another address with `./dev.py user set-email <username> <address>`, then start again. Restoring an older backup that holds two such accounts fails its check the same way (`upgrade_failed`): separate them on the instance that made the backup, then back it up again. No account is ever merged. Letters outside A–Z still compare as written.

### 🐛 Fixed

#### 🔒 Security

- Asset names, broker names and notes that contain markup are shown as plain text in tables, chart tooltips, notifications and validation messages, instead of being interpreted as HTML. This closes a stored cross-site scripting issue present since v1.0.0, where a crafted asset name could run code in another user's browser.
- **Plugin diagnostics now require signing in.** The endpoint behind the plugin diagnostics of the About page answered anyone who could reach the server, with the import errors of the installed plugins — exception text that can include internal paths. It now requires a session, like the update check next to it. Present since v1.1.0.
- **The average purchase cost API now requires signing in.** `POST /portfolio/wac`, which returns a broker's average purchase cost and quantity held over time, answered anyone who could reach the server, for any broker. It now requires a session and answers only for the brokers you can see. Present since v1.0.0.
- **Deleting your account removes the brokers you alone own.** Account deletion now applies the last-owner rule to each of your brokers: a broker you are the only owner of goes with its transactions and imported reports, even if you shared it with viewers or editors, and a broker with another owner stays with them, minus your access. Before, those brokers stayed behind with no owner to manage them, and one you had shared with no one was out of everyone's reach. Present since v1.0.0.
- **A deleted record's id is never given to a new one.** A new broker, asset, transaction, user, FX route or asset event no longer takes the id of one deleted before, so a report folder, a bookmarked link or an export still pointing at the old id can no longer land on a new record.
- **The session cookie is `Secure` over HTTPS.** The new `SESSION_COOKIE_SECURE` setting (default `auto`) marks the sign-in cookie `Secure` when LibreFolio is reached over HTTPS, directly or behind a reverse proxy that sends `X-Forwarded-Proto`: Tailscale Serve and Funnel, Caddy and Traefik do, and Nginx needs `proxy_set_header X-Forwarded-Proto $scheme;`. Plain-HTTP access keeps working, and `always` or `never` force the choice. Until now the cookie was never `Secure`.
- **An instance always keeps an active administrator.** `dev.py user demote` and `user deactivate` refuse the last active administrator, and deleting your own account counts only the active administrators: before, the last active one could leave when the others were deactivated. `user activate` and `user deactivate` no longer crash after saving, and `dev.py user` commands exit with 1 when they fail. Present since v1.0.0.
- **Signing in no longer reveals which accounts exist.** A wrong password gets the same answer, in the same time, whether the account exists, is active or is disabled; only the right password learns that an account is disabled, and the sign-in page now says so. Before, the server answered *Account is disabled* before checking the password. Present since v1.0.0.
- **The PDF preview no longer contacts third-party servers.** Every time it opened, it downloaded its engine and stamps from jsDelivr and its interface font from Google Fonts, and it fetched from jsDelivr the fallback fonts a document needed, so offline it never showed a page. Present since v1.0.0.

Now, if the final check finds new or changed duplicates between your files, Import sends you back to the Duplicates step, where the groups that did not change keep your choices; if it only changes which rows are selected, Import stays on the review step; both times it says so.
- The Transactions page no longer asks the server for the same broker dozens of times a second in the background when that broker has no icon, portal URL or import plugin.
- In the bulk editor, a balance problem highlights every row that contributes to it and jumps to the first of them in the order shown. Rows are sorted by date — a pair by its earlier date — so a backdated currency exchange no longer stays at the bottom; the order shown never changes what is saved, and new rows on the same date keep the order in which you added them.
- In the Transactions table, the bulk editor and the import wizard's tables, the header of the actions column stays at the end of the table instead of covering the rightmost visible column when the table is wider than the screen.
- Page-size menus remain reachable in short, scrollable modal tables instead of clipping their first options.
- The Transactions page clears its selection after a saved bulk edit, clone, deletion, addition or import, and after linking or unlinking a pair; cancelling keeps it.
- Uploading broker reports from the Files page or from a broker's **Uploaded Reports** no longer fails with a validation error; the import wizard was not affected. Present since v0.9.0.
- Uploading several reports right after LibreFolio starts no longer fails: while the import plugins were still loading, one of the first uploads after a restart could end in an *Internal Server Error*, or record an incomplete list of the plugins able to read the file.
- Files uploaded before an update offer today's import plugins: after an update LibreFolio checks your earlier uploads against the current plugins, so each file offers the plugins that can read it now. Exports uploaded with 1.1.0 or earlier must be uploaded again, together, to form a report set; while one of them is selected, the wizard now says so and keeps **Parse** disabled.
- Previewing a damaged Excel file now says the file cannot be read, instead of failing with a server error.
- Every CSV importer now reads broker exports saved as Windows-1252 or Latin-1 (for example re-saved with Excel on Windows): accented characters and the euro sign no longer make the import fail, and semicolon-separated files are no longer split on commas.
- The Generic CSV is offered only for a CSV whose first row names a date and a type column (in any language it knows), instead of for every CSV, even those it then failed to read; if you choose it anyway for another file, the refusal names all the missing required columns at once.
- In the bulk editor, applying an imported row with Auto (WAC) cost now clears its *enter the cost* todo, even when Auto was already selected — no more switching to manual and back.
- In the bulk editor, import todos are now worded as in the import wizard: in the interface language when a translation exists, otherwise as the importer wrote them, in the language of the file. The Generic CSV's *missing inherited per-unit cost* blocker is now translated, and Crédit Agricole's todo for a matured bond with no starting position in the file is now in Italian, like its other todos.
- Rows handed over by an import are now validated once right away, whatever their number: above 50 rows the editor used to show no problems until *Validate now*.
- Cloning two separate transactions of the same type in the bulk editor no longer shows them as one linked pair, and cloning a pair together with other rows now keeps the pair linked instead of being refused.
- Resetting one row of a saved pair, or using *Reset selected*, now also resets its hidden half: an edit made through the pair's form is no longer kept on one half and saved alone.
- **An asset transfer in *Auto* keeps the cost of the shares it moves.** Moving a whole position to another broker with the cost basis in *Auto* gave the receiving broker a cost of 0, so the shares' whole value counted as gain; switching an existing transfer, or a pair made with **🔗 Promote pair**, to *Auto* averaged the receiving broker instead of the one the shares came from. The receiving side now takes the sending broker's average cost at the moment the shares left; partial transfers keep the value they had.
- **Promoting two rows into a transfer asks for the cost basis.** A promoted pair whose receiving side had no cost basis was saved anyway, without one; it is now refused with the usual message asking for a cost basis, like any other transaction.
- The analysis detail of an import shows each field to complete as readable facts — the file row, the amounts, the importer's suggestions and the source rows — instead of raw JSON.
- The import wizard's unresolved-assets badge no longer repeats its number (*1 1 assets unresolved*) and uses the singular for one asset.
- **DEGIRO statements are read correctly, in any language.** The importer reads the Account Statement by column position, so English and other-language exports are recognised. Each movement keeps its own amount and currency (amounts came from the balance, and every currency was EUR), sales and dividend taxes get their own types, numbers with a decimal comma and more than two decimals are no longer read as thousands, promotional credits become interest, and rows it cannot classify are listed in a warning instead of being dropped. Currency conversions become linked FX conversions: the review step shows each one as a single row, From/To with the rate the two amounts imply, and ticks both legs together. The Transactions export is recognised and points you to the Account Statement ([#35](https://github.com/Librefolio/LibreFolio/issues/35)).
- **An asset transfer moves one asset, and the same quantity out and in.** The bulk editor — banner and selection toolbar alike — offers to merge two rows into a transfer only when the asset is the same and the quantities cancel exactly, and saving a transfer pair with two different assets, or with quantities that do not cancel (the message gives both), is refused: crossed pairs such as −3 and +5 were suggested, and two new adjustments of −3 and +5 merged into a transfer were saved, creating 2 shares from nothing.
- **An adjustment linked to an asset event is no longer merged into a transfer.** Merging an adjustment linked to a split turned the split's shares into a transfer still tied to the split, which the average cost then read as a split; the bulk editor no longer suggests such a merge (banner, selection or 💡 suggestions), and saving one is refused.
- Opening the bulk editor no longer marks rows with a manual cost basis as modified: *Save All* was enabled at once and re-sent the unchanged rows.
- Cash transfers above about 10 million are suggested for merging only when the amounts match to the cent; a one-cent difference used to be suggested too.
- Merging two new rows into a cash transfer or a currency exchange no longer saves the outgoing side as a positive amount.
- The warning for an empty manual cost basis no longer promises a lot at zero cost: such a row is refused on save, and the warning now says so; for a gift it asks for the donor's original cost, not 0.
- The 💡 merge suggestions follow the *Max Δ days* slider: at 0 (the same day only) the search failed silently and suggested nothing, and moving the slider did not search again until a row changed.
- **The import wizard keeps Next disabled until your brokers have loaded**, so a quick click no longer opens file selection with the uploaded files hidden.

#### 🧩 Asset providers and feedback

- Provider tests and metadata requests ignore stale responses after the asset or provider configuration changes. Late metadata cannot silently overwrite manual edits.
- Equivalent distributions no longer appear different merely because their entries arrived in another order.
- Duplicate broker-name errors include localized recovery guidance and reset when a new dialog is opened. Successful broker creation and deletion receive confirmation toasts.
- Manual update checks refresh release metadata and compare against the running server version. Failed or unavailable checks no longer report “up to date”; a positive success message includes the version detected online.
- Docker image availability checks now complete GHCR's public authentication handshake through the LibreFolio backend, so a published release is no longer rejected because the registry first returns an authentication challenge. Invalid or untrusted challenges still fail closed.
- When you create an asset, the provider data comparison no longer opens on top of the question about which ISIN is the main one: it waits for your answer and never asks the same question twice.
- Borsa Italiana ETFs and ETCs take the currency they are quoted in (EUR), not the fund's denomination currency, whether they are found by search or added from their page address.
- The provider comparison shows the asset type with its icon and name in your language, instead of a raw code such as `STOCK`.
- The Dashboard now warns about assets whose provider has not delivered a new price for more than 7 days, with a **Sync prices** button that refreshes those assets; manual assets are never flagged. The warning existed but was never shown. Present since v1.0.0.
- The Borsa Italiana help link opens its user guide page instead of the developer page.
- Provider descriptions state their real coverage: LibreFolio's Bank of England provider serves 15 currencies, not 20+, the ECB about 30, and justETF gives a current price in USD, CHF and GBP too, not only their history.
- Delete and upload messages show their number again instead of a raw `{n}`: deleted or blocked asset events, the result of deleting exchange-rate pairs, uploaded and deleted broker reports with their bulk-delete confirmation, and the confirmation before deleting distribution entries.

#### 🗓️ Asset events and the data editor

- **Removing an event row you had not saved yet no longer deletes another event.** The data editor sent the row's date as an id, so saving could delete an unrelated event of any asset, the one whose id matched the year (event 2026, for example), unless a transaction was linked to it.
- **Editing an asset event linked to a transaction works.** Changing its amount, notes or type no longer ends in a server error, and the link stays. Changing an event's type now edits that event instead of adding a new one and keeping the old.
- A provider sync no longer fails when one of its automatic events, such as a dividend, is linked to a transaction.
- The events CSV of an asset's backup imports back into the data editor: its `value` column is read as the amount. Imported rows are matched on date and type, so a split and a dividend on the same date no longer replace each other.

#### 📈 Charts

- The amount axes of the Growth and Performance charts no longer print the same label twice (`5.5k` shown as `6k` next to a real `6k`, `1.25M` as `1.3M`), and an axis edge placed automatically beyond the data is no longer labelled as if it were a regular step. The Growth tooltip's total P&L now reads `EUR -12.00` like the other amounts, instead of `−EUR 12.00`.
- The lot comparison chart no longer leaves an empty strip left of its amounts, most visibly on phones.
- At weekly or monthly resolution, the week or month not over yet reads right on the asset and FX charts, the Growth chart, the allocation history and the lot comparison chart: its tooltip dates the value on its last day with data, no longer on the Sunday or the month's last day still to come. On the asset and FX charts its events no longer disappear and their markers sit on its point like the others; on the Growth chart its point stands on that day, so the line no longer reaches a date still to come. Present since v1.0.0.

#### 📉 Risk Analysis

- **The Correlation tab keeps its answers.** The Assets page restarted its live-price check every time its list refreshed, and every restart discarded the risk answers in flight; the check now restarts only when the set of assets changes.
- **A risk answer set aside is asked again.** When the data change while a risk calculation is in flight, its answer is asked for again — up to three attempts in all — instead of vanishing; if it still cannot arrive, the level says so.
- **Fewer results marked partial for no reason.** A carried price or rate degrades a series only when it is older than the 7-day staleness threshold, so weekends and holidays no longer mark risk results partial. On a whole portfolio or broker, a holding without prices of its own no longer marks the portfolio's KPI, VaR, drawdown or comparison partial, since those read the portfolio's own return.
- **Risk warnings read in your language**, with the assets, counts and days they concern, on the Correlation tab too: a warning that carried a number or a name used to show its placeholder in braces. A missing translation falls back to the engine's English sentence, never to a raw key or a placeholder. Present since v1.1.0.
- **A failure inside a risk calculation is reported as ours.** Many internal errors were answered with *The metric is undefined for these data.* — a verdict about your data — and were not logged. They now say the calculation failed and are recorded; a measure that genuinely has no defined value still says so. Present since v1.1.0.
- **A simulation too large to run says so, and what to change.** At the default settings a 67th holding read *Invalid calculation parameters*, and beyond 100 holdings *The metric is undefined for these data*. Each size limit now names its remedy: *Use fewer simulation paths or a shorter horizon*, *Choose a shorter period*, or, for a quasi-Monte Carlo simulation, *Shorten the horizon or choose Monte Carlo sampling*; beyond 100 holdings, *Simulate a broker with fewer holdings instead*. A quasi-Monte Carlo simulation reaches its limit with an ordinary portfolio: at the longest horizon, 10 years, a sixth asset is already too many.
- **The signals of the Risk group have their guide button**, which opens their theory page, like the other indicators. Present since v1.1.0.

#### 💱 Exchange rates and the Dashboard

- **An asset priced in another currency but bought in your display currency no longer shows a zero purchase cost.** With the Dashboard in euro, a US-dollar asset bought with euro counted no cost at all, so its whole value appeared as unrealized gain; the purchase cost is now exactly what you paid. Opening positions and transfers whose cost basis is in the display currency are fixed the same way, and opening positions no longer inflate the total P&L ([#32](https://github.com/Librefolio/LibreFolio/issues/32)).
- **A missing exchange rate is no longer a silent zero or an unconverted amount.** When a rate needed for a purchase cost, a sale or a cash movement is missing, the yellow banner names the pair and the dates, and **Sync rates** downloads them (for a pair without a provider, **View FX** or **Add FX pair** takes you to it); the lots panel reports them too. Until then the affected average price and P&L show "—" instead of a wrong figure.
- **The broker summary API counts sales and transfers.** `GET /brokers/{id}/summary` used to add up purchase amounts in mixed currencies; each holding's cost and average price now come from its purchases, sales and transfers, in the asset's currency, and are empty when part of the cost is unknown: a missing exchange rate (listed in the new `missing_fx_pairs`) or a transfer without a cost basis.
- **Broker cards no longer count a transfer between two of your brokers as a gain or a loss.** Moving money or securities from one broker to another showed a gain on the receiving card and the same loss on the sending one: the capital now moves with them on the day they arrive, as in the broker lines of the P&L view, and while a transfer is on its way its value stays on the sending broker's card.
- **Cash held in another currency is revalued every day.** Exchange-rate gains and losses on that cash now count in its value and in the P&L, in the charts as on the cards, and the Dashboard's total cash equals the sum of the broker cards.
- The Dashboard's **Sync rates** for missing exchange rates now downloads the missing dates. It used to download only the period on screen, so rates missing before a pair's first stored rate stayed missing and the warning never cleared; it now downloads the reported dates plus a week either side (never beyond today), reports each pair, and warns when the provider has no rates for those dates.
- A new currency pair downloads its whole rate history, whichever page it is added from, instead of only that page's period. Pairs added earlier may have a gap at the start of their history: on the FX page choose **All**, click **Sync All** and then **Start Sync**, once.
- The display-currency menus of the Dashboard and of an asset page list only the currencies you can convert to — both ends of each configured pair; the currency a chain route passes through is no longer offered unless it belongs to a configured pair. Preferences and broker settings still list every currency.
- The daily change percentage on the Dashboard and Broker KPI cards no longer shows "+-": it is the change over the absolute value of the previous day's figure, so its sign and colour follow the direction of the change, and it is hidden only when that figure is zero.
- **The Returns card no longer shows 0.00% for a return it cannot compute.** A missing TWRR or MWRR now shows "—", and so does the Timing effect when either of the two is missing: it used to show a difference that does not exist, coloured and labelled as favorable or unfavorable timing.
- **Pages open in your own Default Currency.** The Dashboard, the broker list and broker pages, the risk panel of the Assets page and the AI Export of an exchange-rate pair started from the instance's *Default currency for new users* instead of the **Default Currency** in your preferences. A currency you pick on the Dashboard still takes precedence.
- **The exchange-rate pages speak your language.** Their sync messages, card titles, rate column, rate editor messages and buttons, and CSV import errors were in English whatever the interface language; they are now translated.
- **Syncing prices or exchange rates waits as long as the Timeout you choose.** Every sync request stopped at 120 s whatever the field said, with a message blaming your value; it now waits for your timeout, at least 120 s, and the message names the limit applied.
- **Coming back to the Dashboard no longer reloads what you just saw.** With the same period, currency and broker filter, the KPIs, charts, the Positions tab's **Period** view, lots and Risk tab appear at once, also after opening an asset and returning with its back button (←), and KPI figures already known no longer count up from zero. If something changed meanwhile — a new transaction, new prices, or the live price an asset page checks — the figures stay on screen and move to the new values when the background refresh lands. A price or rate sync that brought nothing new no longer forces a reload, the currency and broker filter now stay for the session like the period, and **Refresh** reloads everything, risk and lots included.
- On the Risk tab, a failed refresh now keeps the figures on screen and tells you so, like the rest of the Dashboard; after you switch to another period or currency, the previous figures are not kept.
- **The Dashboard's *Period* view and lots panel show only the brokers you own**, also when you come back to them. Coming back to the Positions tab used to include brokers shared with you as viewer or editor.
- **The Dashboard's Risk tab now counts only the brokers you own**, like the rest of the Dashboard: brokers shared with you as viewer or editor are no longer part of its figures. It still covers every broker you own, whatever the broker filter.
- The data-quality warning for assets with no recent market price says they are valued at their last transaction price; it said they were valued at cost.
- **An inverted currency pair shows its real change.** On a pair's page, flipping the pair showed the change of the original quote with its sign reversed — −25% where the displayed rate had lost 20%. The page now measures the change on the rate it displays, like the list, the cards and the table. Present since v1.0.0.
- **Lots no longer show an amount in its own currency as if it were converted.** When the exchange rate of a lot's purchase, sale, dividend, fee or tax was missing, the lots panel used the unconverted amount — 2,500,000 dong counted as 2,500,000 euro — in the table, the lot details, the charts and their totals. Those amounts now show "—", and so does every total that includes one; the net figures say they are unavailable, and the yellow banner names the missing pair and its dates. The AI Export marks them as unavailable (`null`), never as zero, and each lot table says how many lots are affected. Present since v1.0.0.

#### ⚡ Faster reports

- **Reports and the Dashboard no longer stall on long currency histories.** A currency conversion now loads only the exchange rates it can use, instead of the whole history of the pair, with identical results: on a real portfolio with rates going back to 2000, a report in a currency other than the base one went from 10–27 s to under 3 s. Thanks to Martin Sova ([#30](https://github.com/Librefolio/LibreFolio/pull/30)).

#### 🐳 Docker and self-hosting

- **The published images ship the production interface again.** Since at least v1.1.0 they contained a debug build of the web app (not minified, with source maps), 58 MB instead of 21 MB. The image build now refuses a debug build, local builds included.
- **The full image includes the documentation screenshots for offline use**, as the installation guide says; until now full and light were identical. The light image, the one `latest` points to, still loads them from the online documentation.
- The installation guide and the release notes name the image tags that exist: `latest` (light), `X.Y.Z` (full) and `X.Y.Z-light`, without a leading `v`. `latest-light`, `v1.1.0` and `v1.1.0-light` never existed.
- **`latest` is the light image.** A release publishes `latest` from the light image, and the full image only as `X.Y.Z`; the light image is published first, so the in-app update notice appears only once `latest` points to the new version. A prerelease publishes only its own tags, and neither moves `latest` nor updates the online documentation. A prerelease is always tagged `X.Y.Z-rc.N` and is never promoted: the release gets a new tag of its own.
- **After an update, the browser loads the new interface.** LibreFolio's pages now always ask the server whether they changed, so a browser can no longer keep running the previous version's interface against the new server — Chromium could, for days, until a manual reload ([#26](https://github.com/Librefolio/LibreFolio/issues/26)).
- **The Tailscale guide's startup script restarts the container when Tailscale fails.** A failed `tailscale up` at boot used to leave the container running but unreachable; the script now exits so Docker restarts it, the compose example adds a health check, and the guide explains how to upgrade an existing container and what to check when it keeps restarting. The Tailscale compose examples of the Italian, French and Spanish guides are valid YAML again.
- **Commands inside the Docker container work again.** Since v1.1.0 every `dev.py` command run with `docker compose exec` stopped at once with *No module named 'backend.test_scripts'*, user management and database commands included, because the image leaves the test suite out. They run again; `test`, `i18n` and the documentation translation commands, which need files the image does not ship, say what is missing.
- The *Password Recovery* card, opened by *Forgot Password?*, shows reset commands that work: `docker compose exec librefolio python dev.py user reset <username> <new_password>` for Docker and `./dev.py user reset` for a manual install, instead of a `./dev.sh` script the image does not contain.
- The image's health check probes port 6040, where the server listens, instead of `PORT`: a container started with `docker run -e PORT=…` is no longer reported as unhealthy while the app answers.
- **Users are no longer signed out at random when the server runs several workers.** An empty `JWT_SECRET=` line in `.env` gave each `dev.py server` worker its own key; it now counts as unset, so the workers share one.
- **Global settings reject invalid values.** The **Settings › Admin › Global Settings** page and the settings API accepted invalid values — a negative session duration, an unknown timezone, a scheduler time such as 25:00 — which could lock every user out or stop the scheduler. Each value is now checked against its type and allowed range, and a save containing an invalid value is refused as a whole, with nothing applied.
- **`dev.py db upgrade`, `current`, `downgrade` and `check` work on the database file you name.** The first three ignored the path and worked on the configured database, `downgrade` included; `db check` called a script that does not exist and now verifies the CHECK constraints.
- On Linux, `./dev.py server` and `./dev.py mkdocs gallery` now report a port that is already in use, and `--force` frees it; until now the check always found the port free.

The first start can take a little longer on a large database. `python -m backend.app.db.post_migration` (`--dry-run` to preview) runs the same step with the server stopped.

- In the import wizard's *Select Files* step, a broker with more than five files lists them five per page, and after an upload only the brokers that received the new files open expanded.

A new tooltip beside an asset's currency says it is the currency its prices are stored in.

- The header hides while scrolling down and returns while scrolling up on desktop and mobile. Focus, open menus and dialogs keep it visible.

The messages that confirm the pair and report its download show it with its flags, as a link to its page, with the rates fetched and changed and the provider on the same line; creating an asset on the Assets page confirms it with a link to the new asset.

Full screen and copying selected text remain. #### 💰 Purchase cost and P&L

- **Purchase cost is what you paid, in the display currency.** Each purchase is converted at its own date's rate, so the purchase cost of an asset priced in another currency no longer moves with today's rate; sales are measured against that cost, and the average price per unit and the yield on cost follow it. In a portfolio held in a single currency, purchase cost and average price are unchanged, except for shares added without a cost basis (below).
- **Shares added without a cost basis are flagged.** A transfer or adjustment that adds shares without a cost basis now counts at zero cost in the totals, its position's average price and P&L show "—", and the yellow banner lists the asset so you can set its cost; the Dashboard used to enter it silently at the current average price. The lots panel flags it too.
- **The unrealized change includes the exchange rate, and its tooltip splits it.** For assets priced in another currency, the Dashboard's *Unrealized change* now includes the effect of the exchange rate, which used to end up in the reconciliation residual; its tooltip shows the assets' own change for each currency and the exchange-rate effect for each pair.
- **Securities that move in or out of a view count as capital, not as profit.** In a view filtered to some brokers, securities sent to or received from a broker outside the filter count as capital at their market value on the day they move, not as a gain or a loss. The same goes for the half of a transfer whose other broker was deleted, securities or cash.

#### 📉 Risk Analysis leaves beta, except the simulation and the asset page

- **Risk Analysis is no longer marked beta.** The beta notice used to sit above every risk panel, saying the whole subsystem was provisional. On the Dashboard, broker pages and the Correlation tab of the Assets page it now appears only in the **Simulation** tool of *What if…?*, where it names the reason: the outcome depends heavily on how much history is requested relative to the horizon, so a short window with a long horizon can produce implausible figures. Below it, a permanent reminder says that the simulation is a model, not a measurement. The asset page's **Risk & Scenarios** tab keeps its beta notice: it has not been rebuilt yet. The risk API, `/api/v1/risk`, leaves beta too: from this release it changes only with a major version, except the simulation.
- **The Dashboard and broker pages no longer show tracking error, information ratio and active return, nor a risk-free rate field**: their ratios use a rate of 0. The asset page's **Risk & Scenarios** tab keeps all three and its rate.
- **The simulation offers five modes and starts on *Reshuffled history***, your own returns reordered in blocks; *Calm market*, *Prolonged crisis* and *Shock and recovery* add a stated assumption, and *Normal curve (GBM)*, the only model before, stays as an advanced choice.
- **The Correlation tab no longer offers the hypothetical shock**: a selection has no weights to shock. Its *What if…?* section replays a past period instead.
- **One benchmark picker on every risk page.** The Dashboard, broker pages, the asset page's **Risk & Scenarios** tab and the Correlation tab share one choice: each opens on the benchmark you last chose, remembered in this browser, and it may be an asset you hold. Only what the page itself measures leaves the list, and a current choice the page measures stays shown with a warning. In a compact picker the chosen asset fits on one line.
- **The benchmark picker shows which benchmarks your period can measure.** On every risk page — the Dashboard, a broker's page, the asset page's **Risk & Scenarios** tab and the Correlation tab of the Assets page — the assets with no usable price history over the period are listed apart, read-only, with the reason. A benchmark you chose earlier that cannot be measured over the period stays chosen and shown, but nothing is compared against it — no beta or correlation, no benchmark row or line — until a period in which it can be measured. If the check cannot be made, nothing is locked.
- **Risk figures follow the markets' calendar.** A weekend or holiday row that only repeats the previous close is no longer read as a quote, so it no longer dilutes daily VaR. Weekday holidays of the main exchanges (TARGET, Borsa Italiana, Xetra, Euronext Paris, LSE, Switzerland, NYSE) are recognised.
- **The data-quality banner reaches the Correlation tab.** One banner above the notice lists what is wrong with the data for all four sections, *What if…?* included: prices outdated or missing, and exchange rates outdated, missing or without a source, each kind once for every asset or pair a section ran into. Its **Sync prices** and **Sync rates** run the tab's own **Sync selection**; the other actions open the asset's page or the FX pages.
- **What if…? opens on a tool selector.** On the Dashboard and on a broker's page, the section offers the historical replay, the hypothetical shock and the simulation as tools you add one at a time, always in that order. Nothing is open on your first visit; after that, the tools you left open come back, in this browser. Closing a tool with its × also removes its answer.
- **CVaR no longer understates the tail.** The previous estimator was biased low, so CVaR now reads a little higher at every confidence level — the prudent direction. The change is relative to the figure: at the default 95%, a few tenths of a percent of it (a 2.00% CVaR reads about 2.01%), more at 99% and on short histories. VaR almost always stays the same: it moves up by one observation only when the number of observations falls exactly on the edge of the tail — at 95%, when it is a multiple of 20.
- **Sharpe and Sortino on the asset page's Risk & Scenarios tab are no longer flattered by a risk-free rate.** The daily rate was spread over 365 days but charged against trading-day returns. At a 2% rate this added about 0.04 to the Sharpe of an asset with 16% volatility, and more on calmer assets: about 0.3 at a 5% rate and 5% volatility. The rate now follows the series' own frequency. At a rate of 0, the default, nothing changes, and the Dashboard and broker figures were never affected.

#### 🕰️ Shock scenarios and result tables

- **The hypothetical shock on the Dashboard and broker pages offers scenarios by asset class, sector or region**, where it used to apply one uniform shock to every holding, **and the replay and the shock show a table.** The replay gives each holding a row, the shock each class, sector or region of its scenario that you hold, named in your language: its weight in the portfolio, its return, its contribution and, for a holding, the amount, beside a bar you can widen; a column with nothing to show is left out, so a selection of assets shows just the return and the bar.

#### 🧠 Technical Analysis

- **Indicators count trading sessions**, as their standard definitions do: an SMA 200 spans 200 sessions, not 200 calendar days, and their period fields say so.

### ⚠️ Breaking changes

- **`GET /brokers/{id}/summary`: the cost fields can be empty.** Each holding's `total_cost` and `average_cost_per_unit` now come from its purchases, sales and transfers, in the asset's currency, instead of adding up purchase amounts in mixed currencies, and are `null` when part of the cost is unknown: an exchange rate it needs is missing — the new `missing_fx_pairs` lists those pairs and their dates — or shares were added by a transfer or an adjustment without a cost basis. A client reading the summary must accept `null` in those two fields.
- **`POST /portfolio/lots/analysis`: amounts can be empty.** When an exchange rate a lot needs is missing, its cost, opening price, realized P&L, proceeds, fees, taxes and income, the unit price of its timeline segments, the P&L, income, fees and taxes of its value history, the asset's unallocated fees, taxes and income, and the shares of the fee, tax and income pools assigned to lots and operations are `null` instead of an unconverted amount. A client reading the lots analysis must accept `null` in those fields.
- **Purchase cost and P&L change value for assets in another currency.** Portfolio and broker reports convert each purchase at its own date's rate and include the exchange-rate effect in the unrealized change, so figures stored or compared from 1.1.0 differ for those assets; portfolios in a single currency keep the same figures, except for shares added without a cost basis.
- **The risk API changed in two ways a client can see**, as its beta status in 1.1 allowed: a VaR's `horizon_days` now counts calendar days, and the result gives the number of observations it compounds in `horizon_observations`; a simulation too large to run answers `resource_limit` instead of `invalid_parameters`.
- **Two endpoints now require signing in.** `GET /system/plugin-diagnostics` and `POST /portfolio/wac` answer 401 without a session; `POST /portfolio/wac` also answers 403 when a requested broker is not shared with you.
- **`PATCH /api/v1/settings/global/bulk` refuses invalid values.** Every value is checked before anything is saved: an unknown key answers 404, a value outside its type or range answers 422 naming every refused key, and nothing in the request is saved. New upper limits: `session_ttl_hours` 8760 (one year) and `max_file_upload_mb` 1024; a larger value already stored stays in effect until it is changed.
- **Behind a proxy that reports HTTPS for a plain-HTTP address, signing in no longer sticks.** With the new default `SESSION_COOKIE_SECURE=auto`, a reverse proxy that sends `X-Forwarded-Proto: https` to a browser on plain HTTP makes the session cookie `Secure`, so the browser drops it and every sign-in ends back on the login page. Make the proxy send `$scheme` instead of a fixed `https`, or set `SESSION_COOKIE_SECURE=never`.

## [1.1.0] - 2026-09-07

The first feature release after 1.0. It introduces the **Risk Analysis** subsystem (beta), rebuilds technical analysis as a backend plugin platform, ships the first public **AI Export V1** catalog, adds 19 new broker importers, and replaces the legacy valuation cascade with a single unified price resolver. ### 🧪 Beta

#### 📉 Risk Analysis — new subsystem

Quantitative risk and allocation analytics, powered by [QuantLib](https://www.quantlib.org/) and [Riskfolio-Lib](https://github.com/dcajasn/Riskfolio-Lib).

> **This subsystem is beta.** Analytic parameters, result shapes and the `/api/v1/risk` contract may still change in a future release without a major version bump. Results are intended as decision support, not as authoritative financial figures — always read the reported data-quality status alongside the numbers.

- **9 risk analytics**, registered through a plugin registry with schema-driven parameter forms (the same pattern already used by Asset, FX and BRIM providers):
    - **Historical risk metrics** — historical volatility, drawdown, Sharpe and Sortino from the selected scope's canonical returns.
    - **Historical VaR / CVaR** — historical-simulation loss estimates at a configurable confidence level and horizon.
    - **Drawdown summary** — dated current and maximum peak-relative drawdown episodes with recovery status (`no_drawdown` / `recovered` / `open`).
    - **Correlation** — Pearson correlation matrix computed on target-currency returns over a joint calendar.
    - **Risk contribution** — current-composition volatility contributions broken down by asset.
    - **Stress test** — apply hypothetical shocks or replay a real historical period, from a typed and audited scenario catalog.
    - **Comparison** — performance and risk measured against a real comparison asset or benchmark.
    - **Simulation** — conditional GBM return percentiles from historical drift and covariance estimates (QuantLib).
    - **Portfolio allocation** — builds a hypothetical composition from the selected sample, strategy, estimators and constraints (Riskfolio-Lib).
- **Scope-neutral analytics** — each analytic declares the scopes it supports (`asset`, `asset_set`, `portfolio`) and the return mode it consumes (`price_only` or `twrr`), so the same engine serves an asset detail page and a whole portfolio.
- **Process isolation** — QuantLib and Riskfolio-Lib run inside dedicated `spawn` workers. A heavy, hanging or failing optimisation can never block the async event loop or take down the API. Idle workers are reaped without interrupting jobs that are still running.
- **Honest failure reporting** — a dedicated error taxonomy (`insufficient_history`, `undefined_metric`, `invalid_covariance`, `optimization_infeasible`, `resource_limit`, `worker_busy`, `execution_timeout`, …) plus a per-result status (`ok` / `partial` / `unavailable` / `failed`). An analysis reports *why* it could not compute instead of silently returning a misleading number.
- **Cached Risk UI** with shared Asset/FX detail controls and content-keyed result caching.
- Monte Carlo random seeds are kept separate from QMC Sobol start indexes, so runs stay reproducible and low-discrepancy sequences are not accidentally correlated.

- **Provider config fields are tidier** — the per-asset provider parameters now show a short inline label with the longer explanation moved into an ⓘ tooltip, and the user manual documents how to set `mic`/`platform`/`codice_fondo` by hand (in all four languages).

#### 🧹 Clean audit re-check — P0 fixes (2026-09-02)

- **Configured base currency was ignored everywhere** — valuation paths read a `base_currency` global key that was never registered, silently falling back to EUR, and the engine's fallback branch called the settings helper with inverted arguments (a guaranteed `TypeError` had it ever run). The effective base currency is now the per-user setting, seeded from the admin-level default at first creation, EUR as last resort.
- **Image previews blocked the API event loop** — Pillow resize in the file-serving endpoint now runs in a worker thread (`asyncio.to_thread`), so a large image no longer stalls every concurrent request.
- **Bulk asset PATCH issued N+1 queries** — assets are now preloaded in one SELECT and the currency-change guard uses per-asset `GROUP BY` aggregates: a 50-asset bulk update drops from ~50+ queries to 4.
- **Silent `except: pass` swallows** — a fixed one in the cache layer (`clear()` could not log a failed close) and a new punctual `S110` ruff gate so the class cannot return.

#### 🧪 Second beta wave — consolidation (2026-09-02)

- **Decimal separator erased while typing** — in the transaction form's amount field, typing `12,` was rewritten to `12` mid-keystroke (the field's own emission came back reformatted); the comparison is now numeric, so `12,` and trailing zeros survive until blur. The quantity field no longer starts pre-filled with `0`, which forced cursor gymnastics to type decimals.

- **Import wizard: transaction types in English** in the analysis summary — now translated.
- **Import wizard: rows stayed deselected** when a broker's opening date was fixed before assigning their asset — the importable-row re-selection now also runs on asset assignment.

The signal now computes against the full available history by default (new `full_history` parameter, shown as a toggle in the signal settings), and AI Export drawdown sections always use the full history regardless of the export period.
- **Charts could freeze the whole API on assets with long FX-uncovered history** — the currency-conversion pass deduplicated its errors inside the per-point loop (quadratic), so a full-history load with thousands of distinct missing-rate days spun the worker at 100% CPU for minutes and every concurrent request timed out (the "technical signals could not be updated" banner). Errors are now deduplicated once per job and capped with a summary line.
- **Docker build shipped without the emoji font on download failure** — a failed Google Fonts fetch was logged and ignored, so the image went out with a broken font link (flags rendered as letters on Windows). #### Earlier in this cycle

- **Inflated ROI on portfolios seeded in kind** — in-kind adjustments contributed to the capital baseline but not to the cash-only flow used as the ROI denominator, so transferred-in capital appeared as pure gain. ROI, TWRR, MWRR and the headline figures now all derive from the same flows.
- **Fully-closed positions showed "—" for annualized return** — realized net return is now annualised over the position's real flight time, dust-aware for partial redemptions.
- **False "valued at cost" warnings** — the data-quality flag was computed over the whole history, so an asset kept the flag forever once it had ever been price-less. It is now evaluated as of the valuation date.

- **Cost basis flat after a bond maturity** — an unidentifiable Crédit Agricole redemption was booked as a plain cash deposit, inflating paid-in capital. It is now booked as a sale at par.

- **Broker detail page-size selector did nothing** — the grouped transactions table never received the page-size callback.
- **KPI card percentages moved with the selected period** — net worth now shows total P&L over invested capital, and the period card shows the last-day delta.

- Transactions "without asset" filter, dynamic default column visibility in `DataTable`, right-aligned Asset/FX table toolbars, cross-account cache leakage on auth changes, and a number of translation inconsistencies across EN/IT/FR/ES.

### ⚠️ Breaking changes

These affect newly introduced analytics or local UI persistence only — the stable REST API and the database schema are unchanged.

## [1.0.0] - 2026-07-20

LibreFolio is a self-hosted, open-source portfolio tracker: your brokers' reports in,
a clear and honest picture of your wealth out. No cloud service in between — the whole
stack (FastAPI backend, SvelteKit frontend, SQLite database) runs in a single Docker
container on your own hardware. This first release packages the core engine, the import
wizard, and the dashboards that grew up over the project's first months.

### ✨ Added

#### 📊 Core & Dashboard Engine
- **3-Pool Cash Model Engine**: Accurate event-driven balance tracking (Known/Resolved/Working cash pools) with precise separation of transactions.
- **Advanced ROI Solvers**: High-performance implementations for Time-Weighted Rate of Return (TWRR) and Money-Weighted Rate of Return (MWRR/XIRR) with Newton-Raphson boundary caps.
- **Cost Basis Calculations**: Real-time Weighted Average Cost (WAC) calculations and First-In, First-Out (FIFO) cost basis tracking computed at runtime.
- **ECharts Dashboard**: Interactive widgets including growth chart, asset allocation pie, geography distribution map, sector weightings, and portfolio exposure treemap.
- **Responsive Layout**: Collapsible sidebar, touch-friendly UI design, and complete theme toggle (Light / Dark modes).

#### 📥 Broker Report Import Module (BRIM)
- **Import Wizard v5**: Stepper-based import flow for broker statements (Upload, Configure Parser, Analyse, Reconcile Assets & Duplicates, Bulk Review, Commit).
- **11 Supported Brokers**: Native parsers for Interactive Brokers (IBKR), Degiro, eToro, Directa SIM, Charles Schwab, Revolut, Coinbase, Freetrade, Finpension, Trading212, and a Generic CSV mapping tool.
- **On-the-fly Creation**: Prompt to create missing brokers or assets directly during the import flow without aborting.
- **Duplicate Detection**: 4-level duplicate confidence scoring (Likely/Possible with matching rules) to prevent double entry.

#### 💱 Forex & Currency Routing
- **Triangulation Graph**: Arbitrary multi-currency exchange rate conversions via direct or multi-hop path routing.
- **Official Providers**: Auto-sync from European Central Bank (ECB), Federal Reserve (FED), Bank of England (BOE), and Swiss National Bank (SNB).
- **MANUAL Override Sentinel**: Ability to manually input specific exchange rates or edit sync buffers via data grid editor.

#### 📈 Asset Providers & Scheduler
- **Price Synchronization**: Multi-source price updates from Yahoo Finance (async offload), justETF, Borsa Italiana, and custom CSS scrapers.
- **Scheduled Investments**: Automated creation of periodic purchasing/accumulation plans.
- **Scheduler Daemon**: Leader-election backend daemon (psutil/lock-file based) that synchronizes historical and current market data on a cron schedule.

#### 🧠 Technical Analysis (Signals)
- **Indicator Overlays**: Automated charts showing EMA, MACD, RSI, and Bollinger Bands.
- **FX Pair & Benchmark Comparison**: Overlap benchmark lines on any price graph to compare performance.

#### 🔒 Security, Admin & Localisation
- **Role-Based Sharing**: Multi-user permissions on broker accounts (Owner, Editor, Viewer).
- **Static Assets Uploader**: Secure management and crop tool (Cropper.js) for upload of custom broker/user icons and files.
- **PWA Support**: Installable Progressive Web App (PWA) with offline capabilities.
- **Multi-language Support**: Complete localization in English, Italian, French, and Spanish.
