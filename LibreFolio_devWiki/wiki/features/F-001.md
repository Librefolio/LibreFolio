# F-001 — User Authentication & Sessions

## What it does
Provides login, logout, and session management for LibreFolio. Users authenticate with username/email and password; the server issues a JWT stored in an HttpOnly cookie named `session`. The cookie is sent automatically on every request, enabling stateless multi-worker auth without a session store.

First-registered user is automatically promoted to admin. Inactive users are blocked at the `get_current_user` dependency level with HTTP 401.

## Layer breakdown
**Backend**: `backend/app/api/v1/auth.py` (endpoints: POST `/auth/login`, POST `/auth/logout`, GET `/auth/me`, POST `/auth/register`, POST `/auth/change-password`, PATCH `/auth/profile`), `backend/app/services/auth_service.py` (JWT creation/decode, bcrypt hashing), `backend/app/services/user_service.py`

**Frontend**: `frontend/src/lib/stores/app/auth.ts`, login/register pages under `frontend/src/routes/`

## Implementation notes
- Cookie name: `session`, HttpOnly, SameSite=lax, max-age configurable via `GlobalSetting` `session_ttl_hours`;
  `Secure` per `SESSION_COOKIE_SECURE` (see [[features/F-065]])
- JWT payload carries only the user's integer id (`sub`); user record fetched from DB on every request
- `get_current_user` FastAPI dependency used across all protected routes
- `require_admin` dependency (`backend/app/api/v1/settings.py`) raises 403 unless the user `is_superuser`
  (there is no `get_admin_user`)
- Password hashing: bcrypt (the `bcrypt` package directly)
- **Login answers (since 2026-10-09)**: the password is checked first, whatever the account; a wrong password gets
  the same `401 "Invalid credentials"` for an unknown, active or disabled account, and an unknown one still costs a
  bcrypt check against a dummy hash; only the right password learns `403 {"error_code": "ACCOUNT_DISABLED"}` —
  [[problems/login-account-enumeration-before-password]]
- **Account deletion** is self-service only (`DELETE /auth/users/me`): the last-owner rule is applied to every
  broker, all or nothing, and the last active administrator cannot delete their own account
  ([[problems/account-deletion-orphaned-brokers]])
- **App start: only a 401 signs out (since 2026-10-08)** — `auth.checkAuth()` answers `authenticated`,
  `unauthenticated` (a 401 from `/auth/me`), `unreachable` (timeout, network error, 5xx) or `superseded` (a newer
  check owns the screen). Before, `routes/(app)/+layout.svelte` raced the check against a 5 s timeout and sent any
  failure to `/`, losing the page asked for. Now a server silent for `AUTH_SLOW_MS` (5 s) gets the
  `ServerUnreachable` panel with Retry (the client session is kept), and a 401 goes to `loginUrl(page)` =
  `/?redirect=<path+query>`; the global 401 interceptor (`api/zodios-client.ts`) does the same except on the root.
  The destination is user input: `safeInternalPath()` (`utils/internalPath.ts`) honours only an in-app path (one
  leading `/`, no `//`, no `\`, no control character, same origin once resolved). A sign-out the user asked for
  (`isSignOutRequested()`) returns to a plain login — [[sources/phase00-taxonomy-select-2026-10]] (step 19)
- **Register link** is hidden only when the instance says registration is closed (`enable_registration === false`);
  the backend still lets the first user register whatever the setting (`is_first_user`) — residual K-5, a decision
  left to the developer
