# F-002 — User Management

> **Corrected 2026-10-09 (checked at `b0635b0cf`).** This page described an admin CRUD API (`GET/POST /users`,
> `PATCH/DELETE /users/{id}`) and a user-management tab in Settings. Neither exists: `backend/app/api/v1/users.py`
> has only `GET /users/search`, and the Settings tabs are About, Global settings, Preferences and Profile.
> Administration of accounts is done through the CLI.

## What it does
> **2026-10-15 (1.3, `a6a5afc98`)**: administrators also manage accounts from the app — the **Users** tab of
> Settings › Administration (`UsersTab.svelte`) over an admin API under `/api/v1/users` (list, activate/deactivate,
> promote/demote, delete after a preview, sign out everywhere, reset links, invitations); guide
> `admin/users.en.md`. The CLI paragraph below stays true and lists the commands it shares with the tab.

- **Administrators** manage accounts from the command line: `./dev.py user create | list | reset | deactivate |
  activate | promote | demote | init-settings` — since 1.3 also `set-email | invite | reset-link | setup-link |
  reassign-owner | reset-onboarding` — (`scripts/user_cli.py`; in the Docker image through
  `docker compose exec … python dev.py user …`). Since 2026-10-09 a failed command exits with status 1.
- **Every user** registers (`POST /auth/register`; the first account becomes administrator), edits their profile
  (`PUT /auth/profile`), changes their password (`POST /auth/change-password`) and can **delete their own account**
  (`DELETE /auth/users/me`) — see [[problems/account-deletion-orphaned-brokers]].
- `GET /users/search` lets a user find others by username (no e-mail exposed) — for broker sharing pickers and for
  the update-check hint that points a non-admin to an administrator (`admins=true`).

## Layer breakdown
**Backend**: `backend/app/api/v1/auth.py` (register, profile, password, self-deletion), `backend/app/api/v1/users.py`
(search and, since 1.3, the admin routes), `backend/app/services/accounts/user_service.py`.

**Frontend**: `frontend/src/lib/features/settings/tabs/ProfileTab.svelte` (profile, password, account deletion);
`frontend/src/lib/features/settings/tabs/UsersTab.svelte` (administrators, since 1.3).

**CLI**: `scripts/user_cli.py`, registered under `dev.py user`.

## Dependencies
- [[F-001]] Auth — sessions and login.
- [[F-003]] Role System — administrators vs users, and the last-active-admin guard.

## Implementation notes
- `is_active=False` disables login without deleting the account (soft disable).
- Deleting an account applies the last-owner rule to every broker (all or nothing): a broker the user was the last
  OWNER of is deleted with its transactions and report files; elsewhere only the user's access goes. The last
  active administrator cannot delete their own account, nor be deactivated or demoted ([[features/F-003]]).
