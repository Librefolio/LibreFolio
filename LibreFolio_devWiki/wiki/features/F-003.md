# F-003 — Multi-User Role System

## What it does
Two-level role system: **admin** (full access including user management and global settings) and **user** (access to their own data and shared brokers they have been granted access to). At the broker level, a finer-grained Owner/Editor/Viewer model ([[F-010]]) controls per-resource access.

## Layer breakdown
**Backend**: `backend/app/db/models.py` (`User.is_superuser` — the admin flag; `UserRole` — `OWNER`/`EDITOR`/`VIEWER`,
the **broker-level** role stored in `BrokerUserAccess`), `backend/app/api/v1/settings.py` (`require_admin`
dependency), `backend/app/services/user_service.py`

**Frontend**: role-aware UI — admin-only Global settings tab, conditional rendering based on `$auth` store

## Dependencies
- [[F-001]] Auth — role is attached to the authenticated user record

## Enables
- [[F-010]] Broker Sharing — the Owner/Editor/Viewer sub-system extends the role model to broker resources

## Implementation notes
> Corrected 2026-10-09 (checked at `586a4f0ea`): the page said `UserRole` was `admin`/`user`, that a
> `get_admin_user` dependency checked `role == "admin"`, and that roles change through `PATCH /users/{id}`. None of
> the three exists.
- Administrator = `User.is_superuser`. `UserRole` (`OWNER`, `EDITOR`, `VIEWER`) is the per-broker role
  ([[features/F-010]]).
- `require_admin` (`backend/app/api/v1/settings.py`) calls `get_current_user` and raises 403 unless the user is a
  superuser.
- Admin status changes only from the CLI: `./dev.py user promote | demote` ([[features/F-002]]).
- **Last active administrator (since 2026-10-09, train 22)**: demoting or deactivating the last *active*
  administrator is refused (`_is_last_active_admin()` in `user_service.py`, used by `set_user_active` and
  `set_user_admin`), and so is deleting one's own account when one is the only active administrator (400 from
  `DELETE /auth/users/me`). An inactive administrator does not count: they cannot log in to administer the
  instance. The CLI exits with status 1 when it refuses.
- No per-asset or per-FX-pair ACL — only broker-level ACL via `BrokerUserAccess`
