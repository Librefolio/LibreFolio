# F-006 — Global Settings admin-managed

## What it does
System-wide settings managed by admins and visible to all users. Stored in the `global_settings` table as key/value pairs with a `value_type` column. Current keys (`SETTINGS_REGISTRY.global_` in `backend/app/schemas/settings.py`, 2026-11-07): `session_ttl_hours`, `registration_mode`, `require_email_verification`, `max_file_upload_mb`, `backup_cleanup_max_mb`, `backup_cleanup_max_days`, `storage_limit_mb`, the `scheduler_*` keys, `default_currency`, `default_language`, `default_theme`. The `GlobalSettingsTab.svelte` renders these settings in the Administration group of the settings page. *2026-11-07 lint: the page listed `portfolio_base_currency` (no such key) and scheduler settings as planned.*

## Layer breakdown
**Backend**: `backend/app/api/v1/settings.py` (GET `/settings/global` — signed-in users; PATCH `/settings/global/bulk` — admin only), `backend/app/services/accounts/global_settings_service.py`, `backend/app/db/models.py` (`GlobalSetting` model: `key`, `value`, `value_type`)

**Frontend**: `frontend/src/lib/stores/app/globalSettings.ts`, settings page admin tab

## Dependencies
- [[F-003]] Role System — only admins can write global settings

## Enables
- [[F-052]] Market Data Scheduler — scheduler settings (`scheduler_enabled`, `scheduler_current_price_frequency_minutes`, `scheduler_history_sync_times`, `scheduler_history_sync_days`, `scheduler_history_sync_horizon_days`, `scheduler_timezone`) stored here

## Implementation notes
- `GlobalSetting` model: `key` (primary key), `value` (string), `value_type` (`string`/`int`/`bool`/`json`), `updated_by_user_id`
- `get_session_ttl_hours()` helper used by auth to read TTL dynamically
- Environment variables can pin a setting (`LIBREFOLIO_DEFAULT_LANGUAGE`, `LIBREFOLIO_DEFAULT_CURRENCY`,
  `LIBREFOLIO_DEFAULT_TIMEZONE` in `global_settings_service.py`; `LIBREFOLIO_REGISTRATION` in `settings_service.py`). *2026-11-07 lint: the
  page named a `PORTFOLIO_BASE_CURRENCY` variable, which the code does not read.*
- Admins write via `PATCH /api/v1/settings/global/bulk`; `GET /api/v1/settings/global` needs a signed-in session (1.3)
- Three sync wrappers of the async settings readers, never called, were removed: [[problems/sync-functions-dead-code]]
