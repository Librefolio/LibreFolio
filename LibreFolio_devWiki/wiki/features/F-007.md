# F-007 — Theme System dark/light/auto

## What it does
Three-mode theme system: light, dark, and auto (follows OS preference). The selected theme is persisted in localStorage under key `librefolio-theme` and also synced to the user's server-side settings. The system applies the `html.dark` CSS class to toggle between themes. All component colors use Tailwind CSS 4 custom properties defined in `app.css`, so a single class toggle flips the entire UI.

## Layer breakdown
**Frontend**: `frontend/src/lib/stores/app/themeStore.ts` (writable store + localStorage persistence), `frontend/src/app.css` (CSS variables in `html.dark`), `frontend/src/lib/components/layout/Header.svelte` (toggle button)

## Implementation notes
- Tailwind CSS 4 config via `@theme {}` in `app.css` — no TS config file
- Brand colors: `#1a4031` (libre-green), `#f5f4ef` (libre-beige)
- `auto` mode uses `window.matchMedia('prefers-color-scheme: dark')` listener
- Charts (ECharts) read the theme with `isDarkTheme()` and redraw through `onThemeClassChange()`, both in
  `frontend/src/lib/theme/themeMode.ts`. That is one `MutationObserver` per chart on the `class` of `<html>`, called
  on **any** class change, not only `dark`: workstream R kept this on purpose (D4), since the Designer Lab relies on
  it. Charts do not subscribe to the theme store. Gate: `themeModeReads.gate.test.ts`. *Corrected 2026-10-15: this
  page used to say «reactive store subscriptions».*
- Two views read the theme only when they draw and have no observer, so they keep their colours until the next
  redraw: `SemiDonutChart` and the table preview of `FilePreviewModal` (backlog R-7).
- Colours picked by theme that are not Tailwind classes live in `frontend/src/lib/theme/`: `themed(pair, dark)`, the
  chart tables, and the `--lf-cmp-*` tokens of component styles with their `-dark` twins. See
  [[decisions/colour-factorisation-at-pixel-parity]].
