# F-008 — i18n System EN/IT/FR/ES

## What it does
Full frontend internationalization supporting English, Italian, French, and Spanish. All UI strings are externalized to JSON translation files — **4 215 leaf keys per language at 2026-10-09** (the "840+" of Phase 6 is long gone). The active language is persisted in user settings and applied at startup. New keys are managed via the `./dev.py i18n` CLI which handles audit, add, remove, update, and search operations.

## Layer breakdown
**Frontend**: `frontend/src/lib/i18n/{en,it,fr,es}.json` (translation files), `frontend/src/lib/stores/app/language.ts` (active language store), svelte-i18n library, `frontend/src/lib/components/layout/LanguageSelector.svelte`

## Implementation notes
- Library: `svelte-i18n`
- Key count: 4 215 per language (2026-10-09, after the Release 2 i18n audit removed the dead ones; 840+ as of Phase 6)
- Namespaces: flat with dot notation (e.g. `assets.list.title`, `signals.ema`)
- CLI: `./dev.py i18n audit` detects missing keys across languages and — since the 2026-10 audit — dead and
  unverified keys, reading product sources only ([[problems/i18n-audit-false-dead-and-false-used]])
- `./dev.py i18n add <key> <en-value>` adds a key to all 4 language files
- Flag emojis use `Noto Color Emoji` font loaded separately
- Known library traps: [[problems/svelte-i18n-formatter-cache-ignores-locale]] (plural/number rules leak across
  locales when a message text is identical in two catalogues — gated by `catalogIcuLocale.test.ts`) and
  [[problems/i18n-loading-gate-remounts-app]] (`isLoading` used as a layout gate rebuilt the whole app)
