# F-010 — Broker Sharing Owner/Editor/Viewer

## What it does
Fine-grained per-broker access control. The broker owner can share access with other users at three levels: **Owner** (full control including delete and resharing), **Editor** (can add/edit transactions and import files), **Viewer** (read-only access). Access entries are managed via the broker detail page.

## Layer breakdown
**Backend**: `backend/app/db/models.py` (`BrokerUserAccess` model: `broker_id`, `user_id`, `role`), `backend/app/api/v1/brokers.py` (access management endpoints: GET and PUT `/brokers/{id}/access` — the whole list in one write — and PATCH/DELETE `/brokers/{id}/access/me` for one's own entry), `backend/app/services/brokers/access.py`

**Frontend**: broker detail page sharing tab, `frontend/src/routes/(app)/brokers/[id]/`

## Dependencies
- [[F-009]] Broker CRUD — sharing applies to existing brokers
- [[F-003]] Role System — extends the app-level role model to broker resources

## Enables
- [[F-046]] Transaction API — `create_bulk` verifies `EDITOR` access before committing transactions

## Implementation notes
- `BrokerUserAccess.role` values (`UserRole`): `OWNER`, `EDITOR`, `VIEWER`
- `GET /brokers` only returns brokers where the user has an access entry
- `POST /brokers` auto-creates an OWNER entry for the creating user
- `BrokerUserAccess.share_percentage` (0–1, the sum per broker at most 1) weights the broker in the portfolio
  aggregation (`financial_math/portfolio/engine.py`, `portfolio_service.py`). *2026-11-07 lint: the page called it
  «planned Phase 9»; it is live — see [[problems/portfolio-cache-ignored-role-and-share]].*
- The last OWNER cannot be removed — [[decisions/broker-last-owner-guard]]
