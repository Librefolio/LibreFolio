# F-013 — BRIM Broker Parser Plugins

## What it does
The registered collection of broker report parsers. Each plugin extends `BRIMProvider`, is auto-discovered through
`BRIMProviderRegistry`, and returns a `BRIMParseOutput` from `parse()`. At `586a4f0ea` there are **31** `broker_*.py`
modules (Generic CSV included); the current catalogue is maintained in the linked developer documentation rather than
frozen as a count in this page.

## Layer breakdown
**Backend**: `backend/app/services/brim_providers/` contains the concrete parsers, normally one module per supported
source, plus `broker_generic_csv.py`. **Generic CSV is not a catch-all** (corrected 2026-10-09): it recognises columns
from their header names and aliases, and its `can_parse` accepts only a `.csv` whose header names both a date and a
type column; a file no plugin recognises is offered every plugin.

Sample reports in `backend/app/services/brim_providers/sample_reports/` for testing.

## Implementation notes
- Fake asset ID flow: plugins output transactions with reserved **positive high integers**
  beginning at `FAKE_ASSET_ID_BASE`; the multi-file merge remaps them before resolution
- `plugin_version` field on each plugin — cache invalidation if plugin logic changes (parse output; detection is
  keyed by the app version — [[problems/brim-compatible-plugins-frozen-at-upload]])
- **Detection**: `can_parse(file_path)` (there is no `detected()` method), with an optional
  `cannot_parse_reason()` that becomes the HTTP 400 message when a user forces the plugin on a file it refuses; set
  plugins add `report_roles`, `detect_role`, `describe_member` and `combine` ([[decisions/brim-report-sets]])
- **Encoding**: plugins never open a file with a fixed encoding; they read through the base helpers
  (`TEXT_ENCODINGS` = UTF-8, Windows-1252, Latin-1) — a guard test enforces it
  ([[problems/brim-text-exports-hardcoded-utf8]])
- Warnings list (non-fatal): missing prices, unknown asset types, skipped rows; optional field todos
  ([[concepts/import-todo-signals]])
- All plugins tested via `./dev.py test external brim-providers`

### Release 2 plugin notes (archived 2026-10-09)
- **DEGIRO** (issue #35, train 9, merge `2cecf5a00`): rewritten to read the Account Statement **by column
  position**, identical in every language (the amount is the unnamed column 9; the balance is ignored); continuation
  rows (empty date and time) are appended verbatim, because DEGIRO wraps long lines mid-word, even mid-UUID; the
  language is detected from the header (≥ 3 matching columns and a single winner, else English — "Datum" is both
  Dutch and German); decimal marks are decided per value, the file's mark only for ambiguous values such as `1.000`;
  the two legs of a currency exchange are paired without the rate (group, currency, sign, adjacency) and share a
  deterministic `link_uuid`, and the wizard ticks and hands over complete pairs only (`importPairs.ts`); the order
  list `Transactions.csv` is recognised and imports nothing with a warning. Notices keep the file's language
  (`degiro_*` codes have no i18n key). [[sources/phase00-brim-degiro-2026-10]]
- **Danske Bank** (issue #26): the first report-set plugin (custody XLSX + cash CSV) —
  [[decisions/brim-report-sets]], [[sources/phase00-brim-danske-bank-2026-10]].
- **eToro**: a non-zero `Withdrawal Conversion Fee` / `Withdraw Fee` becomes a separate FEE (zero ones are ignored;
  every FEE forces quantity 0 before validation) — an assumption from the observed format, made visible by tests.
  **Crédit Agricole**: the account parser was split into named phases with byte-identical output; the maturity-notice
  helper `attach_maturity_notices` is shared with Intesa (`_brim_output.py`). [[sources/phase00-brim-targeted-2026-09]]
