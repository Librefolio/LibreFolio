# F-016 — FX Pair CRUD

## What it does
CRUD for currency conversion pairs (e.g., EUR/USD, GBP/CHF). Each pair has a base currency, a quote currency, one or more provider assignments with priority ordering, and an `active` flag. When a pair is created, the system auto-assigns a suitable provider based on the base/quote currencies, and auto-inserts the MANUAL sentinel if no real provider covers the pair.

## Layer breakdown
**Backend**: `backend/app/api/v1/fx.py` (POST `/fx/routes`, GET `/fx/routes`, DELETE `/fx/routes` bulk, PATCH `/fx/routes/{id}`, GET `/fx/currencies`), `backend/app/db/models.py` (`FxConversionRoute`: `base`, `quote`, provider assignments + priority)

**Frontend**: `frontend/src/routes/(app)/fx/` — FX list page, create/edit modals, `frontend/src/lib/components/fx/`

## Dependencies

## Implementation notes
- `FxConversionRoute` stores base/quote + provider assignment list with `priority` (lower = higher priority)
- MANUAL provider auto-inserted at `priority=999` when pair has no real provider
- `GET /fx/currencies` returns all ISO 4217 currencies + crypto supported by the system
- Bulk delete: `DELETE /fx/routes` with list of pair slugs

### Creation syncs the pair (since 2026-09-10, full history since 2026-10-06)
- **Auto-sync on creation** (Release 2 group B, R1-03): a pair created with a real provider — direct or multi-hop —
  is synced right after creation; never a MANUAL route, never on edit ("the user controls sync timing"). The add
  modal closes at once; the sync runs as a browser-side promise in `frontend/src/lib/services/fxCreationSync.ts`
  (`finishFxPairCreation`, timeout `FX_SYNC_TIMEOUT_MS` = 120 s), results are matched **by pair**, not by position,
  and the FX detail page subscribes (`subscribeFxCreationSyncCompleted`) with request-epoch/pair/session guards.
  Closing the tab is not covered — a durable backend job was rejected as out of scale. When no sync starts, a green
  "pair created" toast with a link is shown instead.
- **Whole history** (decision D1 of the FX-in-Dashboard plan, 2026-10-06): the creation sync asks from `'min'` to
  today, so a new pair is born without holes; the rule lives in the creation service and the modal lost its
  `dateStart/dateEnd` (D2). Pairs synced range-by-range before that can carry holes that the unbounded
  backward-fill hides — [[problems/fx-backward-fill-unbounded-stale-rates]].
- Success toasts carry a safe internal link to the pair (`entityDetailLinkHtml`,
  `frontend/src/lib/utils/core/entityLink.ts`).
