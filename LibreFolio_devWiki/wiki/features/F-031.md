# F-031 — Asset Events DIVIDEND/SPLIT/INTEREST

## What it does
Stores and serves discrete asset events: DIVIDEND, INTEREST, PRICE_ADJUSTMENT, SPLIT, MATURITY_SETTLEMENT. Providers emit them during sync (yahoo_finance dividends and splits, justetf dividends, scheduled_investment interest and maturity milestones). The user enters them by hand in the data editor's Events tab, one by one or from a CSV, or with «+ New event» in a transaction's *Linked Event* field. Events are shown on charts as markers and in the data editor, and transactions link to them ([[F-051]]).

## Layer breakdown
**Backend**:
- `backend/app/api/v1/assets/events.py` (`event_router`, under `/api/v1/assets/events`):
  - `POST`: the manual upsert, all or nothing; `mode` `upsert` or `create`, `delete_ids`;
  - `DELETE ?asset_id=&ids=`: one asset's events, an outcome per id;
  - `POST /query`: by asset and date range, with an optional FX conversion;
  - `GET ?ids=`: by id.
- `backend/app/services/assets/event_store.py` (`EventStoreOperations`): the manual upsert, the provider upsert in place (`_upsert_asset_events`, called by the sync in `refresh.py`), the queries, the delete.
- `backend/app/schemas/assets/events.py`: `FAAssetEventPoint`, the point shared by the API, the provider output and the Scheduled Investment schedules (`normalize_type()`), plus `FAEventUpsert` and the results.
- `backend/app/db/models.py` (`AssetEvent`): `asset_id`, `date`, `type` (`AssetEventType`), `value` with `currency`, `provider_assignment_id` (NULL for a manual event) and `notes`. No unique key on `(asset_id, date, type)`.
- `backend/app/db/post_migration/event_types.py`: the 1.3 repair of stored types the app does not know.

**Frontend**:
- `frontend/src/lib/components/assets/AssetDataEditorSection.svelte`: the Events tab, saved in one `POST`;
- `frontend/src/lib/components/assets/EventDataImportModal.svelte`: the CSV import;
- `frontend/src/lib/features/transactions/events/`:
  - `EventCreateMiniModal.svelte`: «+ New event»;
  - `EventExistsPanel.svelte`: the events already there when a create is refused;
  - `eventSaveError.ts`: a refusal as one translated sentence;
  - `AssetEventPicker.svelte`: the form's *Linked Event* field.

## Implementation notes
- `AssetEvent.type` enum (`AssetEventType`): DIVIDEND, INTEREST, PRICE_ADJUSTMENT, SPLIT, MATURITY_SETTLEMENT.
- An event's amount is `value` with its `currency`, which must be the asset's (`EVENT_CURRENCY_MISMATCH`, Policy D).
- `provider_assignment_id` tells the sources apart: NULL for a manual event, the provider assignment otherwise.
  - The editor shows a provider's event read-only: the next sync would overwrite an edit. Deleting one is temporary,
    since the provider sends it back.
  - Each source's upsert matches only its own rows on `(date, type)`, so a manual and a provider event can share a key.
- `FAAssetEventPoint` is used in provider results, API responses and Scheduled Investment `asset_events`.
- Events integrated in Round 12 (Phase 6 Step 3): yahoo_finance, justetf, scheduled_investment all emit events.
- 2026-10-08: an event is edited **in place by id**, so its linked transactions follow; the 400 codes
  `EVENT_NOT_EDITABLE` and `EVENT_KEY_CONFLICT` were added ([[problems/asset-event-edit-delete-reinsert]]).
- Release 1.3, workstream W, lots E0 and E1, decisions 20–23 ([[decisions/asset-event-saves-all-or-nothing]]):
  - E0: an events CSV keys its rows on date **and** type;
  - E1: one transaction per request, and refusals as `{error_code, message, params}` naming the item and the event;
  - E1: `mode: "create"` for «+ New event», which never overwrites (409 `EVENT_EXISTS`);
  - E1: the type upper-cased or refused, and the stored types repaired by the post-migration fix `event_types`;
  - E1: a `DELETE` that names its asset, and the editor's deletions inside its one save (`delete_ids`).
- A provider event dated today is written only by the first sync of a later day
  ([[problems/provider-event-dated-today-not-synced]]).
