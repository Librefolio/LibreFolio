# F-049 — BRIM Import UI Asset Matching Wizard

## What it does

Provides the review flow between BRIM parsing and the transaction bulk editor. Users
unify identities extracted from multiple files, correct flagged rows, resolve each
temporary asset reference to one real asset, review duplicates, and choose which rows to
stage.

## Layer breakdown

**Backend**: parse responses, local candidate search, and final duplicate recheck are
served from `backend/app/api/v1/brokers.py` and `backend/app/services/brim_provider.py`.

**Frontend**: `ImportWizardModal.svelte` owns orchestration; the focused
`transactions/import/` components handle grouping, corrections, and asset selection.

## Dependencies

- [[F-012]] BRIM Framework — parser and preview contracts.
- [[F-013]] BRIM Plugins — transaction rows and extracted identity hints.
- [[F-011]] File Management — broker-scoped uploaded reports.

## Enables

- [[F-048]] Transaction Modals — selected rows are staged in `TransactionBulkModal`.
- [[F-083]] Multi-File Multi-Broker Import — one review session can combine files.

## Implementation notes

- Fake asset IDs are positive high placeholders, not negative database IDs.
- The backend combines primary and alternate identifier matches. Exactly one distinct
  candidate may auto-bind; ambiguity remains manual.
- First asset creation/linking is deliberately explicit. A missing automatic binding is
  not, by itself, a parser failure.
- Asset inspection loads full edit data and preserves omission versus explicit-null
  classification semantics.
- The duplicate report is recomputed after corrections and asset resolution. A changed
  final selection keeps the user in review.
- The output is selected `TransactionCreateItem` drafts plus `ImportTodo`s; the standard
  bulk editor performs validation and commit.
