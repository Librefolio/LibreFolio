# F-050 — File Preview System

## What it does
Inline preview for uploaded files in the Files page and the BRIM import modal. Supports multiple preview types: **image** (thumbnail rendering with the existing `PreviewCache`), **text** (raw content), **table** (CSV parsed as data grid), **markdown** (rendered HTML), and **code** (syntax-highlighted). Allows users to inspect a broker report file before triggering BRIM parsing.

## Layer breakdown
**Backend**: `backend/app/api/v1/uploads.py` (`GET /uploads/{file_id}/preview` — already exists for images, extension needed for text/CSV/markdown)

**Frontend**: Planned — new preview modal component, integrated in Files page and `BrokerImportFilesModal`

## Dependencies
- [[F-011]] File Management — builds on existing upload infrastructure

## Enables
- (usability improvement for file review before BRIM import)

## Implementation notes
- Image preview: already implemented via `PreviewCache` (LRU, TTL 1h, 50MB default)
- Text/CSV/markdown: served as raw content, rendered client-side
- `PREVIEW_CACHE_MAX_MB` env var controls image cache size
- Phase 7 Part 4b — absorbed from standalone `plan-phase7b-filePreview.md`
- Autonomous relative to transaction model changes — can be implemented independently

## Delivered (verified on the code, 2026-10-12)
Commit `5b887dd3a` (2026-06-04, "feat(files): add inline file preview system"): `FilePreviewModal.svelte` previews
**image, PDF, markdown, table (CSV and Excel) and text** — the backend's `file_preview.py` and, in the browser,
`detectPreviewType()` in `utils/files/filePreview.ts` pick the type;
the planned **code** type was not built, and PDF was added. Both kinds of file have a preview endpoint: uploads
(`uploads.py`) and broker reports (`brokers.py`). The modal opens from the Files page, from `BrokerImportFilesModal`
and from the import wizard. The user guide documents it: a read-only PDF viewer, and a password that stays in the
browser.

## PDF preview in 1.2 (2026-10-09)
The PDF viewer (EmbedPDF on PDFium/WebAssembly) became a **viewer only**, with its engine and the common fallback
fonts served by the app and the CDN kept as a fallback; editing modes and the document menu are off, a protected PDF's
password stays in the browser, and an empty viewer closes the preview (`1028a1978`). A fallback loop present since
`5b887dd3a`, which restarted the viewer when its start threw, was fixed on the way —
[[decisions/pdf-preview-viewer-only-local-assets]].
