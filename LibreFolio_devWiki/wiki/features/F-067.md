# F-067 — Playwright E2E Tests

## What it does
End-to-end frontend test suite using Playwright, covering all major user flows: auth, settings, broker management, FX pairs, asset management, file operations. 181+ tests across two browser projects (desktop 1280×720 and mobile iPhone 14 Pro Max viewport), both using Chromium.

## Layer breakdown
**Infra**: `frontend/e2e/` — test files organized by domain, `frontend/e2e/fixtures/` (auth-helpers, db-cleanup, the gallery fixtures…), `frontend/playwright.config.ts`

## Dependencies
- [[F-064]] Data Separation — tests run against isolated test DB

## Enables
- [[F-074]] E2E Test Gallery — gallery screenshots generated during E2E runs

## Implementation notes
- Workers: 1 by default, `fullyParallel` on; the runner's `--workers` raises them per run (`E2E_WORKERS`) and the
  backend grows with them (`frontend/playwright.config.ts`). Every test of a lane shares one database and one backend:
  [[concepts/test-isolation-classes]]. *2026-11-07 lint: the page said «sequential — shared DB state».*
- Test server: auto-started via `./dev.py server --test --force` in web server config
- Conventions: `data-testid` attributes always (never CSS classes or text — fragile with i18n)
- `login()`, `logout()`, `navigateTo()` helpers from `auth-helpers.ts`
- `resetDatabase()`, `populateDatabase()` from `db-helpers.ts` (*neither the file nor the two helpers exist any more;
  cleanup lives in `db-cleanup.ts` — 2026-11-07 lint*)
- `openMobileMenu()` for mobile viewport hamburger handling
- Run commands: `./dev.py test front-utility|front-user|front-fx|front-asset|front-broker|front-transaction|front-portfolio|front-ai|front-designer|all-frontend`
- WebKit excluded (stability issues on Linux)
