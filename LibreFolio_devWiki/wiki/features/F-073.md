# F-073 — Backup & Restore

## What it does
Two-tier backup system: **per-series snapshot exports** (implemented) and the **backup of the whole instance**: since 1.3 (lot B1) an
administrator downloads a zip of the data directory from `POST /backup/instance` or writes one with `./dev.py backup create`;
its restore is in progress (lots B2–B3 of `Release_2/Phase_1/07_backupDocker`).

Per-series exports allow downloading CSV or JSON of individual data series before destructive operations: asset price history (`/backup/asset/{id}/prices`), asset events (`/backup/asset/{id}/events`), FX rates (`/backup/fx/{base}/{quote}/rates`). These are the "download before destructive operation" safety valves (e.g., before currency change wipe, pair teardown).

The per-series surface is encapsulated in [[entities/backup-router]] and is the
mandatory pre-confirm step for [[decisions/policy-d-currency-wipe]].

## Layer breakdown
**Backend**: `backend/app/api/v1/backup/exports.py` (streaming CSV/JSON endpoints), `backend/app/services/platform/series_export.py` (`stream_rows_as_csv()`, `stream_rows_as_json()`, `BackupScope`, column definitions)

**Frontend**: download buttons on asset/FX detail pages before destructive actions; since 1.3 (lot B5a) the
administrators' **Settings › Backup** tab creates, follows, downloads and deletes an instance backup
(`frontend/src/lib/features/backup/`)

## Implementation notes
- Per-series exports answer with a `StreamingResponse`, but the rows of the series are read whole before streaming
  (`backup/exports.py`): fine at today's volumes. The instance backup streams every file into the zip instead.
- `BackupScope` enum: `PRICES`, `EVENTS`, `FX_RATES`
- Column sets: `PRICE_COLUMNS`, `EVENT_COLUMNS`, `FX_RATE_COLUMNS` defined in `series_export.py`
- `slugify_for_filename()` helper for safe download filenames
- Instance backup (1.3): a background job per backup, one at a time (`services/platform/instance_backup/jobs.py`); the
  zip holds the database as a `VACUUM INTO` copy, `custom-uploads/`, `broker_reports/`, `scenario_catalog/` and a
  `manifest.json` with every entry's SHA-256; logs, secrets and the scheduler state stay out. The 501 placeholders
  `/backup/export`, `/backup/restore`, `/backup/formats` and `/backup/status` were removed (no consumer).
- On an instance its hosting provider blocked (`LIBREFOLIO_BLOCKED`, H CP6), the four routes of the instance backup stay
  allowed for an administrator (`api/v1/instance_block.py`, decision 12), and `GET /system/block` says so in
  `backup_available`.
