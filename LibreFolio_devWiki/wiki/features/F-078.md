# F-078 — User Filter in Files Page

## What it does
On the Files page, every user can show the files uploaded by given users: an «uploader» column with avatar and
name, filtered by multi-selection and kept in the URL, on the static uploads and on the BRIM reports alike. The plan
of 2026-05-10 asked for an admin-only filter fed by a new users endpoint; what shipped is described below.

## Delivered in another form (verified 2026-10-12, step C of the historian)
The filter shipped on 2026-09-09 in `ef722b552` («ship urgent import and UX fixes»), as **U4** of workstream E's urgent
fixes ([[sources/phase00-feedback-import-urgent-2026-09]]): «sortable uploader column with avatar/name multi-selection
filter, not a separate toolbar; preserve list/grid filtering and unknown uploader identities». The Files page has an
«uploader» column whose filter is kept in the URL (`?uploader=…`); `FilesTable.svelte` resolves each
`uploaded_by_user_id` to a name and an avatar through the existing `GET /api/v1/users/search`, and shows a file without
a known uploader as such. Two differences from the plan below: the filter is **not admin-only** — every user sees it,
as every user sees the uploads list — and **no admin endpoint was created**: `backend/app/api/v1/admin.py`, the file the
plan named, never existed in the history. `get_upload_by_user()` is still called only by its tests.

## Implementation notes (the plan of 2026-05-10)
- Backend: `GET /api/v1/admin/users` endpoint needed (or reuse existing user list)
- Backend: `uploaded_by_user_id` column filter on uploads query
- `get_upload_by_user()` in `backend/app/services/static_uploads.py` already pre-wired
- Frontend: user dropdown filter on Files page (admin-only visible)
- Medium priority
