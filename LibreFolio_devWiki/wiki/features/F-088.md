# F-088 — Rolling (Return-over-N) Return

## What it does
For each date in the asset's price history, the chart shows the return an investor would have had by buying N
calendar days earlier: `return(t, N) = price(t) / price(t − N) − 1`. The user picks the window from presets — 1W,
1M, 3M, 1Y (7, 30, 90, 365 days; default 1M) — or a custom amount of weeks, months or years. The series is in the
toolbar's target currency, so FX movement is included.

Since the developer's decision 29 (2026-10-16, workstream J, CP-10a) it is **the one Rolling Return** of the app:
the same plugin is also offered in the Signals panel (Risk group, Asset charts only) as an overlay with its own
`window_days`. The observation-based `RISK_ROLLING_RETURN` of 1.1 is gone.

## Layer breakdown
**Backend**: the signal plugin `ASSET_CALENDAR_ROLLING_RETURN` (`backend/app/services/signal_plugins/calendar_rolling_return/plugin.py`,
`catalog_visible = True` since decision 29; until then it was hidden, a chart mode only). It goes through the
existing price resolver and its staleness policy, and reports carried (weekend/holiday) points; series and axis key
`calendar_return`. `window_days` is a whole number of calendar days, at least 1, with no maximum (the chart's custom
windows have none). The return between the two closes comes from the one home,
`financial_math.returns.price_return(start, end)` (None when a close is missing or the start is 0), which
`market_series` uses too.

**Frontend**: the chart's Rolling Return mode, the window selector (`calendarReturnWindow.ts`, presets and custom),
persisted per asset in the chart settings store; `priceChartHelpers.ts` reads the series. The store's version 3
migrates a saved overlay of the old signal (`migratePersistedChartSettings`): type `risk-rolling-return` →
`asset-calendar-rolling-return`, `window` → `window_days` (N observations become N days), style `rolling_return` →
`calendar_return`, and the saved axis scale `independent:risk_return` → `independent:calendar_return`. In this mode candles,
Abs/% and price editing are disabled.

## Implementation notes
- **Computed on the backend**, not client-side as this page planned in May 2026: one formula, one price resolver,
  no TypeScript re-implementation (decision of the performance-charts contract, SP06 G3).
- Calendar days, not observation counts. Until 2026-10-16 the older `RISK_ROLLING_RETURN` signal
  (observation-based, compounding the prepared returns) stayed beside it under the same name (backlog C-71).
  Decision 29 removed it: before the cut a parity run showed both give the same values where the windows coincide
  (444 695 points, worst gap 5.7e-14 percentage points). On exchanges a saved window of 30 observations (about 42
  calendar days) becomes 30 days; on crypto nothing changes.
- The plugin owns the `signals.riskRollingReturn.*` keys in its own i18n fragment, with the window tooltip
  `signals.riskRollingReturn.windowTooltip`.
- The `#rolling-return` anchor exists only in the English chart page; IT/FR/ES lack it (`check-links` red accepted
  as translation debt, backlog I-08). *Since M's translation rounds the anchor exists in all four languages; I-08 was
  closed on 2026-10-12 (lint 2026-10-12).*
