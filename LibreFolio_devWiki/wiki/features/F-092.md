# F-092 — Default Language/Currency for New Users

## What it does
Global settings that define the default language and currency applied to newly registered users. When a user registers, their settings are initialized from the global defaults rather than hardcoded EN/USD.

## Implementation notes
- `get_default_language()` and `get_default_currency()` in `backend/app/services/global_settings_service.py`
- Applied in user registration flow
- Low priority

## Delivered (verified on the code, 2026-10-12)
A user's settings row is seeded from the global defaults when it is first created:
`get_or_create_user_settings()` (`settings_service.py`) reads `default_language`, `default_currency` and
`default_theme` — first in `2a8e5bf1c` (2026-07-17), through the settings registry since `2572b2403` (2026-09-03).
Without a row, `get_effective_base_currency()` falls back to the global `default_currency` — the helper born from a
P0 of the second clean audit ([[problems/base-currency-setting-silently-defaulted-eur]]). The functions named in the
notes above, `get_default_language()` and `get_default_currency()`, were never written. The admin guide lists
**Default Currency** and **Default Language** among the Global Settings.

Since 1.2 the Welcome page of [[F-105]] starts from these defaults, as its hint says (`onboarding.welcome.defaultsHint`):
the settings row it pre-fills is the one `get_or_create_user_settings()` creates on the first read.
