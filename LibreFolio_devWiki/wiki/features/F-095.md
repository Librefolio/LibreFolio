# F-095 — Asset Delete — Transaction Count Link

## What it does
When a user attempts to delete an asset that has linked transactions, the delete confirmation dialog shows the count of linked transactions and a link to `/transactions?asset_id=123`. This prevents accidental data loss and provides a quick path to review before deleting.

## Implementation notes
> Shipped 2026-09-10 (`e50d66408`, Release 2 asset data operations, B3) — the design below replaced the May idea of a
> `linked_transaction_count` on `GET /assets/{id}`.
- **Backend**: the bulk delete answers per item with `FAAssetDeleteResult.transaction_count` — the **global** count
  of transactions using the asset (any broker, also ones the user cannot see) — when deletion is blocked
  (`backend/app/schemas/assets.py`). It checks every item first, reports `NOT_FOUND` for every missing asset, deletes
  each item in its own savepoint after a no-op write (the SQLite savepoint trap,
  [[problems/sqlite-savepoint-without-write-begins-as-transaction]]), re-counts if a foreign-key error reveals a race,
  and never answers success for a failed commit (`backend/app/services/asset_sources/crud.py`).
- **Frontend**: the result shows the count with a **Transactions** link to `/transactions?asset_id=<id>` built by
  `buildTransactionsFiltersUrl` (no other filter carried over), for the single delete and in the bulk results
  (`frontend/src/routes/(app)/assets/+page.svelte`); when deletion is blocked the single-asset modal stays open. The
  transactions page shows only accessible brokers, so it may list fewer rows than the count (documented).
