# F-103 — BRIM Report Sets

## What it does
Some banks split one account's history across several exports (Danske Bank: a custody XLSX and a cash CSV). The user
uploads them together; the import wizard recognises them as one **report set**, shows a set card with each member's
role and period, combines them into one derived file, parses that, and — before handing the rows to the bulk editor —
offers an **"Align with the bank"** step that proposes only the corrections needed to match the cash balances and
positions the bank itself states.

## Layer breakdown
**Backend**: `brim_report_sets.py` (members, preview, combine, history start), `brim_gap_fix.py` (truth-point
comparison, proposals tagged `gap_fix`, writes nothing), plugin hooks in `brim_provider.py`, the upload's `batch_id`
and the set endpoints in `api/v1/brokers.py`.

**Frontend**: `importReportSets.ts` (set logic in the wizard; a partly ticked set blocks the analysis),
`ReportSetCard.svelte`, `GapFixStep.svelte` / `GapFixToggle.svelte`, wired in `ImportWizardModal.svelte`.

## Dependencies
- [[F-011]] / [[F-012]] — uploads and the BRIM pipeline.
- [[F-013]] — a set plugin declares report roles.
- [[F-049]] / [[F-083]] — the multi-file wizard that hosts the set card and the gap-fix step.

## Implementation notes
Design and decisions (D-S1 derived combined file, D-S22 set = files uploaded together, D-S31 rejected, truth points
and checkpoint): [[decisions/brim-report-sets]]. Files uploaded by 1.1.0 lack a `batch_id` and must be uploaded again
together. Backlog L1 (a deleted set member), L3 (Crédit Agricole as a set), L7 (a forced set plugin on an unreadable
file).
