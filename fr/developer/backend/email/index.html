    📧 Email Service (SMTP)

    The email service sends LibreFolio's transactional emails through an SMTP server that the administrator names in environment variables. It can write six kinds — a password-reset link, an invitation, an address to confirm, the activation link of the first administrator, a test message, and the notice that an account's email address changed. The service lives in backend/app/services/email/, its configuration in backend/app/config/email.py, and its hourly budget counts with the sliding-window limiter of backend/app/utils/runtime/rate_window.py. Its routes (backend/app/api/v1/email.py) give administrators the state of email, a test email and the emailing of the links they create; one more lets anyone ask for a reset link for a forgotten password; two more spend the link of a verification email and send it again. The Email tab of the settings (frontend/src/lib/features/email/) shows the state and sends the test email; the same folder holds the page of a verification link and the sign-in's notice, «Send by email» and the «forgot password» form. The administrator's guide is Email.

    Status: lots E1 to E5 of release 1.3

    Every email has a caller: the test email (POST /api/v1/email/test), the links an administrator emails (POST /api/v1/email/links), a reset link for a forgotten password (POST /api/v1/email/password-reset), the verification email of a new account (Email Verification), the notice of an email change, and the setup link of the initial administrator: workstream A's deliver_setup_link() (backend/app/services/accounts/bootstrap_admin_service.py, lot A7a) sends build_admin_setup() for a link the instance generated itself.

    🎯 Purpose and Rules

    Email is optional (feature F04 of the release 1.3 plan). Four rules shape the whole package:

    1. Optional. With LIBREFOLIO_SMTP_HOST unset or blank, email is off and nothing changes for a self-hosted install: nothing is sent, the other LIBREFOLIO_SMTP_* variables are not even validated, and the configuration check reports ok. "Email off" is the default state, so a caller handles EmailUnavailableError as a normal outcome, not as a fault.
    2. Environment only. The configuration comes only from the LIBREFOLIO_SMTP_* variables, and the password also from a secret file (LIBREFOLIO_SMTP_PASSWORD_FILE). It is never written anywhere, so it is never in the database and never in a backup; it is never shown in the interface either. GET /api/v1/email/status answers with the state, the problem and the variable at fault, the checks' i18n keys and detail, the hourly budget and the state of the links: never the host, the port, the user, the sender, the Reply-To or the password. The detail of a check, the part meant for the interface, never holds the host, the user or the sender either. The public GET /api/v1/system/instance says only whether email is usable and whether emails can carry links.
    3. Read at every call. The accessors read the process environment each time, nothing is cached, and they are the only readers of these variables, as the config package rule requires. The variables are documented, commented, in the «Email» section of .env.example.
    4. Links from LIBREFOLIO_PUBLIC_URL alone (developer decision 45). Every link an email carries, the ones an administrator sends included, is that variable followed by the path of the page that takes the token, never anything taken from a request (Links). Without the variable, no email with a link goes out.

    ⚙️ Configuration

    📋 The Variables

    Variable Unset or blank Accepted Code when unusable
    LIBREFOLIO_SMTP_HOST Email off A host name or an IP address, IPv6 without brackets: letters, digits, ., -, _ and :; no scheme, user, port, path, bracket or space SMTP_HOST_INVALID
    LIBREFOLIO_SMTP_TLS starttls starttls, tls or none, in any case SMTP_TLS_INVALID
    LIBREFOLIO_SMTP_PORT The port of the mode: 587 (starttls), 465 (tls), 25 (none) ASCII digits, 1–65535 SMTP_PORT_INVALID
    LIBREFOLIO_SMTP_USER No authentication Any text, stripped SMTP_CREDENTIALS_INCOMPLETE without a password
    LIBREFOLIO_SMTP_PASSWORD, or LIBREFOLIO_SMTP_PASSWORD_FILE No password env_secret("LIBREFOLIO_SMTP_PASSWORD"): the value as written, otherwise the content of the file SMTP_PASSWORD_UNREADABLE (a _FILE that cannot give it); SMTP_CREDENTIALS_INCOMPLETE without a user
    LIBREFOLIO_SMTP_FROM Required with a host One mailbox: Name <address> or address SMTP_FROM_MISSING, SMTP_FROM_INVALID
    LIBREFOLIO_SMTP_REPLY_TO Replies go to the sender One mailbox SMTP_REPLY_TO_INVALID
    LIBREFOLIO_SMTP_MAX_PER_HOUR 50 ASCII digits, at least 1 SMTP_MAX_PER_HOUR_INVALID
    LIBREFOLIO_SIGNUP_EMAILS_PER_ADDRESS 20 ASCII digits, at least 1 SIGNUP_EMAILS_PER_ADDRESS_INVALID
    • One variable is not an SMTP one. LIBREFOLIO_SIGNUP_EMAILS_PER_ADDRESS (signup_emails_per_address(), the limit of the registration emails per client address) does not start with SMTP_ENV_PREFIX. email_config_state() validates it with the others, so a bad value makes email unusable (email.smtp is an error naming it, the server starts anyway), and only while a host is set; delivery.address_budget_limit() reads it again at every request.
    • Blank is unset, and values are stripped — except the password, which env_secret() takes as written, spaces included (Secrets from Files).
    • The modes: starttls upgrades a plain connection before anything else is sent and refuses to go on without the upgrade; tls is TLS from the first byte (SMTPS); none sends in clear, meant for a relay on the same machine or the local network (the encryption check warns otherwise).
    • ASCII digits is literal: a sign, a decimal, 2_525 or fullwidth digits, all of which int() would take, are refused.
    • A mailbox is exactly one address, with a non-empty local part and domain and no whitespace inside; a comma inside a quoted display name belongs to the name. A CR or LF anywhere in the raw value is refused, even where stripping would remove it: no header injection reaches a message.
    • The : of the host is there for IPv6 literals, written without brackets (::1, fd00::25); [::1] is refused. A value with exactly one colon, such as smtp.example.com:587, is a name with its port and is refused too, with a message saying that the port goes in LIBREFOLIO_SMTP_PORT: an IPv6 address always has at least two colons.

    🧾 EmailConfigError

    EmailConfigError is a ValueError with two attributes, variable and code. Its message is <VARIABLE>: <rule>, for example LIBREFOLIO_SMTP_PORT: expected a whole number from 1 to 65535: it never holds the value of a variable, so never a secret. The accessors raise it for the six *_INVALID codes. The other three codes combine several variables, so email_config_state() decides them: SMTP_PASSWORD_UNREADABLE, SMTP_CREDENTIALS_INCOMPLETE and SMTP_FROM_MISSING.

    🔌 Email Off, Usable or Unusable

    email_config_state() (in delivery.py) reads every variable through its accessor and never raises. It returns a frozen EmailConfigState:

    State configured problem, variable server, sender, reply_to, max_per_hour usable
    Off: no host False None Unset; max_per_hour 50 False
    Unusable True The code and the variable at fault Unset; max_per_hour 50 False
    Usable True None The SmtpServer, the two mailboxes as (display name, address), the hourly limit True

    The first fault wins, in this order: the host; then the TLS mode, the port, the user, the password, the sender, the Reply-To and the hourly limit (an EmailConfigError, or a SecretFileError reported as SMTP_PASSWORD_UNREADABLE on LIBREFOLIO_SMTP_PASSWORD_FILE); then the credentials, which come in pairs (SMTP_CREDENTIALS_INCOMPLETE on whichever of LIBREFOLIO_SMTP_USER and LIBREFOLIO_SMTP_PASSWORD is set without the other); then the sender (SMTP_FROM_MISSING).

    An unusable value turns email off: send_email() raises EmailUnavailableError with the problem code, and the check email.smtp reports an error. The fault is logged once per process: _report_invalid() is a functools.cache keyed by variable, problem and reason, so the event Email configuration cannot be used: email stays off, with those three fields, appears the first time a fault is read, not at every send. A different reason is new information and is logged again, such as a password file that was missing and is now empty. The reason is the accessor's message or the SecretFileError message, which names the variable and the path of the file, never its content: no secret reaches the log.

    The server starts either way. The startup audit reads the configuration at every start of every process, through the configuration checks: an unusable value is logged there, first by _report_invalid(), then as the email.smtp error of the audit. Later reads in the process log it again only for a new reason. log_configuration_audit() never stops a start for email, only for the platform's own secrets and settings (Configuration Checks).

    📡 Transport (smtp.py)

    deliver(server, message) sends one EmailMessage through one SmtpServer with the standard library's smtplib: no third-party SMTP client. It blocks, so it runs in a worker thread: send_email() calls it through asyncio.to_thread(), as the Event Loop Blocking Rule requires, and a test checks that the connection is opened on a thread without a running event loop.

    SmtpServer is a frozen dataclass: host, port, tls (starttls, tls or none), user, password (kept out of repr) and timeout. email_config_state() builds it with SMTP_TIMEOUT_SECONDS, 20 s, read at call time. It is the socket timeout to connect and for each exchange with the server, not a deadline for the whole conversation.

    The conversation:

    1. Connect: smtplib.SMTP_SSL in tls mode, smtplib.SMTP otherwise; then EHLO.
    2. starttls mode: STARTTLS, then EHLO again. A server that does not offer STARTTLS is refused with TLS_FAILED before the password or the message is sent: the mode never falls back to plain text.
    3. Authentication, only with a user: login().
    4. The message: send_message(); the envelope sender is the From address, the recipient the To address.
    5. QUIT. Once the server has accepted the message, a failure here — a QUIT answered badly, a dropped connection — is not a failure of the delivery: the email counts as sent.

    Both TLS modes use ssl.create_default_context(), which verifies the certificate and the host name. smtplib's own default for starttls() and SMTP_SSL is an unverified context (ssl._create_stdlib_context()), which is why deliver() always passes its own.

    A failure raises SmtpDeliveryError with a code from SmtpErrorCode, a StrEnum whose values are the names:

    Code When
    CONNECTION_FAILED The connection could not be opened or was lost: nothing listening, a name that does not resolve, a refused greeting, a network error outside the TLS step
    TLS_FAILED STARTTLS not offered or refused, a failed handshake, a certificate that does not verify (ssl.SSLError at any step)
    AUTH_FAILED The credentials were refused, or another SMTP error ended the login step (a server without AUTH, for one)
    SENDER_REFUSED MAIL FROM refused
    RECIPIENT_REFUSED RCPT TO refused
    TIMEOUT A TimeoutError anywhere in the exception chain: smtplib turns a read that timed out into SMTPServerDisconnected
    SEND_FAILED DATA refused, or another protocol error while sending; also an address with letters outside ASCII towards a server that does not advertise SMTPUTF8, which smtplib refuses on the client side (SMTPNotSupportedError, before MAIL). With SMTPUTF8 advertised, smtplib sends MAIL FROM:<…> SMTPUTF8 BODY=8BITMIME and the message in UTF-8; for ASCII addresses it adds neither

    str() of the error is the code alone, for the interface. detail holds what the server said (such as 550 5.1.1 <alice@example.com>: Recipient address rejected), or the exception's text, raw: the transport adds no password and masks nothing. It leaves the process only through the Email not sent log, which masks it (What Is Logged). The original exception is dropped (raise … from None).

    📤 Delivery (delivery.py)

    ⏳ The Hourly Budget

    INSTANCE_BUDGET is a SlidingWindowLimiter over 3600 s (BUDGET_WINDOW_SECONDS) with a single key, shared by every send of the process. send_email() hits it with limit= the configured LIBREFOLIO_SMTP_MAX_PER_HOUR, read at call time; budget_status(max_per_hour=None) peeks it with the limit it is given (the status passes the one of the state it has just read) or else the configured one, and returns its RateDecision (allowed, remaining, retry_after) without spending anything, for GET /api/v1/email/status.

    • One unit per attempt. An attempt that passes the configuration and recipient checks spends one unit before any connection, whether the server then accepts the message or not.
    • Refusal before any connection. With the budget spent, send_email() raises EmailRateLimitedError without opening a connection; its retry_after is the number of seconds until the oldest send of the hour leaves the window. A refused attempt is not recorded, so it never pushes that moment further.

    Per process, not per instance

    The budget lives in the memory of each process: with N worker processes the instance may send N times LIBREFOLIO_SMTP_MAX_PER_HOUR emails an hour, and a restart starts from zero. .env.example says so: the limit is per server process. GET /api/v1/email/status shows the budget of the process that answers it.

    📨 send_email()

    async def send_email(content, *, to, user_id=None) sends one EmailContent to one address. A blocked instance sends nothing (decision D-E13): sending_blocked() is true while the hosting provider sets LIBREFOLIO_BLOCKED, and also when that variable cannot be read, which the startup checks stop the server on. The /api/v1 guard already refuses the email routes on a blocked instance (Instance Block); the check here holds for any other caller. Then send_email() reads the configuration with asyncio.to_thread(email_config_state): with LIBREFOLIO_SMTP_PASSWORD_FILE that read opens a file, and no file is read on the event loop.

    🏷️ The Key of a Mailbox

    mailbox_budget_key(address) is the key of the three per-mailbox limiters, each still 3 emails an hour: FORGOT_BY_MAILBOX (A Forgotten Password), EMAIL_CHANGE_NOTICES_BY_MAILBOX (An Email Address Changes) and VERIFICATION_BY_MAILBOX (Sending the Link Again). The aliases of one mailbox give one key, so they share its budget (backlog E-9):

    1. The address stripped and case-folded. A value without @ stops here.
    2. Split at the last @, the local part cut at its first +, on every domain, unless nothing would be left before it.
    3. For Gmail, googlemail.com becomes gmail.com, and every dot of the local part goes.
    Address Key
    Victim.Name+News@GoogleMail.com victimname@gmail.com
    first.last+x@example.org first.last@example.org
    first.last@outlook.com first.last@outlook.com: outside Gmail a dot is part of the mailbox
    a.b@mail.gmail.com a.b@mail.gmail.com: a subdomain of Gmail is not Gmail
    +tag@example.org +tag@example.org: nothing before the +

    • No IDNA. A domain beyond ASCII is case-folded, never encoded.
    • The other limits are unchanged: per account, per client address and per identifier. FORGOT_BY_IDENTIFIER still counts the identifier as typed, stripped and case-folded: it limits whoever asks, while the mailbox's key protects whoever receives.
    • What it cannot see: a catch-all domain, or Fastmail-style subdomain addresses (anything@user.fastmail.com), give a new key for each local part. Only the hourly budget of the instance bounds them (Coming Next).

    🚫 No Stranger's Text

    Three kinds can go to an address chosen by someone who is neither an administrator nor the operator: a password reset, an email verification and the notice of an email change. None of them carries text that person chose (night decision N62 of 17/10, to be reviewed):

    • No username. build_password_reset() and build_verification() take no username and open with common.greeting_anonymous, as the invitation does. A reset link an administrator emails (A Link an Administrator Emails) shares the builder, so it greets nobody by name either.

    • Pinned by tests (EMM-036…041): a username or a new address cannot even be passed to these builders, a TypeError, and no text of their catalogue sections holds $username.

    🌍 Languages

    EMAIL_LANGUAGES is ("en", "it", "fr", "es"), exactly the choices of the default_language setting (a test compares the two), so no account can pick a language its emails lack. email_language(tag) lowercases the tag, keeps its primary subtag and falls back to English: it-IT, it_IT and IT give it; de, an empty tag or None give en. Every builder passes its language through it.

    🛡️ Rendering Rules

    • Placeholders: the texts use string.Template placeholders — $username (in common.greeting alone), $instance, $inviter, $duration — filled with substitute().
    • One line per value: before they fill a placeholder, _render() puts every value on one line (_one_line()). Control characters (Unicode category Cc) and line and paragraph separators (Zl, Zp) become spaces, and the bidirectional embeddings, overrides and isolates (U+202A to U+202E, U+2066 to U+2069) are removed. A username may hold any character: without this it could add lines of its own to the plain-text part, or reorder the text around it.
    • Escaping: every line of the HTML part is escaped (html.escape) after it is filled, so a value that comes from a person — a user name, the name of the instance, the inviter — stays text, never markup. The link is escaped in its href and in the visible fallback address.
    • Subjects: the subject is the catalogue's text, never filled: no user value and no link reaches it, and it stays on one line. Every relay and every notification sees it.
    • Durations: $duration is babel.dates.format_timedelta(ttl, locale=language), Babel's default wording: 30 minutes in Italian gives «30 minuti», 7 days in English "1 week", 72 hours in Italian «3 giorni».
    • The two parts: the plain text holds the greeting, the body lines, for a link kind the action followed by the link verbatim on its own line, the closing lines, then a -- signature line and the footer. The HTML part fills templates/layout.html ($lang, $subject, $body, $footer): a table-based layout with inline styles, a button for the link and, below it, the address to copy (common.button_fallback); <html lang="…"> declares the language.
    • The catalogues and the layout are read once, when messages.py is imported.

    📚 The Catalogue

    templates/en.json, it.json, fr.json and es.json share one structure: a common section (greeting, greeting_anonymous, button_fallback, footer) and one section per EmailKind value, holding subject, intro and, for the link kinds, action, expiry and ignore; invite adds intro_anonymous and admin_role; test has outro instead, and email_changed advice.

    • the four JSON files and layout.html exist in templates/, beside messages.py;

    ➕ Adding a Text or a Kind

    A text: add the key to the same section of the four JSON files in one change, with the same $placeholders in every language, then list it in the builder (the before or after keys that _render() assembles).

    A kind:

    1. a value in EmailKind, which is also the name of its catalogue section;
    2. that section in the four JSON files, with a subject free of placeholders;
    3. a keyword-only build_* builder that passes the language through email_language(), the link through _checked_link() and the lifetime through _duration(), and puts user values only into body placeholders — none at all when someone other than an administrator or the operator can choose its recipient (No Stranger's Text);
    4. the tests of backend/test_scripts/test_services/test_email_messages.py, which pin every kind and the signature of each builder.

    📬 Composing the Message

    compose_message(content, *, to, sender, reply_to=None, now=None) returns the EmailMessage to send:

    Header Value
    Subject content.subject
    From sender, a (display name, address) tuple; a non-ASCII name is encoded as RFC 2047 words
    To to, exactly one bare address
    Reply-To Only when reply_to is given
    Date now, or the current time, in GMT
    Message-ID make_msgid() in the domain of the sender's address, never the name of the machine
    Auto-Submitted auto-generated: auto-responders do not answer (RFC 3834)
    X-Auto-Response-Suppress All: Exchange and Outlook send no automatic reply
    Content-Language content.language

    The body is multipart/alternative, the plain text first and the HTML last: a client shows the last alternative it can display. Content-Language is set after the body, because set_content() clears every Content-* header and turning the message into a multipart moves them into its first part.

    to must be exactly one bare address: one @ with something on both sides, and no whitespace (not even a trailing line break: nothing is trimmed), comma, <, > or ". Anything else is an EmailRecipientError (a ValueError), so no message is composed for a second, hidden recipient.

    ⛓️ Links (links.py)

    Every link an email carries, the ones an administrator sends included, is built from LIBREFOLIO_PUBLIC_URL alone (developer decision 45): the variable, then the path of the page that takes the token, the token in the fragment (token_service.token_path(), such as /reset-password#token=…). Nothing in a request — its host, its Origin, a link the browser sends — becomes part of an emailed link: otherwise a stranger could have a real token sent to a user inside a link to a site of theirs. Without the variable, no email with a link goes out; the links an administrator copies stay as they are (registration_service.public_link(), the path alone without the variable).

    Member Contract
    links_state() LinksState(base, problem), read now, never raises. base is LIBREFOLIO_PUBLIC_URL as public_url() (backend/app/config/accounts.py) gives it, one trailing slash removed, once _usable_base() accepts it: http or https, a host, a valid port, no user name or password (they would travel in every link), no whitespace, and no ? or # at all (even an empty one would swallow the path that follows). problem is PUBLIC_URL_MISSING (unset or blank) or PUBLIC_URL_INVALID (anything else, an address urlsplit() cannot parse, such as https://[::1, included). ready is a base without a problem; instance is the host of base, port included, the name an email gives the instance
    require_links() The LinksState when ready, else EmailLinksUnavailableError, its code the problem
    email_link(purpose, token) require_links(), then public_link(token_path(purpose, token)); EmailLinksUnavailableError without a usable base
    email_instance_config() The email field of GET /system/instance: available is email_config_state().usable and not sending_blocked(), links is available and links_state().ready (below)

    🔑 A Forgotten Password

    Open since lot E4, with the current password for an email change

    «Forgot password» opened with lot E4, once changing an account's email asked for the current password (workstream A's lot A6e, Changing the Email). Without that rule, a moment inside someone's session (a stolen cookie, an unlocked machine) would be enough to put one's own address on the account, then reset its password from it: a lasting takeover. The two go together: the hold the feature had since the security review of lot E3 is gone, with FORGOT_PASSWORD_HELD and ForgottenPasswordHeldError, and nothing in the code holds it any more (a night decision of 16/10, to be reviewed).

    POST /api/v1/email/password-reset answers before it looks for the account, so that nothing in the answer — its status, its body, its timing — tells which accounts exist:

    1. Admission, admit_forgotten_password(address, identifier), before the answer: email usable, links ready, the limiters per address and per identifier, then the hourly budget, peeked. Every refusal is the same for everyone and depends on no account.
    2. The answer: 202, the same body for everyone.
    3. The work, forgotten_password_work(identifier), a FastAPI background task with a session of its own on the request's engine (the request's session ends with it), in this order:
      1. the account, looked up as the login does (get_user_by_username_or_email(), the identifier stripped); nothing for an unknown or inactive one;
      2. the per-account limits (_reset_emails_allowed());
      3. nothing while a reset link an administrator created for the account is still live (_admin_link_live()): a request never cancels it;
      4. email, links and the hourly budget checked again, since the answer went out: nothing is created when the email cannot go;
      5. the per-mailbox limit;
      6. create_password_reset() (workstream A): a new link, valid 30 minutes, which revokes the account's earlier live reset links, by now only those of earlier requests;
      7. the per-account limits counted again inside the write transaction, the new link included: of two requests that passed the first count together, the second sees the first one's link and rolls back (SQLite writes one at a time), so they cannot both send;
      8. the commit, then the email, to the account's address in its language. If it does not go out, whatever the reason, the new link is revoked: it reached nobody.

    Every outcome is a log event without the identifier (What Is Logged).

    🔔 An Email Address Changes

    ✅ Email Verification (verification.py)

    With the global setting require_email_verification on, an account created by signing up cannot sign in until its owner confirms the address from the link of a verification email (developer decision 44). backend/app/services/email/verification.py holds the email side of the feature — the wait, the emailed link, its confirmation, «send the link again» — and its module docstring is the contract. Every link comes from email_link(), so from LIBREFOLIO_PUBLIC_URL alone (developer decision 45).

    The hooks in workstream A's files, written by workstream E:

    The coordinator's decisions:

    • Every account but the first verifies its address, the ones opened by an invitation included: hold_for_verification() skips only the instance's first account.
    • The safe side: with the option on and no email with a link possible (email off or not working, no usable LIBREFOLIO_PUBLIC_URL, a blocked instance), registration is refused with 409, rather than creating an account that would wait for a link nobody can send.
    • A waiting account takes a place under LIBREFOLIO_MAX_USERS while its link is live (The User Limit). Once the link has expired the place is free again, and «send the link again» needs one.
    • «Send the link again» asks for the username (or the email address) and the password, checked as the sign-in checks them.
    • Turning the option off leaves the waiting accounts waiting: only hold_for_verification() reads the option, at registration, so their links and «send the link again» keep working.

    📨 Emailing a Link

    _issue_and_send() emails the account a new link, for registration_email_work() and resend_verification(), in this order:

    1. Email usable (require_email()), links ready (require_links()), the hourly budget peeked, then the recipient's mailbox (VERIFICATION_BY_MAILBOX, peeked on the address through mailbox_budget_key()): past either, EmailRateLimitedError with the wait. Nothing is created when the email cannot go.
    2. The account's verification tokens revoked, the hold included. That first write takes SQLite's write lock, so what follows sees every request that wrote before it. When it revokes nothing, the account no longer waits — its link was confirmed, or an administrator activated or deactivated it meanwhile — and a new link would make it wait again: the transaction rolls back, with EmailVerificationNotNeededError for an active account and VerificationAccountDisabledError for an inactive one, and nothing is sent. Otherwise a new token is issued that carries the account's address.
    3. The per-account limits counted again inside the write transaction, the new link included (_emailed_in_last_hour()): with more than 3 in the last hour, or more than one in the last 5 minutes, the transaction rolls back, the revocations with it, and it raises EmailRateLimitedError with a wait of 300 seconds. Of two requests that passed the first count together, the second stops here (SQLite writes one at a time).
    4. With needs_place — «send the link again» for an account whose link has expired, which holds no place — the user limit counted again in the same transaction, the new link included, as register_user() counts it: over the limit, the transaction rolls back with VerificationUserLimitError. Of two requests that saw the same last free place, the second sees the first one's link here.
    5. Only for «send the link again» (count_address, with the client address; registration_email_work() was counted at the registration): a unit of the address's counter (delivery.ADDRESS_BUDGET, address_budget_hit()). Refused — another request took the last unit since the first look — the transaction rolls back with EmailRateLimitedError. The unit stays spent if the email then fails. Then the commit, before the email.
    6. build_verification() in the account's language, with the link from email_link(), what is left of its lifetime (link_ttl()) and the instance's name (LinksState.instance), and no username (No Stranger's Text); then send_email() to the account's address, as stored. Once the email went out, a hit on VERIFICATION_BY_MAILBOX, and the Verification link emailed event.
    7. When anything after the commit raises (the language, the link, the message or send_email(), whatever the exception), the email did not go as far as LibreFolio knows: the token just committed loses its address (email set to NULL, committed) and the exception goes on to the caller.

    The token stays as a hold, rather than being revoked as a forgotten password's link is: the account needs an unspent token to keep waiting, and keeps it, with its place while the token is live. The link cannot be confirmed, since confirm_email() refuses a token without email (without revoking it: Confirming a Link), and it counts neither against the per-account limits, which count only tokens with an address, nor against the mailbox, which counts only emails that went out: «send the link again» works at once. The same holds after a failed background email, which registration_email_work() logs. A registration's email refused by the mailbox's limit leaves the hold in place: the account waits, and its owner asks for the link again later (the answer has said sending by then: it could not know).

    🔓 Confirming a Link

    confirm_email() spends a link for POST /email/verification/confirm, in this order:

    1. The token inspected for the purpose email_verification (token_service.inspect_token()): any status but valid raises EmailVerificationLinkInvalidError, its code the status, expired, consumed, revoked or unknown. A token whose account no longer exists is unknown.
    2. A token without email — a hold, or a link whose email did not go out as far as LibreFolio knows — is refused with revoked but not revoked, and nothing is written: it may be the account's only unspent token, and revoking it would end the wait. The account keeps waiting and «send the link again» works. The Email verification refused: the link's email did not go out event is logged.
    3. A token emailed to an address the account no longer has (compared with user_service.same_email(), decision P18) is revoked and committed, the Email verification refused: the link was sent to another address event is logged, and the refusal is revoked.
    4. consume_token(): a link that another request spent meanwhile rolls back as consumed.
    5. The account active, email_verified_at set, its other verification tokens revoked; the commit, then the Email verified event.

    Why a link whose email «did not go out» can be confirmed at all: when the connection is lost, or the 20 s timeout runs out, after the message was sent (DATA) but before the server's answer, deliver() reports a failure while the server may have queued the message. The email then arrives with a link that LibreFolio counts as never sent.

    🔁 Sending the Link Again

    resend_verification() is the sign-in's «send the link again», for POST /email/verification/resend, in this order:

    1. The per-address counter, only looked at (address_budget_peek()), before the password: a full one refuses at once with the longest wait of this counter and the instance's budget. A try costs it nothing, so wrong passwords (which have the sign-in's own limit) cannot use up the registrations or the forgotten passwords of a network. A request without a client address skips it.
    2. The account, looked up as the sign-in does (get_user_by_username_or_email()), and the password checked with workstream A's verify_password_or_dummy() in a worker thread: an unknown account costs a dummy hash, and both log Verification resend refused: wrong credentials, then raise VerificationCredentialsError.
    3. An active account raises EmailVerificationNotNeededError; an inactive one that does not wait, VerificationAccountDisabledError.
    4. Email usable (require_email()) and links ready (require_links()).
    5. The per-account limits, on the links already emailed: EmailRateLimitedError with the wait.
    6. Without a live link, the account's place went with its link: if the instance is full now (user_usage()), it raises VerificationUserLimitError, and emailing the link counts again inside its write (needs_place).
    7. Emailing a link; its step 5 spends the unit of the address's counter.

    Since lot A8a, workstream A's limit on failed sign-ins sits between steps 1 and 2: when login_throttle.refusal(identifier, address) refuses, on the sign-in's own two counts, the request gets EmailRateLimitedError with that wait, before the password is checked. In step 2, a wrong password or an unknown account counts there (record_failure()), and the right password forgets the identifier's failures (record_success()) before step 3, whatever follows.

    delivery.ADDRESS_BUDGET and VERIFICATION_BY_MAILBOX are SlidingWindowLimiters in the memory of the process, like the «forgot password» limiters (VERIFICATION_BY_MAILBOX is the counterpart of FORGOT_BY_MAILBOX), with the same consequences; the two per-address limiters follow the same proxy rules (A Forgotten Password).     🌐 The API (api/v1/email.py)

    backend/app/api/v1/email.py is a router with prefix="/email" and the tag Email, which api/v1/router.py mounts under /api/v1; its models, all StrictModel, are in backend/app/schemas/email.py. Three routes are for administrators, /status, /test and /links: they depend on require_admin (backend/app/api/v1/settings.py), 401 without a session, 403 for an account that is not an administrator; then the email configuration is not read, and nothing is sent or spent. /password-reset, /verification/confirm and /verification/resend need no session. One more route, outside this router, publishes whether email is usable: email in GET /api/v1/system/instance.

    📊 GET /api/v1/email/status

    A plain def: reading the configuration may read the password file, so FastAPI runs the route in its thread pool, not on the event loop. Every call evaluates EMAIL_CONFIG_CHECKS and email_config_state() afresh; it opens no connection and resolves no name. It answers an EmailStatusResponse:

    Field Value
    state off (no host), ready (usable) or invalid (a value cannot be used: email stays off)
    problem, variable invalid only: the code and the variable at fault, as in Email Off, Usable or Unusable; null otherwise
    checks The three checks of EMAIL_CONFIG_CHECKS, in that order, each an EmailCheckRead: check_id, severity, i18n_key, detail
    budget ready only: an EmailBudgetRead from budget_status(), which spends nothing — max_per_hour, remaining, and retry_after_seconds, the limiter's retry_after rounded up, 0 while an email fits
    links Every state: an EmailLinksRead from links_state() — ready, base (LIBREFOLIO_PUBLIC_URL, the base of every emailed link, which the Email tab checks from the browser) and problem (PUBLIC_URL_MISSING or PUBLIC_URL_INVALID)

    EmailCheckRead is a ConfigCheck without its summary, because the English log line of the plain-text warning names the SMTP host. No state returns the host, the port, the user, the sender, the Reply-To, the password or the path of a password file.

Like any send_email(), it spends one unit of the budget once the configuration and the address pass.

    🔑 POST /api/v1/email/password-reset

    An async def, without a session. The body is a PasswordResetEmailRequest: identifier, a username or an email address, 1 to 254 characters. It runs the admission with rate_limit_address(request), queues forgotten_password_work() as a background task on the request's engine (session.bind), and answers 202 PasswordResetEmailAccepted, whose message is the same for everyone: If an active account matches, its owner gets an email with a link to choose a new password.

    Status detail When
    202 — Admitted: the work runs after the answer
    409 error_code EMAIL_UNAVAILABLE Email is off or unusable; no problem, unlike the administrators' routes
    409 error_code EMAIL_LINKS_UNAVAILABLE LIBREFOLIO_PUBLIC_URL is missing, or cannot start a link; no problem either

    🔓 POST /api/v1/email/verification/confirm

    An async def, without a session: the link proves that its reader received the email. The page of the link calls it only on the owner's click, never when it opens (In the Frontend). The body is an EmailVerificationConfirmRequest: token, 1 to 256 characters, read from the fragment of the link. The route calls confirm_email() and answers 200 EmailVerificationConfirmResponse: the username of the account, for the sign-in, which names it in its confirmation (In the Frontend).

    Status detail When
    200 — The account is active, its address verified, its other verification links revoked
    400 error_code TOKEN_INVALID, status Not a live verification link: expired, consumed, revoked or unknown. revoked also for a link emailed to an address the account no longer has, which is revoked then, and for a link whose email did not go out, which is left as it is: the account keeps waiting

    🔁 POST /api/v1/email/verification/resend

    An async def, without a session: the credentials of the sign-in stand in for one. The body is an EmailVerificationResendRequest: username, the username or the email address as at sign-in, 1 to 254 characters, and password, 1 to 1024. The route calls resend_verification() with rate_limit_address(request) for the per-address limits, its own and the sign-in's, and answers 200 EmailVerificationResendResponse: the language of the email.

    Status detail When
    200 — A new link went to the account's address; the older ones no longer work
    401 error_code INVALID_CREDENTIALS A wrong password or an unknown account: one answer for both, at the same cost, with the sign-in's status, counted as a failed sign-in (Failed Sign-in Limit)
    403 error_code ACCOUNT_DISABLED An inactive account that does not wait: an administrator deactivated it
    409 error_code EMAIL_VERIFICATION_NOT_NEEDED The account is active: there is nothing to verify
    409 error_code EMAIL_UNAVAILABLE Email is off or unusable, or the instance is blocked
    409 error_code EMAIL_LINKS_UNAVAILABLE LIBREFOLIO_PUBLIC_URL is missing, or cannot start a link

    502 error_code EMAIL_DELIVERY_FAILED The SMTP server did not take the message: the new link lost its address, the account still waits, and a new request may follow at once

Like /password-reset's, the two …_UNAVAILABLE answers carry no problem, and the 502 carries no smtp_code: whoever asks is not an administrator.

A caller without a session gets the 401 of get_current_user, a plain string; a signed-in one gets the 423 instance_blocked. The web app reads both as the block (In the Frontend).

    🌍 email in GET /api/v1/system/instance

    The public configuration of the instance, which answers without a session (Public instance configuration), has an email field: an EmailInstanceConfig (backend/app/schemas/email.py) with two booleans. get_instance_config() (backend/app/api/v1/system/instance.py) fills it with email_instance_config(), through asyncio.to_thread: the read may open the password file.

    • available: a server is set, every variable can be used, and the hosting provider does not block the instance (sending_blocked()); with the instance not blocked, that is the state ready of GET /api/v1/email/status. Usable, not delivered: nothing is sent and no server is contacted to tell, so a server that refuses the login still counts as available.
    • links: available, and LIBREFOLIO_PUBLIC_URL a usable base (Links): emails with a link can go out. The server never checks that this address reaches the instance; only the Email tab does, from the administrator's browser.
    • Nothing more: the answer is the same for whoever asks and never holds the configuration, the address or the budget. An unusable value read here is logged like any other read, at most once per process for the same reason.
    • Off by default: both booleans default to False, and InstanceConfigResponse declares the field with default_factory=EmailInstanceConfig, so it is optional in the schema: an answer built without it, or read from an older server, says that nothing can be sent.

    In the frontend, email.links decides three things: whether the share dialogs offer «Send by email» (sendByEmailVisible()), whether the sign-in's Forgot Password? card shows the «forgot password» form (Links by Email in the Interface), and whether the Global Settings tab lets the switch of email verification turn on (In the Frontend).

    🪟 The Sliding-Window Limiter

    backend/app/utils/runtime/rate_window.py is the one primitive for every limit that counts events in a moving window: the hourly email budget, the «forgot password» limits of flows.py and the per-address limit of «send the link again» (verification.py) use it, and so does workstream A's limit on failed sign-ins (lot A8a), which «send the link again» consults too. A new limit of this kind uses it too, instead of a counter of its own.

    Member Contract
    SlidingWindowLimiter(limit, window_seconds, *, max_keys=10_000, clock=time.monotonic) ValueError when limit < 1, window_seconds <= 0 or max_keys < 1; limit and window_seconds are properties
    peek(key=None, *, limit=None) The RateDecision a hit would get now; counts nothing and never creates a key
    hit(key=None, *, limit=None) The same decision; records the hit only when it is allowed
    count(key=None) How many hits of key are in the window now
    reset(key=None), clear() Forget one key, or every key
    len(limiter) The number of keys holding a hit still in the window
    RateDecision(allowed, remaining, retry_after) Frozen
    • The window: a hit at t counts while clock() - t < window_seconds; exactly window_seconds later it no longer does.
    • Allowed while the count is below the limit: remaining is limit - count for a peek and limit - (count + 1) after an allowed hit; retry_after is 0.
    • Refused: remaining is 0 and retry_after = ts[count - limit] + window_seconds - now, where ts are the live hits, oldest first: the wait until enough of them leave. With a limit of 3 and a 60 s window, hits at 1000, 1001 and 1002 make a fourth at 1003 wait 57 s.
    • A refused hit is not recorded: a caller that keeps knocking does not push its own unlock further away.
    • Per-call limit: limit= replaces the default for that call only (below 1, a ValueError); lowered below the count, the wait is for enough hits to expire.
    • Keys are any hashable value, and None, the default, is a key like any other.
    • Bounded memory: at most max_keys keys, always, and a new key is never refused for want of room. A new key beyond them evicts the key with the fewest hits still in the window at that moment, and among those the one used or regrouped longest ago: a key goes to the end of its group when it is peeked, hit or counted, and when one of its hits leaves the window. No limit, the limiter's own or a call's, enters the choice. The new key is never the one evicted, and an evicted key's hits are forgotten with it. Only an allowed hit creates a key, and a key whose hits have all left the window is dropped at the next call, read or not.
    • Why the fewest hits go (lot E-14, from workstream E's review of decision N70): a key sprayed to make room holds one hit, so a spray of fresh keys never frees a key that holds more, locked or not. To free a key with n hits, every other key must hold n hits too: for workstream A's limit on failed sign-ins per identifier (10 in 15 minutes, 10,000 keys), about 90,000 failures within the window buy 9 more guesses. Measured on the limiter, the cheapest attack costs about 10,000 requests per extra guess. N70's eviction (the first key not full among the 32 least recently used, as eviction_scan) cost about 1,100, no better than plain least-recently-used eviction: an identifier stopped one failure short of the lock is never full, so a spray of 10,000 fresh ones freed it.
    • Exact expiry: a heap holds, for each key, when its oldest hit leaves the window, and every call first takes the hits that have left out of their keys. A key whose hits have left keeps no protection, read or not: with expiry only on reading, a crowd of keys kept at a count they no longer hold would let a key with fewer hits go for one request each.
    • No search: the keys are grouped by count, each group oldest first, so a new key costs the same however many keys there are: about 30 µs for a new key and its 10 hits beside 10,000 full keys, where a walk of every key costs about 7 ms. The «forgot password» limits are hit at every request, before anything else is read (admit_forgotten_password()), so a walk would make a cheap request a CPU amplifier. The heap keeps at most two entries per key plus 64, and is rebuilt from the keys past that: memory stays bounded whatever the rate of requests.
    • Injectable clock: tests move a fake clock instead of waiting.
    • Thread-safe: one lock; threads hitting a key with a limit of N get exactly N hits allowed.
    • Per process, in memory: with N worker processes a limit is N times the configured one, and a restart forgets every count.

    • No inherited configuration. Every module, the rate window's included, starts with an autouse fixture that removes every LIBREFOLIO_SMTP_* variable; each test then sets only what it needs with monkeypatch, and password files live in tmp_path. A test lane already drops them: configure_test_runtime() (scripts/cli_base.py) removes every variable .env.example documents and every LIBREFOLIO_* name, so the lane's server runs without email. The fixture keeps a run outside a lane honest too: a new email test follows the same rule and never reads the lane's environment.
    • Never a real network. FakeSmtpServer (backend/test_scripts/fixtures/email/fake_smtp.py) is written with the standard library and listens on 127.0.0.1, on a port the OS picks. It speaks the part of SMTP that smtplib uses (EHLO with AUTH PLAIN LOGIN, then 8BITMIME and SMTPUTF8 unless smtputf8=False, STARTTLS only when given a tls_context, MAIL, RCPT, DATA, QUIT), can refuse at each step (credentials, refuse_sender, refuse_recipients, refuse_data, quit_code, greet=False), and records messages, auth_attempts and connections; each message keeps its mail_options, the parameters after MAIL FROM:<…>. SMTPUTF8 lets an address with letters outside ASCII through, as real servers do: without it, smtplib refuses such an address on the client side, SEND_FAILED (EMD-047). Read such an address from rcpt_tos or data, never from the parsed message, whose parser turns those bytes into escapes. A refused recipient is named in the 550 reply, as Postfix does, so the masking of the log meets a real server's habit. As a context manager it closes every socket, joins every thread and fails the test on a defect of its own. closed_port(), also a context manager, yields a port of 127.0.0.1 that refuses connections and holds it for the whole block, so no listener started meanwhile can take it. In api email, socket.getaddrinfo resolves the loopback only and records any other name, which proves that the status never looks up the configured host.
    • No waiting. The delivery, flows and API tests replace delivery.INSTANCE_BUDGET with a limiter on a fake clock, clear the cache of _report_invalid() around each test, and lower smtp.SMTP_TIMEOUT_SECONDS to 5 s as a bound for a hang; both are module attributes read at call time for that purpose. The only real wait is the timeout test, 0.2 s.
    • «Forgot password» as shipped. Since lot E4 nothing holds it: test_email_flows.py and test_email_api.py run the admission, the route and the work as the modules ship them, without a fixture to lift anything, and check that no hold is left (EMF-053, EMA-049).
    • TLS tests. EMD-017 (STARTTLS against a certificate the client trusts) and EMD-018 (an untrusted certificate refused: the verification is real) build their certificates with cryptography, a dependency of the Pipfile since release 1.3; pytest.importorskip still skips them in an environment without it.
