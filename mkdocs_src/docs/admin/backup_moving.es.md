# 🏠 Copias de seguridad: traslado y solución de problemas

Esta página forma parte de la guía de copias de seguridad. Trata del **traslado** de tu LibreFolio entre dos instalaciones y de qué hacer **cuando algo va mal** con una copia de seguridad o una restauración.

El resto de la guía comienza en [Copia de seguridad, restauración y traslado de tu instancia](backup_restore.md).

---

## 🏠 Lleva tu LibreFolio a casa {: #bring-home }

Un archivo de copia de seguridad traslada tu LibreFolio de una instalación a otra. La instalación que lo recibe debe ejecutar la misma versión de LibreFolio o una más reciente ([Nunca hacia atrás](#never-backwards)).

### ✋ A mano: descomprime antes del primer inicio {: #by-hand }

En lugar de una restauración, descomprime el archivo de copia de seguridad en la carpeta de datos antes del primer inicio de LibreFolio, con la misma imagen o una más reciente. El inicio aplica por sí mismo las migraciones pendientes.

```bash
# In the folder of docker-compose.yml, before the first start
unzip librefolio-backup-20261015-121500.zip -d LibreFolio-data
docker compose up -d
```

Una copia de seguridad segura (`.lfbk`) no es un zip: primero conviértela en su zip con `backup decrypt` («Descifrar un archivo seguro» en [Herramientas de administración por CLI](cli_tools.md)), donde se ejecuta la línea de comandos de LibreFolio, y luego descomprime ese zip como se indica arriba. Con Docker, una restauración es más sencilla: toma el `.lfbk` tal cual.

```bash
# Host installation
pipenv run ./dev.py backup decrypt librefolio-backup-20261015-121500.lfbk -o librefolio-backup-20261015-121500.zip

# Docker, in a running LibreFolio container: the paths inside it, and the zip where the container's user can write
docker compose exec librefolio python dev.py backup decrypt /app/backend/data/prod-docker/backups/librefolio-backup-20261015-121500.lfbk -o /app/backend/data/prod-docker/backups/librefolio-backup-20261015-121500.zip
```

- 📂 La carpeta de datos debe estar vacía, o no existir todavía: si LibreFolio ya se ha iniciado sobre ella, detén LibreFolio y mueve `LibreFolio-data` a otro sitio primero. Nada de otros datos puede mezclarse con los del archivo de copia de seguridad.
- 🔎 Nada comprueba el archivo de copia de seguridad de antemano: un archivo de copia de seguridad dañado, o uno de un LibreFolio más reciente, se manifiesta cuando falla el inicio, y algunos daños solo más tarde, cuando una página lee los datos que toca. Una restauración, desde Configuración › Administración › Copia de seguridad o la línea de comandos, lo comprueba sobre una copia antes de que cambie nada. Para comprobar un archivo de copia de seguridad antes de descomprimirlo a mano, usa una instalación de LibreFolio que ya esté en ejecución: `backup inspect <archive>` compara cada fichero con el manifiesto y, para un zip, no escribe nada; `backup restore <archive> --dry-run` hace toda la comprobación de una restauración, sobre una copia («Comprobar un archivo de copia de seguridad» y «Probar una restauración sobre una copia» en [Herramientas de administración por CLI](cli_tools.md)). El ensayo en seco funciona en el directorio de datos de esa instalación: nunca lo apuntes a la carpeta vacía que estás a punto de llenar.
- 🧹 El `manifest.json` que queda en `LibreFolio-data/` es inofensivo: puedes eliminarlo.
- 🔓 `backup decrypt` pide la contraseña en el terminal, o la lee con `--password-file` o `--password-stdin`. Nunca reemplaza un fichero: se rechaza un `-o` que ya exista, y no se escribe nada. Solo el propietario del zip puede leerlo (`0600`): el usuario que ejecutó el comando o, con Docker, el usuario del contenedor. Contiene los datos de todos los usuarios en claro, así que bórralo una vez descomprimido. Cuando la copia de seguridad lleva la clave de la instancia, el comando añade `🔑 It also holds the instance key: with it, every saved provider key can be read.`: quien tenga ese zip también puede leer las claves guardadas de los proveedores de datos.
- 🗝️ Desde una copia de seguridad en claro, no hay `secrets/`: LibreFolio crea una nueva clave de instancia la primera vez que necesita una. Cuando traslades tu propia instalación, vuelve a poner su `secrets/` en `LibreFolio-data/` antes del primer inicio, y los secretos guardados seguirán siendo legibles.
- 🔐 El zip de una copia de seguridad segura contiene `secrets/instance.key` cuando la copia lleva la clave: una vez descomprimido, la clave está en su sitio, y las claves guardadas de los proveedores de datos siguen siendo legibles. Antes del primer inicio, haz privadas la carpeta y el fichero, o el registro de inicio tendrá una advertencia («Comprobaciones de inicio» en [Variables de entorno](configuration.md)): `chmod 700 LibreFolio-data/secrets` y `chmod 600 LibreFolio-data/secrets/instance.key`.
- ⛔ Usa la clave de una copia de seguridad solo así, en una carpeta de datos vacía y en una instalación que no establezca ni `LIBREFOLIO_INSTANCE_KEY` ni `LIBREFOLIO_INSTANCE_KEY_FILE`: una clave establecida allí prevalece sobre `secrets/instance.key`, y las claves guardadas de los proveedores de datos quedarían ilegibles. Nunca la pongas en lugar de una clave ya en uso: lo que se guardó bajo esa clave quedaría ilegible. Para llevar una copia de seguridad segura a una instalación que tiene su propia clave, restáurala: la restauración vuelve a cifrar las claves guardadas con la clave de esa instalación.
- 📖 Los pasos para cualquier instalación, incluida la del host: «Usar un archivo de copia de seguridad en otra instalación» en [Herramientas de administración por CLI](cli_tools.md).

### ⛔ Nunca hacia atrás {: #never-backwards }

LibreFolio nunca hace retroceder una base de datos a una versión anterior: usa la versión que creó el archivo de copia de seguridad, o una más reciente. Un LibreFolio más antiguo rechaza un archivo de copia de seguridad cuya base de datos lleva una migración que no conoce.

- 🏷️ `backup inspect` muestra qué versión creó el archivo de copia de seguridad (`Made by LibreFolio <version>`), y **Configuración › Acerca de** muestra la versión de una instancia.
- ❌ `backup restore` rechaza tal archivo de copia de seguridad con `revision_unknown`, antes de que cambie nada.
- 🛑 A mano, un LibreFolio más antiguo no se inicia sobre tales datos: su registro contiene `Failed to apply database migrations`, y Docker no deja de reiniciar el contenedor. Detenlo con `docker compose down`.

Actualiza primero el LibreFolio receptor ([Actualizar LibreFolio](../user/installation.md#updating)), y después restaura. Con Docker, la imagen `latest` es la versión más reciente.

## 🧯 Cuando algo va mal {: #troubleshooting }

### 🔐 Crear una copia de seguridad segura {: #secure-problems }

| Qué ves | Por qué | Qué hacer |
| --- | --- | --- |
| `❌ A password is needed: give it with --password-file or --password-stdin, or run the command at a terminal (password_required)` | `backup create --encrypt` sin un terminal donde preguntar, como en cron | Da la contraseña con `--password-file` o `--password-stdin` ([Desde la línea de comandos](backup_restore.md#command-line)) |
| `❌ The password of a backup needs at least 12 characters, with an uppercase and a lowercase letter, a digit and a symbol (password_too_weak: …)`, o en Configuración › Administración › Copia de seguridad *La contraseña no cumple las reglas de una contraseña de copia de seguridad.* | La contraseña no cumple las reglas indicadas después de `password_too_weak:`. En Configuración, el medidor mantiene **Crear copia de seguridad** desactivado hasta que se cumpla cada regla; cuando no pudo leer del servidor las reglas de una copia de seguridad (`GET /api/v1/backup/instance/options`), comprueba las de la contraseña de una cuenta, con 8 caracteres, y el servidor rechaza una de menos de 12 caracteres | Elige una contraseña más larga que cumpla todas las reglas. No se escribió nada |
| `❌ The two passwords differ (password_mismatch)` | La segunda contraseña escrita en el terminal no es la primera | Ejecuta el comando de nuevo |
| `❌ password file: <path> does not exist (password_unreadable)`, o `cannot be read`, `is empty or blank`, `is not UTF-8 text` | `--password-file` no puede proporcionar la contraseña | Corrige el fichero: contiene solo la contraseña, en UTF-8. Con Docker, da la ruta dentro del contenedor, como `/run/secrets/backup_password` |
| `⚠️ The instance key cannot be used: the secure backup was made without it, so saved provider keys must be entered again after a restore`, o en Configuración › Administración › Copia de seguridad *La clave de la instancia no se puede usar: la copia de seguridad se creó sin ella, así que las claves de los proveedores de datos deben introducirse de nuevo después de una restauración.* | `secrets/instance.key` está ahí, pero dañada o fuera de alcance, o tiene más de 4096 bytes, más de lo que una restauración vuelve a leer (la clave que genera LibreFolio tiene 43 caracteres). La copia de seguridad está completa, sin la clave | Si el registro de inicio dice qué le pasa a la clave, corrígelo primero («Comprobaciones de inicio» en [Variables de entorno](configuration.md)), y luego crea una nueva copia de seguridad segura. Si no dice nada, la clave es demasiado larga para viajar: guarda una copia de `secrets/` con la copia de seguridad, como harías para una en claro |

### 🧾 La comprobación rechaza el archivo de copia de seguridad {: #check-refused }

`backup restore`, con o sin `--dry-run`, termina con un rechazo y su código entre paréntesis, y no cambia nada. Configuración › Administración › Copia de seguridad rechaza los mismos archivos de copia de seguridad y lo explica en su tarjeta, sin el código: *El archivo de copia de seguridad está dañado.* para `archive_damaged`, por ejemplo.

| Código | Por qué | Qué hacer |
| --- | --- | --- |
| `revision_unknown` | El archivo de copia de seguridad viene de un LibreFolio más reciente | Actualiza este ([Nunca hacia atrás](#never-backwards)), y luego ejecuta el comando de nuevo |
| `manifest_newer_format` | El formato del archivo de copia de seguridad es más reciente que lo que este LibreFolio lee | Actualiza LibreFolio primero |
| `checksum_mismatch`, `archive_damaged`, `missing_entry` | El archivo de copia de seguridad está dañado, cortado o se modificó | `backup inspect` nombra las entradas que difieren. Copia de nuevo el archivo de copia de seguridad desde donde lo guardes, o usa otro |
| `database_damaged` | La base de datos del archivo de copia de seguridad no pasa la comprobación de integridad de SQLite, SQLite no puede leer su esquema, o contiene texto que no es UTF-8: LibreFolio nunca escribe tal texto, y tras una restauración toda lista que lo contuviera fallaría al cargar. Configuración › Administración › Copia de seguridad: *La base de datos de la copia de seguridad está dañada: no se puede restaurar.* | Copia de nuevo el archivo de copia de seguridad desde donde lo guardes, o usa otro. Texto que no es UTF-8 significa que otro programa escribió en la base de datos, o que el archivo de copia de seguridad se modificó |
| `database_foreign_objects` | La base de datos del archivo de copia de seguridad contiene un disparador, una vista o una tabla virtual. LibreFolio nunca los crea, y su SQL se ejecutaría durante la comprobación y en el servidor tras una restauración, así que la comprobación los rechaza antes de abrir la copia para cualquier otra cosa. Configuración › Administración › Copia de seguridad: *La base de datos de la copia de seguridad contiene disparadores, vistas u otros objetos que LibreFolio nunca crea: no la creó LibreFolio, o se modificó, y no se puede restaurar.* | El archivo de copia de seguridad no lo creó LibreFolio, o se modificó después: usa otra copia de seguridad |
| `not_a_backup` | No es un archivo de copia de seguridad que haya escrito LibreFolio, como un directorio de datos comprimido a mano | Vuelve a poner tal copia [a mano](#by-hand), en un directorio de datos vacío |
| `sealed_backup_needs_key` | Una copia de seguridad nocturna sellada (`.tar`): su contraseña está dentro, cifrada para una clave, y la comprobación no puede abrirla. Configuración › Administración › Copia de seguridad: *Esta es una copia de seguridad sellada de un panel de alojamiento: su contraseña está cifrada para la clave del proveedor. Extrae backup.lfbk, abre password.age con age y luego restaura backup.lfbk con esa contraseña.* | Restáurala donde esté su clave privada: `backup restore <archive>.tar --identity-file <key file>` ([Copias de seguridad selladas](backup_sealed.md#sealed)) |
| `sealed_no_identity`, `sealed_identity_invalid`, `sealed_tar_invalid`, `sealed_manifest_invalid`, `sealed_password_invalid` | Una [copia de seguridad sellada](backup_sealed.md#sealed) dada con `--identity-file` que no se abre | Consulta [Crear o abrir una copia de seguridad sellada](#sealed-problems) |
| `no_space` | La copia necesita más espacio libre del que tiene el disco del directorio de datos | Libera algo de espacio: el archivo de copia de seguridad descomprimido, más el doble de su base de datos, más 64 MB, y para una copia de seguridad segura también el tamaño de su `.lfbk` |
| `archive_unreadable` | El archivo de copia de seguridad no se puede abrir, casi siempre porque el usuario del servidor no puede leerlo | Con Docker y la imagen oficial, `sudo chown 1000:1000 <archive>` en el host se lo entrega a ese usuario |
| `restore_already_pending` | Otra restauración espera al siguiente inicio | Reinicia LibreFolio para aplicarla, o descártala con `backup pending --cancel` o **Cancelar la restauración** en Configuración › Administración › Copia de seguridad |
| `wrong_password` | La contraseña no abre la copia de seguridad segura: no es con la que se creó, o se modificó el inicio del fichero. Configuración › Administración › Copia de seguridad la vuelve a pedir: *Contraseña incorrecta, o el fichero se modificó: escribe la contraseña de nuevo.* | Escríbela de nuevo tal como se eligió, mayúsculas y minúsculas incluidas. Si es correcta, copia el fichero de nuevo desde donde lo guardes |
| `password_required` | Una copia de seguridad segura, y ninguna contraseña: el comando no tenía terminal donde preguntar, ni `--password-file` ni `--password-stdin` | Ejecuta el comando en un terminal, o da la contraseña con una de las dos opciones |
| `envelope_damaged` | La copia de seguridad segura está dañada, cortada o se modificó después de crearse | Cópiala de nuevo desde donde la guardes, o usa otra: LibreFolio no lee ninguna parte de un `.lfbk` dañado |
| `envelope_unsupported` | La copia de seguridad segura viene de un LibreFolio más reciente, o pide una configuración que esta no acepta | Actualiza este primero ([Nunca hacia atrás](#never-backwards)), y luego ejecuta el comando de nuevo |

Dos mensajes más:

- `❌ No file at <path>`: con Docker, da la ruta dentro del contenedor, `/app/backend/data/prod-docker/…`.
- `❌ The backup has no active administrator: after a restore nobody could manage the instance`, o lo mismo en el informe de Configuración › Administración › Copia de seguridad, cuya confirmación entonces permanece desactivada: en la instalación de la que viene la copia de seguridad, haz administrador a una cuenta activa y luego crea una nueva copia de seguridad.

Todos los códigos: «Negativas — qué significan los códigos» en [Herramientas de administración por CLI](cli_tools.md).

Dos avisos dejan que la restauración continúe, pero léelos antes de confirmar.

- 🔑 *Tu cuenta no está entre los administradores de esta copia de seguridad: después del reinicio no podrás iniciar sesión con ella.* Este solo se muestra en el informe de Configuración › Administración › Copia de seguridad, en rojo. Después de una restauración, inicias sesión con una cuenta de la copia de seguridad, con la contraseña que tenía entonces, y la cuenta que usas ahora no está en ella. Antes de confirmar, asegúrate de que conoces la contraseña de uno de los administradores que nombra el informe. Si no la conoces, usa otra copia de seguridad.
- `⚠️ Ledger totals differ from the backup's (<n> lines):`, o *Los totales del libro mayor difieren de los de la copia de seguridad en 2 líneas:* en el informe de Configuración › Administración › Copia de seguridad: el efectivo de un bróker o la cantidad de una posición en la copia, una vez puesta al día, no es la que registró la copia de seguridad. Se perdieron, añadieron o cambiaron transacciones entre la copia de seguridad y la copia, por ejemplo por una migración que corrige datos. Lee las líneas que siguen: cada una da el número de un bróker, luego el de una divisa o un activo, con el importe de la copia de seguridad antes de la flecha y el de la copia después. Los números son los de las direcciones de las páginas del bróker y del activo en la aplicación, `/brokers/<id>` y `/assets/<id>`. Compara estas líneas con la instancia de la que viene la copia de seguridad. La advertencia nunca bloquea la restauración: que confirmes o no depende de ti.

### 🔏 Crear o abrir una copia de seguridad sellada {: #sealed-problems }

Al crear una, con `backup create --sealed` o `--recipient`: no se escribe nada, y el comando termina con `1`.

| Qué ves | Por qué | Qué hacer |
| --- | --- | --- |
| `❌ LIBREFOLIO_BACKUP_RECIPIENTS is not set: give the recipients there, or with --recipient age1…` | `--sealed` no encontró ninguna variable: no está en `.env`, o el contenedor no se recreó después de añadirla | Establécela ([Sellar cada copia de seguridad](backup_sealed.md#sealed-recipients)), luego `docker compose up -d`, o ejecuta el comando desde la carpeta del proyecto con `pipenv run`, que lee `.env` |
| `❌ LIBREFOLIO_BACKUP_RECIPIENTS: item 2 is not an age recipient: expected age1… as age-keygen prints it (BACKUP_RECIPIENTS_INVALID)`, o `expected at most 2 recipients, comma-separated (BACKUP_RECIPIENTS_TOO_MANY)`, o `item 2 repeats an earlier recipient (BACKUP_RECIPIENTS_DUPLICATE)` | La variable contiene algo distinto de una o dos claves `age1…` diferentes: una clave privada, una clave SSH, una coma de más | Escribe solo las claves públicas, tal como las imprimen `keygen` o `age-keygen -y`. La pestaña **Seguridad** dice lo mismo (`backup.recipients`) |
| `❌ A --recipient is not an age recipient: expected age1…, as keygen or age-keygen prints it`, `❌ The same recipient is given twice`, `❌ At most 2 recipients: --recipient twice, while a key is being changed` | Las mismas reglas, para `--recipient` | Da una o dos claves públicas diferentes |
| `❌ A sealed backup draws a password of its own: --sealed and --recipient go without --encrypt, --password-file or --password-stdin` | Una copia de seguridad sellada no tiene contraseña que dar | Quita las opciones de contraseña |
| `❌ --sealed reads the recipients from LIBREFOLIO_BACKUP_RECIPIENTS: give them there or with --recipient, not both` | `--sealed` y `--recipient` juntos | Mantén solo uno de los dos |
| `❌ <path> already exists: a key file is never written over` | `backup keygen` nunca reemplaza una clave: la antigua aún puede abrir copias de seguridad | Elige otro nombre de fichero, o aparta primero el fichero antiguo si estás seguro de que ninguna copia de seguridad lo necesita |

Al abrir una, con `--identity-file`: el comando no cambia nada y termina con `1`. Primero se lee el fichero de clave, luego el `.tar`.

| Qué ves | Por qué | Qué hacer |
| --- | --- | --- |
| `(sealed_backup_needs_key)` | Un `.tar` dado sin `--identity-file`, en la línea de comandos o en Configuración › Administración › Copia de seguridad | Da el fichero de clave, o [ábrelo a mano](backup_sealed.md#sealed-by-hand) y restaura `backup.lfbk` con su contraseña |
| `❌ --identity-file opens a sealed backup (.tar) only: <path> is not one` | Un `.zip` o un `.lfbk` dado con `--identity-file` | Quita `--identity-file`: esos archivos de copia de seguridad se abren como de costumbre |
| `❌ The key file cannot be read (sealed_identity_invalid)`, `Line 3 of the key file is not an age key`, `The key file holds no age key` | El fichero no es una clave privada: solo la clave pública, una clave copiada con un carácter de menos, o un fichero que el comando no puede leer | Da el fichero que escribieron `keygen` o `age-keygen`, con su línea `AGE-SECRET-KEY-1…`. Los comentarios (`#`) y las líneas en blanco pueden quedarse |
| `❌ None of the keys given opens the password of this backup (sealed_no_identity)` | La copia de seguridad se selló para otra clave: una más antigua, antes de un [cambio de clave](backup_sealed.md#sealed-rotation) | Compara sus `recipients` (`tar xOf <archive>.tar manifest.json`) con la línea `# public key:` de tus ficheros de clave, y da la que coincida |
| `(sealed_tar_invalid)`, como `The archive is cut short` o `The archive does not hold manifest.json, password.age and backup.lfbk, in this order` | No es el `.tar` que escribió LibreFolio: cortado por una copia, reconstruido a mano con `tar cf`, o no es una copia de seguridad sellada | Copia de nuevo el original desde donde lo guardes, o usa la copia de seguridad de otra noche |
| `(sealed_manifest_invalid)`, como `The manifest does not describe backup.lfbk: its size or SHA-256 differs` | `manifest.json` se modificó, o `backup.lfbk` también | La copia está dañada: usa otra |
| `(sealed_password_invalid)` | La clave abrió `password.age`, pero lo que hay dentro no es una contraseña que escriba LibreFolio | No es una copia de seguridad de LibreFolio, o se modificó: usa otra copia |
| `❌ The password does not open this backup (wrong_password)` | La clave abrió la contraseña, pero esa contraseña no abre `backup.lfbk`: los dos ficheros vienen de copias de seguridad distintas, o uno se modificó | Usa otra copia, conservada entera tal como la escribió LibreFolio |
| `(envelope_damaged)`, durante la comprobación o la restauración | Un byte de `backup.lfbk` se modificó después de crear la copia de seguridad: la contraseña era correcta | Usa otra copia: LibreFolio no lee ninguna parte de un `.lfbk` dañado |

### 🔁 La restauración no llega a completarse {: #restart-problems }

| Qué ves | Por qué | Qué hacer |
| --- | --- | --- |
| `backup pending` dice `The state of the restore cannot be read`, `(restore_state_unreadable: <reason>)` | `.restore/restore.json` no se puede usar: sus permisos (`io`), un enlace o una carpeta en su lugar (`not_a_file`), o contenido que LibreFolio no escribió (`invalid`). Puede que una restauración se haya detenido a medias. Mientras tanto no se elimina ninguna copia comprobada | Para `io`, devuelve `.restore/` al usuario que ejecuta LibreFolio y vuelve a mirar. Si no, detén LibreFolio y ejecuta `backup pending --recover previous`: los datos de antes vuelven desde `.restore/previous/`. Luego inícialo, o restaura una copia de seguridad de nuevo: «Un estado de restauración ilegible» en [Herramientas de administración por CLI](cli_tools.md) |
| `backup pending` termina con `(server_running)` | En el último inicio, otro proceso de servidor servía el directorio de datos: un worker se reinició por su cuenta, o había un segundo servidor | Reinicia todo el servidor, nunca un solo worker, y ejecuta un servidor por directorio de datos |
| `backup pending` termina con `(other_data_directory)` | El servidor encontró su directorio de datos bajo otra ruta distinta de aquella para la que se confirmó la restauración, como una copia del directorio de datos | `backup pending --cancel`, o **Cancelar la restauración** en Configuración › Administración › Copia de seguridad, y luego restaura el archivo de copia de seguridad de nuevo: con `backup restore`, donde se ejecuta el servidor |
| `backup pending` termina con `(backup_running)` | En el último inicio se estaba ejecutando una copia de seguridad | Nada: el siguiente inicio aplica la restauración |
| `backup pending` dice que la restauración se revirtió, `(first_start_failed)` | El primer inicio sobre los datos restaurados no se completó | Los datos están como estaban. El registro de ese inicio tiene la causa: corrígela y luego restaura el archivo de copia de seguridad de nuevo |
| … revertida, `(swap_interrupted)` | El inicio que aplicó la restauración se interrumpió, y el siguiente la deshizo | Restaura el archivo de copia de seguridad de nuevo |
| … revertida, `(swap_failed)` | No se pudieron mover las carpetas a su sitio | Haz que `sqlite/`, `custom-uploads/`, `broker_reports/` y `scenario_catalog/` sean carpetas reales del directorio de datos, ni enlaces ni montajes separados, y luego restaura el archivo de copia de seguridad de nuevo |
| … revertida, `(stage_missing)` | La copia comprobada desapareció o cambió | Restaura el archivo de copia de seguridad de nuevo |
| Un inicio se detiene, y su registro dice que otro servidor aplicó la restauración o sirve el directorio de datos | Dos servidores de LibreFolio usan el mismo directorio de datos | Detén el otro y luego inicia LibreFolio de nuevo: `backup pending` entonces dice si se conservó la restauración |
| LibreFolio no se inicia, y su registro contiene `The data directory is half restored` | Incluso volver a poner los datos anteriores falló, por ejemplo por un error de disco o de permisos | Corrige la causa que indica el registro: cada inicio lo intenta de nuevo |
| `Failed to apply database migrations` tras descomprimir a mano | Un archivo de copia de seguridad de un LibreFolio más reciente, o una migración que falla: el registro contiene el error | Para un archivo de copia de seguridad más reciente, `docker compose down`, y luego usa la versión que lo creó o una más reciente ([Nunca hacia atrás](#never-backwards)) |

### 🖱️ Qué dice Configuración › Administración › Copia de seguridad {: #restore-settings-problems }

La ventana del reinicio da una razón en palabras donde `backup pending` da un código: la tabla dice cuál, y la fila de ese código en [La restauración no llega a completarse](#restart-problems) dice qué hacer. En la tarjeta, **Intentar de nuevo** vuelve a leer el estado de la restauración: para enviar un archivo de copia de seguridad de nuevo, vuelve a elegirlo.

| Qué ves | Por qué | Qué hacer |
| --- | --- | --- |
| Después de **Restaurar y reiniciar**, la página de inicio de sesión, sin mensaje | La restauración funcionó: terminó todas las sesiones. Solo en el caso de la siguiente fila aparece la página de inicio de sesión aunque no funcionó | Inicia sesión con un administrador de la copia de seguridad, con la contraseña que tenía la cuenta cuando se creó la copia. Si nadie la recuerda: [Después de una restauración](#after-restore) |
| La página de inicio de sesión apareció, pero una vez iniciada la sesión los datos están como antes | La página no pudo leer el resultado con su ticket (una recarga de la página, más de una hora de espera, o un reinicio de LibreFolio desde la línea de comandos en vez de desde la página), y LibreFolio se ejecuta sin `JWT_SECRET` ([Mantener a los usuarios con la sesión iniciada tras un reinicio](index.md#session-persistence)): cada inicio cierra la sesión de todos, así que se mostró la página de inicio de sesión aunque la restauración no se completó. Las cuentas y contraseñas de antes siguen siendo válidas | Abre **Configuración › Administración › Copia de seguridad**: la tarjeta dice *La última restauración se revirtió el …*, o muestra la restauración en espera, con la razón; luego consulta la fila de esa razón más abajo |
| *LibreFolio aún no ha vuelto. Si nada lo inicia de nuevo por sí solo, inícialo tú: la restauración se aplica en ese inicio.* | LibreFolio no ha respondido durante un minuto: nada lo inició de nuevo, sin supervisor o con uno que solo lo inicia tras un fallo ([Quién inicia LibreFolio de nuevo](backup_restore.md#supervisors)), o su inicio es lento | Si está detenido, inícialo: `docker compose up -d` con Docker, o [inicia el servidor](cli_tools.md#start-the-server) en una instalación de host. La página continúa por sí sola una vez que LibreFolio responde |
| *LibreFolio no se ha detenido. Si no se reinicia por sí solo, reinícialo tú: la restauración se aplica en ese inicio.*, un minuto después de **Restaurar y reiniciar**, con **Volver a Copia de seguridad** | La solicitud no detuvo el servidor: la restauración sigue esperando al siguiente inicio, y `backup pending` la muestra en espera | Reinicia LibreFolio tú mismo: `docker compose restart librefolio` con Docker, o detén todo el servidor y [inícialo](cli_tools.md#start-the-server) de nuevo. Su inicio aplica la restauración, y la página continúa por sí sola. O **Volver a Copia de seguridad**: la tarjeta muestra la restauración en espera, para reiniciarla de nuevo (**Reiniciar ahora y restaurar**) o cancelarla (**Cancelar la restauración**) |
| **La restauración no llegó a completarse**, con *Los datos están como estaban antes: …* | La restauración se revirtió: *el primer inicio después de ella no se completó* (`first_start_failed`), *el inicio que la aplicó se interrumpió* (`swap_interrupted`), *sus carpetas no se pudieron mover a su sitio* (`swap_failed`) o *su copia comprobada desapareció* (`stage_missing`) | Lo que dice la fila de ese código. **Volver a Copia de seguridad** vuelve a la tarjeta, que dice cuándo se revirtió la última restauración y por qué |
| **La restauración no llegó a completarse**, con *LibreFolio se reinició, pero la restauración no se aplicó.* y la razón | Un inicio dejó la restauración en espera: *En el último inicio se estaba ejecutando una copia de seguridad…* (`backup_running`), *Se confirmó para otro directorio de datos…* (`other_data_directory`) o *En el último inicio otro proceso de LibreFolio estaba sirviendo los datos…* (`server_running`) | Lo que dice la fila de ese código. **Volver a Copia de seguridad** muestra la restauración en espera, con **Reiniciar ahora y restaurar** y **Cancelar la restauración** |
| *El archivo de copia de seguridad es más grande de lo que acepta este LibreFolio (500 MB).* | La instalación limita los archivos de copia de seguridad subidos para una restauración con `LIBREFOLIO_BACKUP_MAX_UPLOAD_MB` (`backup_too_large`) | En tu propia instalación no hay límite a menos que alguien haya puesto uno: auméntalo, o ponlo en `0`, y luego reinicia ([El límite de subida de una restauración](backup_restore.md#restore-upload-limit)). O restaura desde la línea de comandos, que no tiene límite de subida |
| *Descomprimido, el archivo de copia de seguridad es más grande de lo que este LibreFolio acepta para una restauración.* | Los tamaños que declara el manifiesto del archivo de copia de seguridad suman más de lo que la instalación acepta para una restauración (`unpacked_too_large`): `LIBREFOLIO_BACKUP_MAX_RESTORE_MB`. La comprobación rechazó el archivo de copia de seguridad antes de descomprimir nada | En tu propia instalación no hay límite a menos que alguien haya puesto uno: auméntalo, ponlo en `0` o elimínalo, y luego reinicia ([El límite de subida de una restauración](backup_restore.md#restore-upload-limit)). O restaura desde la línea de comandos con `LIBREFOLIO_BACKUP_MAX_RESTORE_MB=0` delante de `backup restore` |
| *LibreFolio no puede leer ahora mismo su límite de restauración: inténtalo de nuevo más tarde.* | `LIBREFOLIO_BACKUP_MAX_RESTORE_MB` no es un número entero de megabytes (`backup_restore_unavailable`): no se inicia ninguna comprobación, y el archivo de copia de seguridad se queda en el servidor. El registro tiene un error, ya desde el inicio | Escribe un número entero de megabytes, `0` para ningún límite, o elimina la variable, y luego reinicia; la pestaña **Seguridad** de Configuración › Administración lo nombra (`backup.restore_limit`). Después vuelve a elegir el archivo de copia de seguridad |
| El envío se detiene con *Un proxy delante de LibreFolio rechazó un archivo de copia de seguridad de este tamaño: pide a quien lo ejecute que acepte subidas más grandes, o restaura desde la línea de comandos.*, o con *El servidor no responde: comprueba la conexión e inténtalo de nuevo.* o *El servidor respondió con un error: el registro del servidor tiene la causa.*, y el registro de LibreFolio no dice nada al respecto | Un proxy delante de LibreFolio rechazó el archivo de copia de seguridad: Nginx solo acepta 1 MB por defecto. El primer mensaje viene de un proxy que responde *demasiado grande* (HTTP 413), los demás de uno que corta la conexión o responde de otro modo | Deja que el proxy acepte archivos de copia de seguridad tan grandes como el tuyo, con `client_max_body_size` en Nginx ([El límite de subida de una restauración](backup_restore.md#restore-upload-limit)), o restaura desde la línea de comandos |
| *No hay suficiente espacio libre en el servidor para este archivo de copia de seguridad.* | El disco del directorio de datos, o una cuota, está lleno (`backup_no_space`): mientras se enviaba el archivo de copia de seguridad, y entonces no se conserva nada de él (un sistema de archivos de red o una cuota pueden informarlo solo al final del fichero), o cuando **Restaurar y reiniciar** confirmó la restauración, y entonces no se confirma nada y la copia comprobada se queda. El registro de una confirmación contiene `A restore could not be confirmed: not enough free space` | Libera espacio en el disco del directorio de datos y luego vuelve a elegir el archivo de copia de seguridad. Después de una confirmación, **Intentar de nuevo**: el informe vuelve, y **Restaurar y reiniciar** confirma de nuevo |
| *No hay suficiente espacio libre en el servidor para comprobar el archivo de copia de seguridad.* | El disco del directorio de datos, o una cuota, está lleno cuando empieza la comprobación, y entonces el archivo de copia de seguridad se queda en el servidor, o mientras la comprobación hace su copia (`no_space`) | Libera espacio, tanto como dice la fila `no_space` de [La comprobación rechaza el archivo de copia de seguridad](#check-refused), y luego vuelve a elegir el archivo de copia de seguridad |
| *No se pudo escribir la copia: el registro del servidor tiene la causa.* | La comprobación no pudo empezar, o no pudo escribir su copia, por otra razón distinta del espacio (`stage_failed`): el propietario o los permisos de una carpeta de `.restore/`, un disco de solo lectura, un error de disco. En el inicio, el registro contiene `A check of a backup archive could not start`, con el error y la razón del sistema | Corrige lo que nombra la línea del registro, como devolver `.restore/` al usuario que ejecuta LibreFolio, y luego vuelve a elegir el archivo de copia de seguridad |
| *No hay suficiente espacio libre en el servidor para la copia de seguridad.*, en la tarjeta **Hacer copia de seguridad de la instancia** | El disco del directorio de datos, o una cuota, está lleno (`backup_no_space`), al empezar la copia de seguridad o mientras se ejecutaba: la copia de seguridad se construye en `backups/`, en ese disco | Libera espacio en ese disco y luego **Intentar de nuevo**. Cuánto necesita una copia de seguridad: «Crear un archivo de copia de seguridad» en [Herramientas de administración por CLI](cli_tools.md) |
| *No se pudo confirmar la restauración: el registro del servidor tiene la causa. Nada cambió.*, después de **Restaurar y reiniciar** | No se pudo escribir la confirmación, por otra razón distinta del espacio (`restore_confirm_failed`): el propietario o los permisos de `.restore/`, un disco de solo lectura, un error de disco. El registro contiene `A restore could not be confirmed`, con el error y la razón del sistema. No se confirma nada, y la copia comprobada se queda | Corrige lo que nombra la línea del registro, como devolver `.restore/` al usuario que ejecuta LibreFolio, y luego **Intentar de nuevo**: el informe vuelve, y **Restaurar y reiniciar** confirma de nuevo |
| *No se pudo cancelar la restauración: el registro del servidor tiene la causa. Sigue esperando al siguiente inicio.*, después de **Cancelar la restauración**: la tarjeta sigue mostrando la restauración en espera, con **Reiniciar ahora y restaurar** y **Cancelar la restauración** | No se pudo descartar la restauración en espera (`restore_cancel_failed`): su estado en `.restore/` no se pudo bloquear ni eliminar, por su propietario o permisos, un disco de solo lectura o un error de disco. El registro contiene `A pending restore could not be cancelled`, con el error y la razón del sistema. Una copia que no se puede eliminar una vez descartada la restauración no es tal fallo: la restauración está cancelada, y el registro tiene la advertencia `The copy of a cancelled restore could not be removed: it goes when its check expires` | Corrige lo que nombra la línea del registro, y luego **Cancelar la restauración** de nuevo, en la misma tarjeta: hasta que se cancele, el siguiente inicio de LibreFolio aplica la restauración. Una copia que quede se elimina en el primer inicio de LibreFolio una vez que su comprobación tenga 24 horas |
| *No se pudo reiniciar LibreFolio: el registro del servidor tiene la causa. La restauración sigue esperando al siguiente inicio.*, después de **Restaurar y reiniciar** o **Reiniciar ahora y restaurar** | LibreFolio no se detuvo: el ticket con el que la página lee el resultado no se pudo escribir (`restore_restart_failed`), en un disco lleno o por el propietario o los permisos de `.restore/`. El registro contiene `The ticket of the restore's outcome could not be written: no restart`. La restauración está confirmada, y espera | Corrige lo que nombra la línea del registro, y luego **Reiniciar ahora y restaurar**, que la tarjeta muestra con la restauración en espera. O reinicia LibreFolio tú mismo, `docker compose restart librefolio` con Docker: su inicio aplica la restauración |
| *No se puede leer el estado de la restauración: el registro del servidor tiene la causa. Puede que una restauración siga esperando al siguiente inicio.* | LibreFolio no puede leer el estado de la restauración en `.restore/` (`restore_state_unreadable`): su propietario o sus permisos, como ficheros escritos por `root`, o un error de disco. No se sabe si una restauración espera: confirmar otra restauración también se rechaza, y un inicio que no puede leer el estado lo deja como está y no aplica nada | Devuelve `.restore/` y sus ficheros al usuario que ejecuta LibreFolio, de modo que pueda leerlos, y luego **Intentar de nuevo**. Con Docker, cada inicio del contenedor devuelve el directorio de datos a ese usuario antes de que LibreFolio lea el estado, así que una restauración que espera se aplica en ese inicio; los permisos cambiados con `chmod` se quedan como están. `backup pending` dice lo mismo, con la razón del sistema |
| La tarjeta rechaza el archivo de copia de seguridad, como *Este fichero no es una copia de seguridad de LibreFolio.*, *El archivo de copia de seguridad está dañado.* o *La copia de seguridad segura está dañada o se modificó: no se puede abrir.* | La comprobación lo rechazó, como hace `backup restore` | Consulta su código en [La comprobación rechaza el archivo de copia de seguridad](#check-refused) |
| La tarjeta vuelve a pedir la contraseña de una copia de seguridad segura: *Contraseña incorrecta, o el fichero se modificó: escribe la contraseña de nuevo.* | La contraseña no abre la copia de seguridad (`wrong_password`) | Escríbela de nuevo: el archivo de copia de seguridad se queda en el servidor y no se envía otra vez. Si la contraseña es correcta, el fichero se modificó: **Cancelar**, y luego elige una copia buena con **Elegir un archivo de copia de seguridad…** |

### 🔑 Después de una restauración {: #after-restore }

| Qué ocurre | Qué hacer |
| --- | --- |
| Nadie recuerda la contraseña que tenía un administrador en la copia de seguridad | Quien ejecuta el servidor establece una nueva con `user reset`, o crea un enlace de restablecimiento con `user reset-link` ([Restablecer una contraseña o bloquear una cuenta](cli_tools.md#reset-a-password-or-lock-an-account)) |
| La página de inicio de sesión responde que una cuenta está deshabilitada: estaba esperando su verificación por correo electrónico | Un administrador hace clic en **Reactivar** en su fila ([Qué hace cada acción](users.md#actions)), o la elimina para que su propietario se registre de nuevo ([Eliminar una cuenta](users.md#delete)) |
| Un enlace enviado antes de la restauración ya no funciona | Envía una nueva invitación o un nuevo enlace de restablecimiento de contraseña ([Usuarios e invitaciones](users.md)) |
| Un ajuste secreto de un plugin se informa como establecido pero ilegible, como anunció el informe de la comprobación (*… no se pueden leer con la clave de esta instancia: vuelve a introducirlos después de la restauración.*) | La copia de seguridad no llevaba ninguna clave que lo lea: una copia en claro, o una segura cuya instancia tenía una clave establecida en su entorno, o no podía usar la suya. Si aún tienes la clave antigua, vuelve a ponerla primero, antes de que nadie introduzca un secreto de nuevo; solo si no, vuelve a introducir el ajuste en **Configuración › Plugins**, donde cada usuario introduce el suyo ([Qué sigue](backup_restore.md#what-follows)). Si el registro de inicio dice que la clave propia de esta instalación no se puede usar, corrige eso primero («Comprobaciones de inicio» en [Variables de entorno](configuration.md)) |
| Tras un traslado, no sale ningún correo electrónico | Configura las variables de correo electrónico en esta instalación y luego reinicia ([Correo electrónico](email.md)) |
