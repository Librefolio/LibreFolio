# 🏠 Sauvegardes : déplacement et dépannage

Cette page fait partie du guide des sauvegardes. Elle couvre le **déplacement** de votre LibreFolio entre deux installations et ce qu'il faut faire **en cas de problème** avec une sauvegarde ou une restauration.

Le reste du guide commence à [Sauvegarde, restauration et déplacement de votre instance](backup_restore.md).

---

## 🏠 Rapatriez votre LibreFolio {: #bring-home }

Une archive déplace votre LibreFolio d'une installation à une autre. L'installation qui la reçoit doit utiliser la même version de LibreFolio ou une version plus récente ([Jamais de retour en arrière](#never-backwards)).

### ✋ À la main : décompressez avant le premier démarrage {: #by-hand }

Au lieu d'une restauration, décompressez l'archive dans le dossier de données avant le premier démarrage de LibreFolio, avec la même image ou une image plus récente. Le démarrage applique lui-même les migrations en attente.

```bash
# In the folder of docker-compose.yml, before the first start
unzip librefolio-backup-20261015-121500.zip -d LibreFolio-data
docker compose up -d
```

Une sauvegarde sécurisée (`.lfbk`) n'est pas un zip : transformez-la d'abord en zip avec `backup decrypt` (« Déchiffrer une archive sécurisée » dans [Outils d'administration CLI](cli_tools.md)), là où s'exécute la ligne de commande de LibreFolio, puis décompressez ce zip comme ci-dessus. Avec Docker, une restauration est plus simple : elle prend le `.lfbk` tel quel.

```bash
# Host installation
pipenv run ./dev.py backup decrypt librefolio-backup-20261015-121500.lfbk -o librefolio-backup-20261015-121500.zip

# Docker, in a running LibreFolio container: the paths inside it, and the zip where the container's user can write
docker compose exec librefolio python dev.py backup decrypt /app/backend/data/prod-docker/backups/librefolio-backup-20261015-121500.lfbk -o /app/backend/data/prod-docker/backups/librefolio-backup-20261015-121500.zip
```

- 📂 Le dossier de données doit être vide ou ne pas encore exister : si LibreFolio a déjà démarré dessus, arrêtez LibreFolio et mettez d'abord `LibreFolio-data` de côté. Aucune donnée étrangère ne doit se mélanger aux données de l'archive.
- 🔎 Rien ne vérifie l'archive au préalable : une archive endommagée, ou provenant d'un LibreFolio plus récent, se manifeste lorsque le démarrage échoue, et certains dommages n'apparaissent que plus tard, lorsqu'une page lit les données qu'elle touche. Une restauration, depuis Paramètres › Administration › Sauvegarde ou la ligne de commande, la vérifie sur une copie avant que quoi que ce soit ne change. Pour vérifier une archive avant de la décompresser à la main, utilisez une installation de LibreFolio qui tourne déjà : `backup inspect <archive>` compare chaque fichier avec le manifeste et, pour un zip, n'écrit rien ; `backup restore <archive> --dry-run` effectue toute la vérification d'une restauration, sur une copie (« Vérifier une archive » et « Essayer une restauration sur une copie » dans [Outils d'administration CLI](cli_tools.md)). L'essai à blanc travaille dans le dossier de données de cette installation : ne le pointez jamais vers le dossier vide que vous êtes sur le point de remplir.
- 🧹 Le `manifest.json` laissé dans `LibreFolio-data/` est inoffensif : vous pouvez le supprimer.
- 🔓 `backup decrypt` demande le mot de passe au terminal, ou le lit avec `--password-file` ou `--password-stdin`. Il ne remplace jamais un fichier : un `-o` qui existe déjà est refusé, et rien n'est écrit. Seul le propriétaire du zip peut le lire (`0600`) : l'utilisateur qui a exécuté la commande ou, avec Docker, l'utilisateur du conteneur. Il contient les données de tous les utilisateurs en clair, alors supprimez-le une fois décompressé. Lorsque la sauvegarde transporte la clé d'instance, la commande ajoute `🔑 It also holds the instance key: with it, every saved provider key can be read.` : quiconque possède ce zip peut aussi lire les clés enregistrées des fournisseurs de données.
- 🗝️ Avec une sauvegarde en clair, il n'y a pas de `secrets/` : LibreFolio crée une nouvelle clé d'instance la première fois qu'il en a besoin. Lorsque vous déplacez votre propre installation, remettez son `secrets/` dans `LibreFolio-data/` avant le premier démarrage, et les secrets enregistrés restent lisibles.
- 🔐 Le zip d'une sauvegarde sécurisée contient `secrets/instance.key` lorsque la sauvegarde transporte la clé : une fois décompressé, la clé est en place, et les clés enregistrées des fournisseurs de données restent lisibles. Avant le premier démarrage, rendez le dossier et le fichier privés, sinon le journal de démarrage contient un avertissement (« Vérifications au démarrage » dans [Variables d'environnement](configuration.md)) : `chmod 700 LibreFolio-data/secrets` et `chmod 600 LibreFolio-data/secrets/instance.key`.
- ⛔ N'utilisez la clé d'une sauvegarde que de cette manière, sur un dossier de données vide, et sur une installation qui ne définit ni `LIBREFOLIO_INSTANCE_KEY` ni `LIBREFOLIO_INSTANCE_KEY_FILE` : une clé définie dans cette installation prime sur `secrets/instance.key`, et les clés enregistrées des fournisseurs de données resteraient illisibles. Ne la mettez jamais à la place d'une clé déjà utilisée : ce qui a été enregistré sous cette clé deviendrait illisible. Pour transférer une sauvegarde sécurisée vers une installation qui possède sa propre clé, restaurez-la : la restauration rechiffre les clés enregistrées avec la clé de cette installation.
- 📖 Les étapes pour toute installation, y compris celle sur l'hôte : « Utiliser une archive sur une autre installation » dans [Outils d'administration CLI](cli_tools.md).

### ⛔ Jamais de retour en arrière {: #never-backwards }

LibreFolio ne ramène jamais une base de données à une version antérieure : utilisez la version qui a créé l'archive, ou une version plus récente. Un LibreFolio plus ancien refuse une archive dont la base de données contient une migration qu'il ne connaît pas.

- 🏷️ `backup inspect` indique quelle version a créé l'archive (`Made by LibreFolio <version>`), et **Paramètres › À propos** indique la version d'une instance.
- ❌ `backup restore` refuse une telle archive avec `revision_unknown`, avant que quoi que ce soit ne change.
- 🛑 À la main, un LibreFolio plus ancien ne démarre pas sur de telles données : son journal contient `Failed to apply database migrations`, et Docker ne cesse de redémarrer le conteneur. Arrêtez-le avec `docker compose down`.

Mettez d'abord à jour le LibreFolio qui reçoit l'archive ([Mise à jour de LibreFolio](../user/installation.md#updating)), puis restaurez. Avec Docker, l'image `latest` est la version la plus récente.

## 🧯 En cas de problème {: #troubleshooting }

### 🔐 Créer une sauvegarde sécurisée {: #secure-problems }

| Ce que vous voyez | Pourquoi | Que faire |
| --- | --- | --- |
| `❌ A password is needed: give it with --password-file or --password-stdin, or run the command at a terminal (password_required)` | `backup create --encrypt` sans terminal pour poser la question, par exemple dans cron | Indiquez le mot de passe avec `--password-file` ou `--password-stdin` ([Depuis la ligne de commande](backup_restore.md#command-line)) |
| `❌ The password of a backup needs at least 12 characters, with an uppercase and a lowercase letter, a digit and a symbol (password_too_weak: …)`, ou dans Paramètres › Administration › Sauvegarde *Le mot de passe ne respecte pas les règles d'un mot de passe de sauvegarde.* | Le mot de passe ne respecte pas les règles listées après `password_too_weak:`. Dans Paramètres, l'indicateur garde **Créer une sauvegarde** désactivé tant que toutes les règles ne sont pas respectées ; lorsqu'il n'a pas pu lire les règles d'une sauvegarde depuis le serveur (`GET /api/v1/backup/instance/options`), il vérifie celles d'un mot de passe de compte, avec 8 caractères, et le serveur refuse un mot de passe plus court que 12 | Choisissez un mot de passe plus long qui respecte toutes les règles. Rien n'a été écrit |
| `❌ The two passwords differ (password_mismatch)` | Le second mot de passe saisi au terminal n'est pas le premier | Relancez la commande |
| `❌ password file: <path> does not exist (password_unreadable)`, ou `cannot be read`, `is empty or blank`, `is not UTF-8 text` | `--password-file` ne peut pas fournir le mot de passe | Corrigez le fichier : il contient uniquement le mot de passe, en UTF-8. Avec Docker, indiquez le chemin à l'intérieur du conteneur, par exemple `/run/secrets/backup_password` |
| `⚠️ The instance key cannot be used: the secure backup was made without it, so saved provider keys must be entered again after a restore`, ou dans Paramètres › Administration › Sauvegarde *La clé d'instance ne peut pas être utilisée : la sauvegarde a été créée sans elle, donc les clés des fournisseurs de données doivent être saisies à nouveau après une restauration.* | `secrets/instance.key` est présent, mais endommagé ou inaccessible, ou plus long que 4096 octets, soit plus qu'une restauration n'en relit (la clé générée par LibreFolio fait 43 caractères). La sauvegarde est complète, sans la clé | Si le journal de démarrage indique ce qui ne va pas avec la clé, corrigez-le d'abord (« Vérifications au démarrage » dans [Variables d'environnement](configuration.md)), puis créez une nouvelle sauvegarde sécurisée. S'il ne dit rien, la clé est trop longue pour être transportée : conservez une copie de `secrets/` avec la sauvegarde, comme pour une sauvegarde en clair |

### 🧾 La vérification refuse l'archive {: #check-refused }

`backup restore`, avec ou sans `--dry-run`, se termine par un refus avec son code entre parenthèses, et ne change rien. Paramètres › Administration › Sauvegarde refuse les mêmes archives et en indique la raison sur sa carte, sans le code : *L'archive est endommagée.* pour `archive_damaged`, par exemple.

| Code | Pourquoi | Que faire |
| --- | --- | --- |
| `revision_unknown` | L'archive provient d'un LibreFolio plus récent | Mettez à jour celui-ci ([Jamais de retour en arrière](#never-backwards)), puis relancez la commande |
| `manifest_newer_format` | Le format de l'archive est plus récent que ce que ce LibreFolio sait lire | Mettez d'abord LibreFolio à jour |
| `checksum_mismatch`, `archive_damaged`, `missing_entry` | L'archive est endommagée, tronquée ou a été modifiée | `backup inspect` nomme les entrées qui diffèrent. Copiez à nouveau l'archive depuis l'endroit où vous la conservez, ou utilisez-en une autre |
| `database_damaged` | La base de données de l'archive échoue au contrôle d'intégrité de SQLite, SQLite ne peut pas lire son schéma, ou elle contient du texte qui n'est pas en UTF-8 : LibreFolio n'écrit jamais un tel texte et, après une restauration, chaque liste qui le contiendrait ne pourrait pas se charger. Paramètres › Administration › Sauvegarde : *La base de données de la sauvegarde est endommagée : elle ne peut pas être restaurée.* | Copiez à nouveau l'archive depuis l'endroit où vous la conservez, ou utilisez-en une autre. Un texte qui n'est pas en UTF-8 signifie qu'un autre programme a écrit dans la base de données ou que l'archive a été modifiée |
| `database_foreign_objects` | La base de données de l'archive contient un trigger, une vue ou une table virtuelle. LibreFolio ne les crée jamais, et leur SQL s'exécuterait pendant la vérification et dans le serveur après une restauration ; la vérification les refuse donc avant d'ouvrir la copie pour quoi que ce soit d'autre. Paramètres › Administration › Sauvegarde : *La base de données de la sauvegarde contient des triggers, des vues ou d'autres objets que LibreFolio ne crée jamais : elle n'a pas été créée par LibreFolio, ou elle a été modifiée, et elle ne peut pas être restaurée.* | L'archive n'a pas été créée par LibreFolio, ou a été modifiée ensuite : utilisez une autre sauvegarde |
| `not_a_backup` | Ce n'est pas une archive écrite par LibreFolio, par exemple un dossier de données zippé à la main | Remettez une telle copie [à la main](#by-hand), dans un dossier de données vide |
| `sealed_backup_needs_key` | Une sauvegarde nocturne scellée (`.tar`) : son mot de passe est à l'intérieur, chiffré pour une clé, et la vérification ne peut pas l'ouvrir. Paramètres › Administration › Sauvegarde : *Il s'agit d'une sauvegarde scellée d'un panneau d'hébergement : son mot de passe est chiffré pour la clé du fournisseur. Extrayez backup.lfbk, ouvrez password.age avec age, puis restaurez backup.lfbk avec ce mot de passe.* | Restaurez-la là où se trouve sa clé privée : `backup restore <archive>.tar --identity-file <key file>` ([Sauvegardes scellées](backup_sealed.md#sealed)) |
| `sealed_no_identity`, `sealed_identity_invalid`, `sealed_tar_invalid`, `sealed_manifest_invalid`, `sealed_password_invalid` | Une [sauvegarde scellée](backup_sealed.md#sealed) fournie avec `--identity-file` qui ne s'ouvre pas | Voir [Créer ou ouvrir une sauvegarde scellée](#sealed-problems) |
| `no_space` | La copie a besoin de plus d'espace libre que le disque du dossier de données n'en a | Libérez de l'espace : l'archive décompressée, plus deux fois sa base de données, plus 64 Mo, et pour une sauvegarde sécurisée, aussi la taille de son `.lfbk` |
| `archive_unreadable` | L'archive ne peut pas être ouverte, le plus souvent parce que l'utilisateur du serveur n'a pas le droit de la lire | Avec Docker et l'image officielle, `sudo chown 1000:1000 <archive>` sur l'hôte la donne à cet utilisateur |
| `restore_already_pending` | Une autre restauration attend le prochain démarrage | Redémarrez LibreFolio pour l'appliquer, ou abandonnez-la avec `backup pending --cancel` ou **Annuler la restauration** dans Paramètres › Administration › Sauvegarde |
| `wrong_password` | Le mot de passe n'ouvre pas la sauvegarde sécurisée : ce n'est pas celui avec lequel elle a été créée, ou le début du fichier a été modifié. Paramètres › Administration › Sauvegarde le redemande : *Mot de passe incorrect, ou le fichier a été modifié : saisissez à nouveau le mot de passe.* | Saisissez-le à nouveau tel qu'il a été choisi, majuscules et minuscules comprises. S'il est correct, copiez à nouveau le fichier depuis l'endroit où vous le conservez |
| `password_required` | Une sauvegarde sécurisée, et aucun mot de passe : la commande n'avait pas de terminal pour poser la question, et ni `--password-file` ni `--password-stdin` n'avait été fourni | Exécutez la commande dans un terminal, ou indiquez le mot de passe avec l'une des deux options |
| `envelope_damaged` | La sauvegarde sécurisée est endommagée, tronquée ou a été modifiée après sa création | Copiez-la à nouveau depuis l'endroit où vous la conservez, ou utilisez-en une autre : LibreFolio ne lit aucune partie d'un `.lfbk` endommagé |
| `envelope_unsupported` | La sauvegarde sécurisée provient d'un LibreFolio plus récent, ou demande des paramètres que celui-ci n'accepte pas | Mettez d'abord celui-ci à jour ([Jamais de retour en arrière](#never-backwards)), puis relancez la commande |

Deux autres messages :

- `❌ No file at <path>` : avec Docker, indiquez le chemin à l'intérieur du conteneur, `/app/backend/data/prod-docker/…`.
- `❌ The backup has no active administrator: after a restore nobody could manage the instance`, ou la même chose dans le rapport de Paramètres › Administration › Sauvegarde, dont la confirmation reste alors désactivée : sur l'installation d'où vient la sauvegarde, faites d'un compte actif un administrateur, puis créez une nouvelle sauvegarde.

Tous les codes : « Refus — signification des codes » dans [Outils d'administration CLI](cli_tools.md).

Deux avertissements laissent la restauration se poursuivre, mais lisez-les avant de confirmer.

- 🔑 *Votre compte ne figure pas parmi les administrateurs de cette sauvegarde : après le redémarrage, vous ne pourrez pas vous connecter avec ce compte.* Celui-ci n'apparaît que dans le rapport de Paramètres › Administration › Sauvegarde, en rouge. Après une restauration, vous vous connectez avec un compte de la sauvegarde, avec le mot de passe qu'il avait alors, et le compte que vous utilisez actuellement ne s'y trouve pas. Avant de confirmer, assurez-vous de connaître le mot de passe de l'un des administrateurs nommés dans le rapport. Si vous ne le connaissez pas, utilisez une autre sauvegarde.
- `⚠️ Ledger totals differ from the backup's (<n> lines):`, ou *Les totaux du grand livre diffèrent de ceux de la sauvegarde sur 2 lignes :* dans le rapport de Paramètres › Administration › Sauvegarde : la trésorerie d'un courtier ou la quantité d'une position dans la copie, une fois à jour, ne correspond pas à ce que la sauvegarde a enregistré. Des transactions ont été perdues, ajoutées ou modifiées entre la sauvegarde et la copie, par exemple par une migration qui corrige des données. Lisez les lignes qui suivent : chacune donne un numéro de courtier, puis un numéro de devise ou d'actif, avec le montant de la sauvegarde avant la flèche et celui de la copie après. Les numéros sont ceux des adresses des pages du courtier et de l'actif dans l'application, `/brokers/<id>` et `/assets/<id>`. Comparez ces lignes avec l'instance d'où vient la sauvegarde. L'avertissement ne bloque jamais la restauration : c'est à vous de décider si vous confirmez.

### 🔏 Créer ou ouvrir une sauvegarde scellée {: #sealed-problems }

Pour en créer une, avec `backup create --sealed` ou `--recipient` : rien n'est écrit et la commande se termine avec le code `1`.

| Ce que vous voyez | Pourquoi | Que faire |
| --- | --- | --- |
| `❌ LIBREFOLIO_BACKUP_RECIPIENTS is not set: give the recipients there, or with --recipient age1…` | `--sealed` n'a trouvé aucune variable : absente de `.env`, ou le conteneur n'a pas été recréé après son ajout | Définissez-la ([Sceller chaque sauvegarde](backup_sealed.md#sealed-recipients)), puis `docker compose up -d`, ou exécutez la commande depuis le dossier du projet avec `pipenv run`, qui lit `.env` |
| `❌ LIBREFOLIO_BACKUP_RECIPIENTS: item 2 is not an age recipient: expected age1… as age-keygen prints it (BACKUP_RECIPIENTS_INVALID)`, ou `expected at most 2 recipients, comma-separated (BACKUP_RECIPIENTS_TOO_MANY)`, ou `item 2 repeats an earlier recipient (BACKUP_RECIPIENTS_DUPLICATE)` | La variable contient autre chose qu'une ou deux clés `age1…` différentes : une clé privée, une clé SSH, une virgule en trop | N'écrivez que les clés publiques, telles que les affichent `keygen` ou `age-keygen -y`. L'onglet **Sécurité** indique la même chose (`backup.recipients`) |
| `❌ A --recipient is not an age recipient: expected age1…, as keygen or age-keygen prints it`, `❌ The same recipient is given twice`, `❌ At most 2 recipients: --recipient twice, while a key is being changed` | Les mêmes règles, pour `--recipient` | Indiquez une ou deux clés publiques différentes |
| `❌ A sealed backup draws a password of its own: --sealed and --recipient go without --encrypt, --password-file or --password-stdin` | Une sauvegarde scellée génère son propre mot de passe | Retirez les options de mot de passe |
| `❌ --sealed reads the recipients from LIBREFOLIO_BACKUP_RECIPIENTS: give them there or with --recipient, not both` | `--sealed` et `--recipient` ensemble | Gardez l'un des deux |
| `❌ <path> already exists: a key file is never written over` | `backup keygen` ne remplace jamais une clé : l'ancienne peut encore ouvrir des sauvegardes | Choisissez un autre nom de fichier, ou déplacez d'abord l'ancien fichier si vous êtes sûr qu'aucune sauvegarde n'en a besoin |

Pour en ouvrir une, avec `--identity-file` : la commande ne change rien et se termine avec le code `1`. Le fichier de clé est lu d'abord, puis le `.tar`.

| Ce que vous voyez | Pourquoi | Que faire |
| --- | --- | --- |
| `(sealed_backup_needs_key)` | Un `.tar` fourni sans `--identity-file`, sur la ligne de commande ou dans Paramètres › Administration › Sauvegarde | Indiquez le fichier de clé, ou [ouvrez-la à la main](backup_sealed.md#sealed-by-hand) et restaurez `backup.lfbk` avec son mot de passe |
| `❌ --identity-file opens a sealed backup (.tar) only: <path> is not one` | Un `.zip` ou un `.lfbk` fourni avec `--identity-file` | Retirez `--identity-file` : ces archives s'ouvrent comme d'habitude |
| `❌ The key file cannot be read (sealed_identity_invalid)`, `Line 3 of the key file is not an age key`, `The key file holds no age key` | Le fichier n'est pas une clé privée : la clé publique seule, une clé copiée avec un caractère manquant, ou un fichier que la commande n'a pas le droit de lire | Indiquez le fichier écrit par `keygen` ou `age-keygen`, avec sa ligne `AGE-SECRET-KEY-1…`. Les commentaires (`#`) et les lignes vides peuvent rester |
| `❌ None of the keys given opens the password of this backup (sealed_no_identity)` | La sauvegarde a été scellée pour une autre clé : une clé plus ancienne, avant un [changement de clé](backup_sealed.md#sealed-rotation) | Comparez ses `recipients` (`tar xOf <archive>.tar manifest.json`) avec la ligne `# public key:` de vos fichiers de clé, et indiquez celui qui correspond |
| `(sealed_tar_invalid)`, comme `The archive is cut short` ou `The archive does not hold manifest.json, password.age and backup.lfbk, in this order` | Ce n'est pas le `.tar` écrit par LibreFolio : tronqué par une copie, reconstruit à la main avec `tar cf`, ou ce n'est pas une sauvegarde scellée | Copiez à nouveau l'original depuis l'endroit où vous le conservez, ou utilisez la sauvegarde d'une autre nuit |
| `(sealed_manifest_invalid)`, comme `The manifest does not describe backup.lfbk: its size or SHA-256 differs` | `manifest.json` a été modifié, ou `backup.lfbk` l'a été | La copie est endommagée : utilisez-en une autre |
| `(sealed_password_invalid)` | La clé a ouvert `password.age`, mais ce qu'il contient n'est pas un mot de passe écrit par LibreFolio | Ce n'est pas une sauvegarde LibreFolio, ou elle a été modifiée : utilisez une autre copie |
| `❌ The password does not open this backup (wrong_password)` | La clé a ouvert le mot de passe, mais ce mot de passe n'ouvre pas `backup.lfbk` : les deux fichiers viennent de sauvegardes différentes, ou l'un a été modifié | Utilisez une autre copie, conservée entière telle que LibreFolio l'a écrite |
| `(envelope_damaged)`, pendant la vérification ou la restauration | Un octet de `backup.lfbk` a été modifié après la création de la sauvegarde : le mot de passe était correct | Utilisez une autre copie : LibreFolio ne lit aucune partie d'un `.lfbk` endommagé |

### 🔁 La restauration n'aboutit pas {: #restart-problems }

| Ce que vous voyez | Pourquoi | Que faire |
| --- | --- | --- |
| `backup pending` indique `The state of the restore cannot be read`, `(restore_state_unreadable: <reason>)` | `.restore/restore.json` ne peut pas être utilisé : ses permissions (`io`), un lien ou un dossier à sa place (`not_a_file`), ou un contenu que LibreFolio n'a pas écrit (`invalid`). Une restauration a peut-être été interrompue à mi-chemin. Aucune copie vérifiée n'est supprimée pendant ce temps | Pour `io`, redonnez `.restore/` à l'utilisateur qui exécute LibreFolio et vérifiez à nouveau. Sinon, arrêtez LibreFolio et exécutez `backup pending --recover previous` : les données d'avant reviennent depuis `.restore/previous/`. Redémarrez-le ensuite, ou restaurez à nouveau une sauvegarde : « Un état de restauration illisible » dans [Outils d'administration CLI](cli_tools.md) |
| `backup pending` se termine par `(server_running)` | Au dernier démarrage, un autre processus serveur servait le dossier de données : un worker a redémarré tout seul, ou un second serveur | Redémarrez tout le serveur, jamais un seul worker, et exécutez un seul serveur par dossier de données |
| `backup pending` se termine par `(other_data_directory)` | Le serveur a trouvé son dossier de données sous un autre chemin que celui pour lequel la restauration a été confirmée, par exemple une copie du dossier de données | `backup pending --cancel`, ou **Annuler la restauration** dans Paramètres › Administration › Sauvegarde, puis restaurez à nouveau l'archive : avec `backup restore`, là où le serveur s'exécute |
| `backup pending` se termine par `(backup_running)` | Une sauvegarde était en cours au dernier démarrage | Rien : le prochain démarrage applique la restauration |
| `backup pending` indique que la restauration a été annulée, `(first_start_failed)` | Le premier démarrage sur les données restaurées ne s'est pas terminé | Les données sont telles qu'elles étaient. Le journal de ce démarrage contient la cause : corrigez-la, puis restaurez à nouveau l'archive |
| … annulée, `(swap_interrupted)` | Le démarrage qui a appliqué la restauration a été interrompu, et le suivant l'a annulée | Restaurez à nouveau l'archive |
| … annulée, `(swap_failed)` | Les dossiers n'ont pas pu être mis en place | Faites en sorte que `sqlite/`, `custom-uploads/`, `broker_reports/` et `scenario_catalog/` soient de vrais dossiers du dossier de données, et non des liens ou des montages séparés, puis restaurez à nouveau l'archive |
| … annulée, `(stage_missing)` | La copie vérifiée avait disparu ou changé | Restaurez à nouveau l'archive |
| Un démarrage s'arrête, et son journal indique qu'un autre serveur a appliqué la restauration ou sert le dossier de données | Deux serveurs LibreFolio utilisent le même dossier de données | Arrêtez l'autre, puis redémarrez LibreFolio : `backup pending` indique alors si la restauration a été conservée |
| LibreFolio ne démarre pas, et son journal contient `The data directory is half restored` | Même la remise en place des données précédentes a échoué, à cause par exemple d'une erreur de disque ou de permissions | Corrigez la cause indiquée par le journal : chaque démarrage réessaie |
| `Failed to apply database migrations` après une décompression à la main | Une archive d'un LibreFolio plus récent, ou une migration qui échoue : le journal contient l'erreur | Pour une archive plus récente, `docker compose down`, puis utilisez la version qui l'a créée ou une version plus récente ([Jamais de retour en arrière](#never-backwards)) |

### 🔑 Après une restauration {: #after-restore }

| Ce qui se passe | Que faire |
| --- | --- |
| Personne ne se souvient du mot de passe qu'un administrateur avait dans la sauvegarde | Qui exploite le serveur en définit un nouveau avec `user reset`, ou crée un lien de réinitialisation avec `user reset-link` ([Réinitialiser un mot de passe ou verrouiller un compte](cli_tools.md#reset-a-password-or-lock-an-account)) |
| La page de connexion répond qu'un compte est désactivé : il attendait sa vérification par e-mail | Un administrateur clique sur **Réactiver** sur sa ligne ([Ce que fait chaque action](users.md#actions)), ou le supprime pour que son propriétaire s'inscrive à nouveau ([Supprimer un compte](users.md#delete)) |
| Un lien envoyé avant la restauration ne fonctionne plus | Envoyez une nouvelle invitation ou un nouveau lien de réinitialisation du mot de passe ([Utilisateurs et invitations](users.md)) |
| Un paramètre de plugin secret est signalé comme défini mais illisible, comme l'avait annoncé le rapport de la vérification (*… ne peut pas être lu avec la clé de cette instance : saisissez-le à nouveau après la restauration.*) | La sauvegarde ne contenait aucune clé permettant de le lire : une sauvegarde en clair, ou une sauvegarde sécurisée dont l'instance avait une clé définie dans son environnement, ou ne pouvait pas utiliser la sienne. Si vous avez encore l'ancienne clé, remettez-la d'abord, avant que quiconque ne saisisse à nouveau un secret ; ce n'est que dans le cas contraire que vous devez saisir à nouveau le paramètre dans **Paramètres › Plugins**, où chaque utilisateur saisit le sien ([Ce qui suit](backup_restore.md#what-follows)). Si le journal de démarrage indique que la clé propre à cette installation ne peut pas être utilisée, corrigez cela d'abord (« Vérifications au démarrage » dans [Variables d'environnement](configuration.md)) |
| Après un déplacement, aucun e-mail n'est envoyé | Définissez les variables d'e-mail sur cette installation, puis redémarrez ([E-mail](email.md)) |
