# 🌍 Internationalization (i18n)

LibreFolio supports multiple languages to ensure accessibility for a global audience. The frontend uses **[svelte-i18n](https://github.com/kaisermann/svelte-i18n)** for managing
translations and locale switching.

## 🗣️ Supported Languages

Currently, the following languages are supported:

- 🇬🇧 **English** (`en`) - *Default*
- 🇮🇹 **Italian** (`it`)
- 🇫🇷 **French** (`fr`)
- 🇪🇸 **Spanish** (`es`)

## 🏗️ Architecture

Translations are stored in JSON files located in `frontend/src/lib/i18n/`.

```text
frontend/src/lib/i18n/
├── en.json                    # Source of truth
├── it.json
├── fr.json
├── es.json
├── index.ts                   # Configuration and initialization
└── catalogIcuLocale.test.ts   # Unit test: no locale-sensitive ICU message shared by two catalogues
```

### 💻 Usage in Components

To use translations in Svelte components, import the `t` store:

```svelte
<script>
  import { t } from '$lib/i18n';
</script>

<h1>{$t('dashboard.welcome')}</h1>
<p>{$t('common.save')}</p>
```

`$lib/i18n` also re-exports `_`, svelte-i18n's other name for the same store: `$_('common.save')` and
`$t('common.save')` are interchangeable, and both appear in the codebase.

### 🔀 Dynamic Values

Messages use the ICU MessageFormat syntax (svelte-i18n formats them with `intl-messageformat`):

```json
{
  "greeting": "Hello, {name}!",
  "positions": "{n, plural, one {# position} other {# positions}}"
}
```

Pass the variables under the `values` option:

```svelte
<p>{$t('greeting', {values: {name: 'Alice'}})}</p>
<p>{$t('positions', {values: {n: 3}})}</p>
```

Without `values` the message comes back as written, placeholders included:
`$t('greeting', {name: 'Alice'})` renders `Hello, {name}!`.

### ⚠️ Locale-Sensitive ICU Messages

svelte-i18n 4.0.1 (the locked version) caches compiled message formatters **by message text only**:
`getMessageFormatter` is wrapped in `monadicMemoize`, which keys the cache on its first argument and never
sees the locale (`frontend/node_modules/svelte-i18n/dist/runtime.js`, lines 383–392 and 496). The app
switches language in place, so a message that is byte-identical in two catalogues keeps the rules of
whichever locale compiled it first.

This changes what the user reads only for locale-sensitive elements: `plural`, `selectordinal`,
`number`, `date` and `time`. Plain text, `{name}` substitutions and `select` render the same in every
locale. For example, `0` selects `one` in French but `other` in English: if the French catalogue reused
the English `positions` text above verbatim, a page rendered in English first would keep showing
`0 positions` after a switch to French, instead of `0 position`.

**Rule**: a locale-sensitive message must never be byte-identical across catalogues. When a translation
would coincide with another locale's text, make it differ. For a French plural, add the CLDR `many`
branch:

```json
{
  "positions": "{n, plural, one {# position} many {# positions} other {# positions}}"
}
```

The unit test `frontend/src/lib/i18n/catalogIcuLocale.test.ts` enforces the rule on the four catalogues.
It also pins the library behaviour: if a svelte-i18n upgrade adds the locale to the cache key, its
characterization test turns red, which is the signal to revisit the rule.

## 🔢 Numbers, amounts and dates {: #ui-locale }

**The rule** (M-18, developer decision of 2026-10-12): every figure — number, amount, percentage, exact
decimal, file size, duration, date, chart axis and tooltip — is written in the **interface language**,
through one source: `uiLocale()` from `$lib/stores/app/uiLocale`. Never in the browser's own locale, so a
percentage never sits beside an amount written another way. Paths below are relative to `frontend/src/`.

### 🗺️ Which locale

`resolveUiLocale(uiLanguage, browserTag)` builds the locale from the interface language. The browser
counts only for its region: when its **primary** tag (`navigator.language`) is in the interface language
and names a region, that tag is the locale. The `navigator.languages` list is never read: browsers list
`en-US` among the secondary languages of most users, so reading it would give an Italian who chose
English American dates.

| Browser primary tag | Locale | Examples |
|:--------------------|:-------|:---------|
| In the interface language, with a region | The browser's tag, canonical | `en-GB`, `en-US`, `it-CH`, `fr-CA`, `es-MX`, `es-419` |
| Without a region, in another language, absent (server side) or invalid | The language's default: `en-GB` for English (12/10/2026, 12 Oct 2026, 14:05), the bare language for `it`, `fr`, `es` | English UI on `en` or `it-IT` → `en-GB`; Italian UI on `en-US` → `it` |

So an Italian interface on an `it-CH` browser writes a decimal point (`12.50%`), a French one on `fr-CA`
writes numeric dates the ISO way (`2026-10-12`), and a bare `en` browser gets `en-GB`: kept as it is,
`Intl` would write it American (10/12/2026, 2:05 PM).

### 🧰 Formatters

Every formatter below defaults to `uiLocale()`, so runes code passes no locale; a legacy component passes
`$uiLocaleStore` (see [Reactivity](#ui-locale-reactivity)), and a unit test may pass a fixed locale to
stay deterministic.

| Formatter | File | Writes |
|:----------|:-----|:-------|
| `formatPercent(value, {digits, signed, scale, suffix, empty, locale})` | `lib/utils/core/formatPercent.ts` | A percentage through `Intl` (`style: 'percent'`), rounded first with `toFixed` so the digits are the ones `toFixed` gave. `digits` defaults to 2 and `signed` to `true`: a `+` before a positive value, no sign on zero. `scale: 100` for a fraction, `suffix: 'pp'` for percentage points, `''` for a bare number. |
| `formatFixed(value, digits, {signed, trim, locale})` | `lib/utils/core/formatFixed.ts` | The localized `toFixed`: the same digits and rounding, with the locale's decimal mark and grouping. `trim` turns `digits` into a maximum; `signed` defaults to `false`. |
| `formatExactDecimal(value, {minFrac, maxFrac, locale})` | `lib/utils/core/formatFixed.ts` | An exact decimal — a backend decimal string, a quantity, a rate, a split ratio — with no float in between. The digits are those of `formatDecimalForDisplay`: cut after `maxFrac` (default 8), never rounded, trailing zeros dropped, padded to `minFrac` (default 0), `-0` read as `0`. `Intl.NumberFormat` is handed them as a string and only writes them. Empty input gives `''`; a value that is not a plain decimal is returned unformatted. |
| `formatCurrencyAmountPlain`, `formatCurrencyAmountHtml` | `lib/utils/currency/currencyFormat.ts` | Money, masked under [privacy](state/app-state.md#privacy-masking); option `locale`. |
| `formatDateTime(value, locale?)` | `lib/utils/core/formatDateTime.ts` | A date and time, to the minute. |
| `formatAxisDate(locale, value, withYear?)` | `lib/utils/core/formatAxisDate.ts` | A short date for a chart axis or tooltip. An empty `locale` means `uiLocale()`; a bare `YYYY-MM-DD` is read as a local calendar day. |

The domain helpers built on them take a `locale` parameter that defaults to `uiLocale()` as well:

- lots, in `lib/components/brokers/lots/`: `formatLotQuantity`, `formatLotQuantityMasked`,
  `formatLotQuantityCell`, `formatQuantity` (Gantt), `formatAxisPercent`, `formatAxisCurrency`,
  `formatAxisAmount`, `formatAxisNumber`;
- risk, in `lib/components/risk/`: `formatCurrencyAmount`, `formatScopedCurrencyAmount`, `dayFormatter`;
- the PAC planner, in `lib/features/tools/pac-allocator/planner/format.ts`: `formatPlannerDate`,
  `formatPlannerTimestamp`, `formatCopyStamp`;
- file sizes: `formatBytes`, in `lib/utils/files/upload.ts`.

### 🚫 Never, for display

- `toFixed` or `toPrecision`: they write no locale at all, so an Italian screen read `9.2` beside
  `4788,01`;
- `formatDecimalForDisplay` for a figure that is only read: it writes a dot in every language, where
  `formatExactDecimal` writes the same digits in the interface locale;
- `toLocaleString(undefined, …)`, a `toLocaleString()`, `toLocaleDateString()` or `toLocaleTimeString()`
  with no locale, `Intl.NumberFormat(undefined, …)` or any other `Intl.*Format(undefined, …)`: the
  browser's locale;
- a hard-coded `'en'` or `'en-US'`;
- `$currentLanguage` or `$locale` as the locale of a figure: a bare language drops the browser's region,
  and a bare `en` writes American dates.

`$currentLanguage` and `$locale` stay right for **text**, which this rule does not cover: translations,
country, currency and sector names, `Intl.ListFormat`, the AI Export response language. Name collation
(`nameComparator`) is text as well; its callers pass no locale today, so it sorts by the browser's rules.

### ⚡ Reactivity {: #ui-locale-reactivity }

`uiLocale()` reads the store through Svelte's `fromStore`, so the read is tracked wherever Svelte tracks:

- **Runes components**: a read in a template, a `$derived` or an `$effect` is tracked, even inside a
  helper's default parameter, so `{formatPercent(value)}` follows an in-place language switch.
- **Legacy components** (no runes: `export let`, `$:`): a function call in a template expression is
  compiled into `$.untrack(…)`, so a read inside the helper is untracked and the figure keeps the language
  of the mount. The template reads `$uiLocaleStore` itself and passes it down:
  `formatSharePercentage(broker.user_share_percentage, $uiLocaleStore)` in
  `routes/(app)/brokers/[id]/+page.svelte`, `formatDate($currentUser?.created_at, $uiLocaleStore)` in
  `lib/components/settings/tabs/ProfileTab.svelte`. It is the trap behind the
  [privacy freeze](state/app-state.md#privacy-legacy-freeze) (devWiki:
  `problems/legacy-component-language-untracked`).
- **ECharts**: `formatter` and `renderItem` callbacks run outside any tracking. The `$effect` that calls
  `setOption` reads the locale itself, `void uiLocale();` beside its other `void` dependencies, so a switch
  rebuilds the option and redraws the chart (`lib/components/charts/ScatterChart.svelte`), as it does for
  the [privacy flag](state/app-state.md#privacy-echarts).

### 🧩 Known exceptions

- **Decimal fields**: `formatDecimalForDisplay` (`lib/utils/core/formatDecimal.ts`) stays locale-neutral,
  with a dot, wherever its output must read back through `normalizeDecimalInput`
  (`lib/utils/core/parseDecimalInput.ts`): the value of `ExactDecimalInput` and `ExactQuantityInput`, the
  edit buffer of `CompactCashCell`. Localizing a field means localizing its reading too. It also serves
  logic that displays nothing: `pluralCount` in the PAC planner's `format.ts`, and the "did the amount
  change" comparison of `WacPreviewSection`.
- **Native date fields**: an `<input type="date">` is drawn by the browser, in the browser's language
  (backlog T-DI).
- **Figures inside catalogue messages** (backlog T-ICU): svelte-i18n writes an ICU `number` argument and
  the `#` of a plural in its own locale, the bare language, without `uiLocale()`'s region. The only
  `number` argument is `{covered, number, percent}` in `risk.warnings.historical_replay_mostly_excluded`,
  and the catalogues hold no ICU dates. It shows only where the region changes the notation: on an
  `es-MX` browser a plural's `#` reads `1234` where the rest of the page writes `1,234`.
- **The AI Export prompt** writes its figures locale-neutral by design, so `uiLocale()` never changes a
  byte of it; the interface language reaches it only as text (the response language, the translated
  additional-data section). The panel's token count and byte size, and the copied message, are figures
  like any other.
- **Currency minor digits**: `new Intl.NumberFormat('en', {style: 'currency', currency})` only reads
  `maximumFractionDigits` (`lib/features/ai-export/templates/snapshotDataRenderer.ts`,
  `lib/features/tools/pac-allocator/planner/format.ts`); it writes nothing.
- **The time zone**: `Intl.DateTimeFormat().resolvedOptions().timeZone`
  (`lib/components/settings/tabs/GlobalSettingsTab.svelte`) reads the browser's zone, not a notation.

### 🧪 Testing

- Drive the language with `currentLanguage.set(…)` (`$lib/stores/app/language`), as the language selector
  does, and set it back to English after the test.
- Pin `navigator.language` when the region matters: the test runtime's tag can follow the host
  (`LANG=it_CH.UTF-8` gives `it-CH`). Stub it before the first import, as
  `lib/utils/core/__tests__/formatPercent.test.ts` does with
  `vi.hoisted(() => { vi.stubGlobal('navigator', {language: 'en-US', languages: ['en-US']}); })`, or per
  test with `vi.stubGlobal`, `vi.resetModules()` and a fresh `import()`, as
  `lib/stores/app/uiLocale.test.ts` does.
- Compute a localized expectation with `Intl` in the same runtime, never as a typed literal: French,
  Italian and Spanish output carries no-break spaces (U+202F, U+00A0), and ICU has changed which one goes
  where between releases. Check that the expectation differs from the English text, or the case proves
  nothing.
- Switch the language in place, after mount and in both directions: only that catches a legacy freeze.
- Two source gates read figure sites. The HTML escaping gate (`htmlInterpolation.gate.test.ts`) trusts a
  computed-key read passed as the first argument of `formatFixed` or `formatPercent`, as it trusts
  `x[k].toFixed(n)`: only those two names and only that argument, so `formatExactDecimal(x[k])` in an
  HTML template is still reported. The [money gate](state/app-state.md#privacy-gate)
  (`lib/utils/privacy/moneyRenderSites.test.ts`) keys its registry by file and snippet: rewriting a
  registered expression, a `toFixed` into a `formatFixed`, means updating its snippet.

## 🛠️ Managing Translations

LibreFolio provides a full CLI toolkit for managing translation files via `./dev.py i18n`.

### 🔍 Audit

Report translation coverage, key usage and, optionally, duplicate values across the four catalogues:

```bash
# Default: warnings only, on the terminal (no full translation table)
./dev.py i18n audit

# Include the duplicate-value analysis
./dev.py i18n audit --duplicates

# Full Markdown report (adds the complete translation table), on the terminal
./dev.py i18n audit --format md

# Excel workbook: i18n-audit.xlsx in the current directory
./dev.py i18n audit --format xlsx

# Markdown and Excel files in a chosen directory
./dev.py i18n audit --format both --output ./reports/

# Markdown report to a chosen file
./dev.py i18n audit --format md --output i18n-report.md
```

| Flag | Description |
|------|-------------|
| `--format`, `-f` | `none` (default): warnings only, on the terminal. `md`: the full Markdown report, on the terminal or, with `--output`, in a file. `xlsx`: an Excel workbook. `both`: the `md` and `xlsx` files. |
| `--output`, `-o` | Directory or file path for file output (default: the current directory). A directory receives `i18n-audit.md` / `i18n-audit.xlsx`; a path ending in `.md` or `.xlsx` is used as given. |
| `--duplicates`, `-d` | Also report keys sharing the same value (case-insensitive), grouped by how many of the four languages share it: 🔴 all four, 🟠 three, 🟡 two, 🟢 one. |

The key-usage verdicts below are part of the Markdown output only (terminal or `.md` file). The workbook
holds the translation table, the missing translations, a coverage summary and, with `--duplicates`, one
sheet per tier. The command exits with status 1 when a key the backend assigns in a metadata field
(`message_i18n_key="…"`, `label_key="…"`, an `x-i18n-key` schema entry) is missing from the catalogues;
unused keys never fail it.

### 🧾 What the Audit Reports

Besides coverage (keys missing in some languages) and the optional duplicates, the audit gives every
catalogue key one of three verdicts. The classifier is `classify()` in `scripts/i18n_usage.py`, called by
`generate_unused_keys_report()` in `frontend/scripts/i18n-audit.py`.

| Verdict | Meaning | Report section |
|---------|---------|----------------|
| **used** | Proven by the evidence below. | not listed |
| **not verified** | Under a real dynamic family, or only under a legacy truncated prefix (listed as *Dynamic prefixes detected*): the final segment is built at runtime and named nowhere. **Not evidence of death.** | 🔵 Not Verified |
| **dead** | No evidence anywhere. The only actionable list. | ❌ Likely Unused |

How the evidence is gathered:

- **Product sources only**: `*.svelte`, `*.ts` and `*.js` under `frontend/src/`, plus the Python sources
  of `backend/app/`. Tests prove nothing: `*.test.ts`, `*.spec.ts` (and their `.js` twins), anything
  under `__tests__/` or `__mocks__/`. Generated clients are skipped too, even where a source imports them:
  `./dev.py api sync` writes `generated.ts`, `generated-tools.ts` and `*.generated.ts` into
  `frontend/src/lib/api/` and git ignores them, so a verdict resting on them would change on a fresh
  clone. The backend they are generated from is read directly anyway.
- **Any whole-key literal counts**, whatever receives it: wrappers such as `translateOr($_, 'k', …)`,
  `label('k', …)` or `tr('k', …)`, props such as `afterCopyKey: 'k'`. Backend literals count too:
  dictionaries, `..._i18n_key=` fields.
- **Templates are expanded**: string constants (`` `${NS}.leaf` ``), literal conditionals
  (`cond ? 'a.b' : 'a.c'`), typed unions and single-literal parameter types (`prefix: 'errors'`), nested
  templates, camelCase continuations (`` `…scheduler.historyDays${day}` ``) and `'ns.' + code`
  concatenations. A final segment built at runtime leaves a **family**; backend f-strings such as
  `f"aiExport.additionalData.reason.{reason}"` are families too.
- **Family members** are proven by the producer's vocabulary or by what the file building the family
  names (`titleKey:` values, the values of an indexed map). The vocabulary is the backend's string
  literals, and a member also matches a code spelling it in capitals or in lower case (`IN_TRANSIT` proves
  `brokers.lots.modal.state.in_transit`); a code may begin with a digit (`"3m"` proves
  `aiExport.additionalData.period.3m`), but a number or a sentence is no code. A *narrow* family, at least
  two segments deep (`risk.assetSet.band.`) or a camelCase continuation, also accepts the words its file
  quotes and those of the modules that file imports directly, in any form (static, type-only, re-export,
  dynamic `import()`) with a relative or `$lib` specifier: `CorrelationHeatmap.svelte` builds
  `` `risk.assetSet.band.${band}` `` and the band names live in the `correlationHelpers.ts` it imports.
  One hop only: a word two imports away, or in a neighbouring module the file does not import, proves
  nothing, and a wide family (`` `ns.${x}` ``) reads no import.
- **Shapes**: a template with several runtime segments, or with one before a literal tail
  (`` `assets.providerParams.${code}.${kind}.${field.key}` ``, `` `assets.panels.${panel.id}Hint` ``),
  keeps its shape. Each runtime segment becomes a slot of exactly one segment, and a segment that resolves
  (a constant, a union such as `kind: 'label' | 'description'`) takes only its values. A key with that
  shape is used when every slot is a word of the building file or of a module it imports directly, or a
  backend code. One slot named nowhere leaves the key not verified, a key with an extra segment does not
  match, and a template without a dotted literal head (`` `${a}.${b}` ``) has no shape: any two quoted
  words would make a key.
- **👻 Backend Families Without Catalogue Keys** lists the prefixes the backend builds inside an existing
  namespace but with no catalogue key under them. It is informational and never counts as unused.
- **📦 Kept Alive Only by Unreferenced Sources** lists the keys whose verdict would weaken without the
  sources no SvelteKit entry reaches, each followed by the verdict it would then get (`→ dead` or
  `→ not verified`), then every unreferenced source: a file nothing reaches renders nothing, yet still
  proves the keys it reads. The entries are the route files under `frontend/src/routes/` (`+page`,
  `+layout`, `+error.svelte`, `+server`, `.server` variants and layout resets such as `+page@.svelte`
  included), the hooks at the root of `frontend/src/` (`hooks.ts`, `hooks.server.ts`, `hooks.client.ts`)
  and the service worker; reachability follows every import form listed above, dynamic `import()`
  included. A `.d.ts` file is never reported, and a test is no source, so a component imported only by
  tests is unreferenced. The section appears only when some key depends on such a source. It is
  informational, never counts as unused and changes no verdict: decide whether the source is dead, then
  remove it with its keys.

### ➕ Add, Update, Remove Keys

```bash
# Add a new key to ALL language files
./dev.py i18n add "dashboard.new_feature" --en "New Feature" --it "Nuova Funzionalità" --fr "Nouvelle Fonctionnalité" --es "Nueva Característica"

# Update an existing key in specific languages
./dev.py i18n update "dashboard.title" --en "My Dashboard" --it "La mia Dashboard"

# Remove a key from all language files
./dev.py i18n remove "obsolete.key"

# Remove without confirmation prompt
./dev.py i18n remove "obsolete.key" -f
```

### 🔎 Search & Explore

```bash
# Search for keys or values containing a query (keys + values in every language)
./dev.py i18n search "broker"

# Search only in keys
./dev.py i18n search "broker" -k

# Search only in values
./dev.py i18n search "broker" -v

# Restrict the value search to one or more languages (comma-separated)
./dev.py i18n search "courtier" -l fr

# Show key tree structure
./dev.py i18n tree

# Show tree for a prefix with key counts
./dev.py i18n tree "fx" --counts
```
